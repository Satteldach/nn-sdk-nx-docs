VR

This chapter covers requirements for application design and development and applies to applications that use the Toy-Con VR Goggles to support VR (Virtual Reality). Developers of applications that use the Toy-Con VR Goggles to support VR must read this chapter. Also note that applications that use the Toy-Con VR Goggles to support VR must comply with 0172: Getting approval from Nintendo in advance if your application supports Toy-Con and 0180: Explaining how to attach the Joy-Con strap (for applications that support Toy-Con) in addition to the requirements in this chapter.

Throughout the rest of this document, gameplay that uses the Toy-Con VR Goggles is called "VR mode."

Note that even if your application only uses the Toy-Con VR Goggles to display stereoscopic 3D and does not use them to track the movement of the user's head, your application is still subject to the guidelines in this chapter.

VR: General

This subchapter covers requirements that apply to all applications that implement a VR mode.

0183: Complying with Parental Controls (VR)
If the Parental Controls item VR Mode (3D visuals) is restricted, you must not allow the user to play in VR mode.
Software to Be Tested
Applications that implement a VR mode
Backgrounder

One of the Nintendo Switch Parental Controls is VR Mode (3D visuals). If this Parental Controls item is restricted, you must not allow the user to play in VR mode inside your application.

Nintendo sets the target age range for VR mode to be 7 years of age or older, and we prompt users to refrain from using VR mode if children age 6 or younger are playing the game.

We provide users with the VR Mode (3D visuals) item in Parental Controls as a feature allowing users to prevent children age 6 or younger from using VR mode. Applications that support VR mode must comply with any Parental Controls restrictions on VR mode.

If parts of your application do not use the Toy-Con VR Goggles, then you are free to allow users to play those parts even when VR Mode (3D visuals) is restricted.
For example, it is not a problem to offer a mode that has the same gameplay as your VR mode, but which can be played without using the Toy-Con VR Goggles.

Info:

Users can temporarily lift Parental Controls restrictions. If the user temporarily lifts the Parental Controls restriction on VR mode, in some cases the restriction may go into effect again at some point during gameplay. In this case, there is no problem as long as your application correctly handles the VR mode exit notification that you receive from the system.

Test Method

You must perform both Test Method A and Test Method B below.
(These test methods are independent of each other. For example, if you need to repeatedly test this guideline in order to reproduce a bug, you can do so by repeating just Test Method B by itself, instead of performing both test methods every time.)


Test Method A:

  1. In Parental Controls, set VR Mode (3D visuals) to Restricted.
  2. Start the application and attempt to play in VR mode.


Test Method B:

  1. In Parental Controls, set VR Mode (3D visuals) to Restricted.
  2. On the HOME Menu, temporarily lift Parental Controls restrictions.
  3. Start the application and begin playing in VR mode.
  4. While playing in VR mode, short-press the POWER Button on the system to put the system into Sleep Mode.
  5. Press the POWER Button again to wake the system from Sleep Mode.
  6. Follow the on-screen instructions and resume the application.
  7. Attempt to begin playing in VR mode.
Pass/Fail Determination

Passes if all of the following conditions are met.

  • In Test Method A step 2, the user cannot play in VR mode.
  • In Test Method B step 6, the application has exited VR mode.
  • In Test Method B step 7, the user cannot play in VR mode.

0184: Prohibited motions of Toy-Con VR Goggles
Do not require or prompt users to perform any of the prohibited motions listed in the Backgrounder.
Software to Be Tested

Applications that implement a VR mode
Backgrounder

The following motions are potentially unsafe. Applications therefore must not require or prompt users to perform any of these motions within the application.

Prohibited operation Why is this prohibited? Illustration
Having the user themselves move to a different location while holding the Toy-Con VR Goggles to their face Wearing the Toy-Con VR Goggles over the face blocks the user's view of their surroundings, and the user may hit nearby people or objects and get injured.

Having the user release both hands from the Toy-Con VR Goggles Doing so would require the user to modify the Toy-Con VR Goggles, or adopt an unstable posture that may result in the user dropping the system.

  • Nintendo Switch Application Safety Improvement Guide

Play through, from beginning to end, all application modes that use the Toy-Con VR Goggles.
Pass/Fail Determination
Passes if the application does not require or prompt users to perform any of the prohibited motions listed in the Backgrounder.

0185: Explanation cautioning users about their surroundings and motion sickness

Your application must caution users about their surroundings and motion sickness.
Software to Be Tested

Applications that implement a VR mode
Backgrounder

To promote a fun and safe experience, if your application uses the Toy-Con VR Goggles, you are required to caution the user.

  • Nintendo recommends using one of the caution screens provided by Nintendo when cautioning the user about their surroundings and motion sickness, but you are also allowed to create your own explanation screen and incorporate it somewhere in your application's overall explanation of how to play, as long as your screen provides the same explanation.

  • You must display the caution screen every time your application starts.
  • You must display the caution at some point before the user actually uses the Toy-Con VR Goggles in your application.
  • Display this message either in the language currently set in your application or in the language currently set in system settings.

If you create your own screen, you must include the following standardized text set by Nintendo.

The following information should be checked by an adult:

  • When using the Toy-Con VR Goggles...
    • Be mindful of your surroundings and other people.
    • Only play while seated.
    • Make sure to take regular breaks.
  • Restrict the use of VR mode for children 6 and under.
    Note: You can set age-based software restrictions by using the Nintendo Switch Parental Controls smart device app or from System Settings > Parental Controls on the HOME Menu.

For details, see the Nintendo Switch Toy-Con Application Planning Guide.
References
  • Nintendo Switch Toy-Con Application Planning Guide
Test Method
  1. Start the application and progress to a scene where the user performs operations with the Toy-Con VR Goggles.
  2. If the application supports multiple languages, perform step 1 for all supported languages.
Pass/Fail Determination

Passes if all of the following conditions are met.

  • The application displays at least one of the following at some point before the user actually operates the Toy-Con VR Goggles.
    • The caution screen provided by Nintendo.
    • An application-specific caution screen that includes the standardized text shown in the Backgrounder.
  • The application displays the above screen at least once per application startup.
  • The application displays the above screen either in the language currently set within the application or in the language currently set in system settings.

0186: Displaying message that prompts the user to take a break
Your application must periodically prompt the user to take a break.
Software to Be Tested
Applications that implement a VR mode
Backgrounder

If your application implements a VR mode, while in VR mode your application must periodically prompt the user to take a break.

Use the following standardized text set by Nintendo as your message. But it is acceptable to reword this text as long as your explanation covers all the information provided in Nintendo’s standardized text.

Would you like to take a break?

You must display this message within 30 minutes of starting the game in VR mode, and you must continue displaying the message at intervals of no longer than 30 minutes.

  • Handling applications that are composed of multiple minigames
    • If your application is designed to remain in VR mode even while displaying screens between minigames (such as menu screens), then your application must maintain a timer for displaying break messages.
Figure 1 Applications designed to remain in VR mode even while displaying screens between minigames

  • If your application is designed to exit VR mode when displaying screens between minigames (such as menu screens), then it is acceptable to reset the timer for displaying break messages each time your application exits VR mode between minigames.
    Likewise, it is acceptable to assume that when the application or user exits VR mode, the user is taking a break from VR mode.
Figure 2 Applications designed to exit VR mode when displaying screens between minigames

If your application is designed in such a way that it cannot display the message within 30 minutes of starting the game in VR mode, contact Nintendo.
When contacting Nintendo, include the following information.

  • An overview of your game.
  • The timing at which your game displays messages that prompt the user to take a break.
  • ROM data that Nintendo can use to check the issue that you are contacting Nintendo about.
    This does not have to be your finished full retail ROM, but the issue that you are contacting Nintendo about must be exactly the same in this ROM as in the full retail ROM that you plan to release.

Specifications like the following are prohibited. Do not design your application this way.

  • Game is started in VR mode. Game displays the message once after the game is started. Game then never displays the message again.
Figure 3 Example of unacceptable implementation (application that displays break message only once)

Display this message either in the language currently set in your application or in the language currently set in system settings.

For details, see the Toy-Con Application Planning Guide.
References
  • Nintendo Switch Toy-Con Application Planning Guide
Test Method
  1. Start VR mode.
  2. Play while staying in VR mode (see Note), and continue playing until the message is displayed.
    Note: For example, if your application exits VR mode after the user clears the game, intentionally do not clear the game.
  3. Close the message displayed in step 2, then resume gameplay.
  4. Repeat steps 2 and 3 several times.
Pass/Fail Determination

Passes if at least one of the following conditions is met in step 2.

  • The application is designed in such a way that the user cannot play in VR mode for longer than 30 minutes after starting or resuming play in VR mode (see Note).
    Note: For example, there is a time limit in the game, and VR mode always ends within 30 minutes.
  • Within 30 minutes after the user starts or resumes play in VR mode, the application displays a message prompting the user to take a break, such as the message in the Backgrounder.

0187: Countermeasures against motion sickness
You must design your application in such a way that it does not easily cause motion sickness.
Software to Be Tested
Applications that implement a VR mode
Backgrounder

Depending on the person, users may exhibit symptoms similar to motion sickness when experiencing VR.
Other guidelines such as 0185: Explanation cautioning users about their surroundings and motion sickness and 0186: Displaying message that prompts the user to take a break require you to prompt users to take a break, but you must also design and implement your application in such a way that it does not easily cause the user to feel motion sickness even after long play sessions.

For more information about strategies to design applications that do not easily cause motion sickness, see the documents in the References.
References

Test Method
Play the application in VR mode for several minutes.
Pass/Fail Determination
The majority of general users do not feel motion sickness after playing the application in VR mode for several minutes.

0201: Prohibition of incorrect stereoscopic display
Your application must not display incorrect stereoscopic images.
Software to Be Tested
Applications that implement a VR mode
Exceptions

If any of the following cases apply:

  • On either the right or left-eye image, there is an object that does not appear on the other image; however, the object is reasonably considered to be out of the field of view of one camera.
  • There is difference between the images due to the difference of the angles from which the object is viewed.
  • Images appear different due to physically possible reflection.
  • Images are vertically shifted due to physically possible reflection on curved surfaces or refraction.
  • Patterns or objects scaled down without applying anti-aliasing appear differently on the left and right-eye images when viewed on a per-pixel level.
Backgrounder

By implementing VR mode, it is possible to intentionally display the following types of images. However, these images may not achieve a correct stereoscopic 3D effect, or may cause the user to feel uncomfortable even if they achieve a stereoscopic effect.

To avoid displaying incorrect stereoscopic images in applications that implement VR mode, it is prohibited for your application to display any images similar to the following.

  • Images that are processed differently for the left and right eyes for some purpose other than stereoscopic depth
    Examples include adding different patterns, using images of different sizes or ones that are shifted vertically relative to each other, and applying different effects to the images for the left and right eyes. This includes using completely unrelated images as the left and right images.
  • Images with inverted stereoscopic depth (swapping the left and right images)
    An image's depth appears to be inverted when the images for the left and right eyes are reversed. In other words, this occurs when the image for the left eye is shown to the right eye and vice versa.
  • Images that are not synchronized between the left and right eyes
    Images that fall under this category include those where the timelines of the right-eye and left-eye images are out of sync, or that don't update for each eye simultaneously; for example, updating for the right eye on odd frames and for the left eye on even frames. If the left and right images are not synchronized, this has the unfortunate consequence of displaying completely different images to the user's left and right eye during scene transitions. Likewise, whenever an on-screen object moves up or down, its position gets vertically out of sync between the left and right images.
References
  • Nintendo Switch Toy-Con Application Planning Guide
Test Method
Play through, from beginning to end, all application modes that use the Toy-Con VR Goggles.
Pass/Fail Determination

Passes if all of the following conditions are met.

  • There is no difference between the left-eye and right-eye images in characteristics such as the colors, shapes, size and pattern of an object.
  • There is no vertical shift between the left-eye and right-eye images.
  • The same effects are used on the left-eye and right-eye images.
  • Two completely different images are not displayed for the left-eye and right-eye images.
  • The depth of the stereoscopic image is not inverted.
  • The left-eye and right-eye images are updated simultaneously.
  • There is no temporal difference between the left-eye and right-eye images.

0205: Notifying the system when the user starts playing in VR mode
Your application must notify the operating system when entering VR mode.
Software to Be Tested
Applications that implement a VR mode
Backgrounder

Applications that implement a VR mode display stereoscopic 3D while in VR mode, and the user views the screen through the Toy-Con VR Goggles.
If the user presses the HOME Button in these circumstances and the system transitions directly to the HOME Menu and displays a screen that does not support stereoscopic 3D, then users still wearing the Toy-Con VR Goggles may experience discomfort.
To avoid discomfort to users playing in VR mode, your application must notify the system in advance to ensure that the system displays one of the following screens (VR curtains) when exiting stereoscopic display.

VR curtain A VR curtain B
  • Instructions to give the system
    • In advance, call the function that notifies the system that your application is entering VR mode.
  • Display timing
    • The system automatically displays the VR curtain every time the user exits stereoscopic display.
  • Display language
    • The system determines the appropriate language and displays it.
  • Other
    • There are two types of VR curtains. The system decides which type to use, based on whether the user is able to return to the application.

For details, see the Toy-Con Application Planning Guide and the NintendoSDK VRGogglesKit Documents.

  1. Start the application and enter VR mode.
  2. While in VR mode, press the HOME Button and confirm that the VR curtain is displayed.

Passes if all of the following conditions are met.

  • During step 2, the VR curtain is displayed.
