Play modes

This chapter covers requirements for application design and development that arise from the differences between the three play modes, and applies to all applications.

This chapter assumes that you have read the Play Mode Guide, which contains detailed descriptions of the play modes. Nintendo strongly recommends reading the Play Mode Guide prior to continuing with this chapter.

Supported play modes

Switch systems support three play modes: TV mode, tabletop mode, and handheld mode.

Nintendo Switch Lite supports only handheld mode, but if the user has Joy-Con controllers or other controllers that allow wireless connection (sold separately), the user can use Nintendo Switch Lite to play applications that support tabletop mode.

When your application supports a given play mode, it means that users can play through the entirety of your application's core content using only that play mode. For example, "an application that supports TV mode" is an application designed so that users can play through its core content from beginning to end without being asked to switch to tabletop mode or handheld mode.

Figure 1 Example of supporting a play mode (here, an example of supporting TV mode)

Depending on how your application is designed, it may be difficult to define what its "core content" consists of. For example, if your application is a minigame collection, its individual minigames might support different play modes. If you are creating an application like this and having difficulty determining which supported play mode to direct users to use when playing the game as a whole, contact Nintendo.

The Play Mode Guide gives real-life examples of application designs and the play modes they support as a reference for developers who are deciding which play modes to support in their application. Please refer to that resource for more information.

0101: Supporting at least one play mode
The core content of your application must support at least one play mode.
Software to Be Tested
All applications
Backgrounder

Your application must support at least one of the three play modes available for Switch. In other words, users must be able to play through the entirety of your application's core content using only that play mode.

See each play mode's subchapter in Play modes for specific points to keep in mind when supporting each different play mode in your application.


Note that if your application includes any of the following specifications, then it requires the use of more than one play mode, and therefore does not support any single play mode. These examples violate this guideline.

  • Requiring the user to dock and undock the system as an essential element of playing the core content of your application
    • If you require the user to dock the system, they cannot continue playing in tabletop or handheld mode. Likewise, if you require the user to undock the system, they cannot continue playing in TV mode. If you require both of these in your application, then it means that no matter what play mode the user started in, you are absolutely requiring them to switch play modes at some point during the core content of your application. As a result, the user is unable to play through the entire core content using just a single play mode.
Figure 1 Unacceptable example of requiring the user to dock and undock the system

  • Requiring the user to attach and detach the Joy-Con controllers from the system as an essential element of playing the core content of your application

    • If you require the user to attach the Joy-Con controllers, they cannot continue playing in TV mode or tabletop mode unless they have extra Joy-Con controllers or other wireless controllers. Likewise, if you require the user to detach the Joy-Con controllers, they cannot continue playing in handheld mode. This inconveniences users who are in a setting where they are only able to play in handheld mode. If you require both of these in your application, then it means that no matter what play mode the user started in, you are absolutely requiring them to switch play modes at some point during the core content of your application. As a result, the user is unable to play through the entire core content using just a single play mode.

Figure 2 Unacceptable example of requiring the user to attach and detach the Joy-Con controllers


You must enter which play modes your application supports on your Application Specifications forms on Nintendo Developer Portal. For information on how to access these forms, see "Additional information."

0219: Prohibition of forcing the user to change play modes
You must not require the user to change play modes in order to progress in the core content for your application's supported play modes.
Software to Be Tested
All applications
Backgrounder

Switch provides three play modes with the following characteristics.

Table 1 Characteristics of each play mode
Play mode Disabled input methods Operations that change the play mode
TV mode
  • Input from the touch screen
  • Input from Joy-Con controllers attached to the system
  • Undocking the system
Tabletop mode
  • Attaching Joy-Con controllers to the system
  • Docking the system
Handheld mode
  • Detaching Joy-Con controllers from the system
  • Docking the system
  • Using additional wireless controllers

If your application requires the user to use "disabled input methods" or "operations that change the play mode" in order to progress in your application's core content, then it is impossible for the user to complete the core content of your game in that play mode.

To ensure that users can complete the core content of your application without leaving your supported play modes, you must not require users to perform the following operations in order to progress in your core content.

Table 2 Play modes and corresponding operations your application must not require in order to progress
Supported play mode Operations your application must not require in order to progress
TV mode
  • Touch screen operations
  • Attaching Joy-Con controllers to the system
  • Undocking the system
Tabletop mode
  • Attaching Joy-Con controllers to the system
  • Docking the system
Handheld mode
  • Detaching Joy-Con controllers from the system
  • Docking the system
  • Using additional wireless controllers
Info:

Boost mode is a high-performance mode that is not available in tabletop or handheld mode.

If your application supports tabletop mode or handheld mode, be aware that users must be able to progress in your application without boost mode.

Test Method

Perform the following tests for all supported modes.

Applications that support TV mode
  1. Put a Switch devkit in TV mode.
  2. Play through the application's core content that supports TV mode from beginning to end.
Applications that support tabletop mode
  1. Put a Switch devkit in tabletop mode.
  2. Play through the application's core content that supports tabletop mode from beginning to end.
Applications that support handheld mode
  1. Put a Switch devkit in handheld mode.
  2. Play through the application's core content that supports handheld mode from beginning to end.
Pass/Fail Determination
Applications that support TV mode

Passes if in step 2, the application does not require the following operations as an essential element of playing its core content in TV mode.

  • Touch screen operations
  • Attaching Joy-Con controllers to the system
  • Undocking the system
Applications that support tabletop mode

Passes if in step 2, the application does not require the following operations as an essential element of playing its core content in tabletop mode.

  • Attaching Joy-Con controllers to the system
  • Docking the system
Applications that support handheld mode

Passes if in step 2, the application does not require the following operations as an essential element of playing its core content in handheld mode.

  • Detaching Joy-Con controllers from the system
  • Docking the system
  • Using additional wireless controllers

Tabletop mode

This subchapter covers requirements for application design and development and applies to applications that support tabletop mode.

If you consider your application to have multiple separate core content experiences, make sure to explain which specific core content experiences support tabletop mode in your Lotcheck submission documentation.

0160: Supporting wireless controllers when Joy-Con controllers are attached to the system
Your application must allow the user to use wireless controllers even when the Joy-Con controllers are attached to the system.
Software to Be Tested

Applications that support tabletop mode
Backgrounder

When the user undocks the system and plays in tabletop mode, one or both Joy-Con controllers may still be attached to the system.

Applications that support tabletop mode must support all features of supported wireless controllers, even when Joy-Con controllers are attached to the system.
If your application requires the user to detach the Joy-Con controllers from the system in order to play a specific mode, but the user is already playing with wireless controllers and does not detach the Joy-Con controllers, then you must ensure that your application remains operable and gives the user some way out of the situation (either progressing forward or backing out), so that the user does not get stuck.

Note that on Nintendo Switch Lite systems, the controllers are part of the system itself and cannot be detached. However, by connecting wireless controllers, Nintendo Switch Lite users can still play applications that support tabletop mode.

If your application is designed in such a way that it becomes inoperable until the user detaches the Joy-Con controllers from the system, then your application cannot be played on Nintendo Switch Lite systems. You must comply with the rules above to ensure that your application can be played by Nintendo Switch Lite users.

Example methods of implementing support
  • Implement an in-game mechanism for switching between wireless controllers and attached Joy-Con controllers
    • If your application is single-player only: Use the single-player only mode of the controller support applet
    • Implement application-specific handling, without using the controller support applet
  • Accept input from both wireless controllers and attached Joy-Con controllers

See the NintendoSDK API Reference > Sample Descriptions > Human Input Device Library Samples > Calling the Controller Support Applet for more information on methods of supporting wireless controllers.

Test Method
  1. Prepare one Switch devkit and two sets of left and right Joy-Con controllers (Joy-Con set A and Joy-Con set B).
    Note: If your application supports multiplayer, prepare the necessary number of controllers.
  2. Set up tabletop mode by attaching Joy-Con set A to the Switch devkit and wirelessly connecting Joy-Con set B, then start the game using Joy-Con set B.
  3. Play through all scenes of the application that support tabletop mode.
Pass/Fail Determination
Passes if, in step 3, you are able to play in tabletop mode using all wirelessly-connected controllers, and you can use all features of the supported wireless controllers (except for vibration, which is not required).
Tips

The unacceptable examples below are some typical ways in which applications violate this guideline. Your application must allow users to play with wirelessly-connected controllers.
Note that the vibration feature is not essential for gameplay, so it is acceptable to not support it.

  • Unresponsive buttons or sticks on wirelessly-connected controllers.
  • Unresponsive motion controls on wirelessly-connected controllers.
