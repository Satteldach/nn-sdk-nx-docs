7 Support After Release

Bugs and other issues can arise after an application has been released to the market.
This section describes useful tools for resolving issues.

  • Crash Reports
  • Error Code List

Crash Reports

A crash report is a collection of information about an application that has crashed due to an unexpected error. If crash reports are enabled for an application, the system will create a crash report when the application crashes and send it to the Nintendo crash report server.

Application developers can analyze the crash reports that users agreed to share in the following two ways.

Analysis Methods

Using a Web Browser

  • By accessing CRPORTAL (https://crash-report.wc.lp1.er.srv.nintendo.net/) and submitting a request, you can use the error monitoring system provided by Sentry (sentry.io) to analyze the crash reports.
  • Currently, you can only analyze the crash reports collected in the market (production environment).
  • The advantage of this method is that you don't need to build a system to visualize the statistical information.

Using the Crash Report Retrieval Tool Included in NintendoSDK

  • By installing NintendoSDK, you can use the crash report retrieval tool (CrashReport.exe) to analyze the crash reports.
  • You can analyze the crash reports collected in the market (production environment) and the crash reports collected in the development environment.
  • The advantage of this method is that it can be used even when the available debugging methods are limited, such as during final testing in a development environment.

Information That Can Be Analyzed

Various types of information can be obtained from the crash reports and analyzed, including information about the number of occurrences of each cause of a crash, error codes, exception addresses, stack traces, and screenshots. This information provides important clues when you contact Nintendo support, so check it in advance.

Preparing for Analysis

To use crash reports, you need the NSS file that is created at the same time as the NSP file, as described in 5.1 ROM Builds > Building Application ROMs. Be sure to save and not delete this NSS file, not only for the initial application, but also for patches.

Error Code List

An error code might be displayed on the screen when the application crashes or a certain operation is performed. If you have obtained an error code, either from a user or from a crash report, you can reference the Error Code List to identify the type of issue involved. Depending on the content, the crash might be due to a hardware defect or a setting that was forgotten, and not due to the application. This list provides a way to determine whether the content is something that should be dealt with by the application developers.
