Objectives and Content

This document describes an overview of the overall process when submitting the master ROM for Nintendo Switch™ (hereafter, Switch) applications.

It describes the procedures for the various application forms, for creating master ROMs, and for submitting master ROMs. Greater detail is provided in Related Documents and Related Systems.

Intended Audience

This document is intended for Switch application developers and for those responsible for submitting master ROMs.

When to Read This Document

Read this document when you are developing Switch applications or submitting a master ROM.

Important Information

Some of the images used in this documentation depict content that is still in development. They may differ from actual content on the screen.

Names of GUI elements in the Nintendo Developer Portal are written in bold.

Terminology in Use Within This Document

Table 1-1 Terminology in Use Within This Document
Term Description
ROM Name within this document for the executable file for the application or demo software that users will operate. Development ROMs are those that can be created by application developers. They will then become product versions that users will control on retail devices after that ROM is submitted to Nintendo and passes Lotcheck testing.
Master ROM

A ROM file that is submitted to Lotcheck is referred to in particular as a master ROM. In this document, releasing refers to the creating of retail versions from the master ROM and then putting that version up for sale in Nintendo eShop or as packaged versions in shops.
Patch A patch (also called update data) is a mechanism for adding functionality or fixing discovered bugs after an application's release. Patches must be submitted using the same procedures as for the master ROM because Lotcheck testing occurs before distributing patches. The ability to distribute what had been called remasters for earlier platforms (that is, applications with updates applied), is not supported on the Switch platform.
Lotcheck

The testing performed by Nintendo on submitted master ROMs. Only master ROMs that pass the Lotcheck process will be released to market.
Nintendo Developer ID (NDID) The ID (described later) that you are required to have to use the Nintendo Developer Portal, OMAS, and SLIM.
Downloadable Content Additional content for an application, and one of the basic units of master ROM data.

Related Systems

Table 1-2 Related Systems
System Description URL
Nintendo Developer Portal (NDP) A website specifically for game developers working for the Nintendo platforms. https://developer.nintendo.com
Online Title Management System (OMAS) A web system for requesting network features for products that support network services, and for receiving reports on network specifications. https://omas2.mng.nintendo.net
Software Legal Information System (SLIM) A system for generating the required software legal information. https://slim.mng.nintendo.net/slim/
Nintendo Content Management System (NCMS) System for adding and managing the various data, including promotional videos, needed for the download sales of applications and demo versions. https://ncms3.mng.nintendo.net/ncms3/
