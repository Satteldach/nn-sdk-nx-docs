This section describes the procedure for creating a master ROM.

The master ROM is an executable NSP file that includes all the associated data needed to run an application, including the minimally required elements and icons.

Master ROM Types

Figure 5-1 Master ROM Types

Master ROMs must be created and submitted for applications, patches, and downloadable content (DLC). The gray squares () in Figure 5-1 Master ROM Types indicate the types of master ROMs that can be created.

Application information is handled in units of what is known as a product. There are four types of applications: full retail applications, demo applications, on-card downloadable content, and multi-application cards. Each of these categories has an associated product type. (A product is the unit used to handle application information.)

For all applications, including full retail applications, demo applications, on-card downloadable content, and multi-application cards, an initial release is created, and then patches are created to update the application. Downloadable content can also be created and distributed for applications. However, downloadable content cannot be updated using application patches.

Process for Creating a Master ROM

Creating a Master ROM for an Application

Use the following procedure to create a master ROM for an application.

Figure 5-2 Creating a Master ROM for an Application

  1. Add the software legal information.
  2. Prepare the icons and, optionally, offline HTML files.
  3. Create an NMETA file.
  4. Build the release version using the Visual Studio project.
  5. Update the ROM content as necessary.
  6. Test the release version of the NSP file.

Creating a Master ROM for Downloadable Content

The procedure for creating a master ROM for downloadable content is essentially the same as the procedure for applications, except that different information must be configured in the NMETA file.

For the detailed procedure, see 5.1 ROM Builds.
