2.3 Application-Level Support

This section is for developers. It describes how to implement applications that support Nintendo Switch Online, and how to transition inside the application based on whether the user has a Nintendo Switch Online membership.
The implementation of the application and the transitions in the application both differ depending on the Nintendo Switch Online policies that have been set for the online features in the application. This page provides a separate description for each application policy.

References in this section to "countries without Nintendo eShop" simply mean that Nintendo eShop has not yet been deployed in the country of residence associated with the Nintendo Account linked to a particular user account.

Common to All Application Policies

Developers must appropriately process the Result values returned from the account library, regardless of the application policy.
For more information, see Nintendo Switch Guidelines > Handling Result Values Returned by the account Library.

The following information about getting NSA ID tokens only applies for user accounts that have been linked to a Nintendo Account or an account for China. You cannot get an NSA ID token if you have only created a network service account in DevMenu.

All Features Require Membership

No special handling is required if the developers process the Result values returned by the account library appropriately.
The ability of the application to get an NSA ID token with the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function depends on whether the user has a Nintendo Switch Online membership. If the user is a member, the application can get an NSA ID token. If the user is not a member, the application fails to get a token.
The application also fails to get an NSA ID token in countries without Nintendo eShop, because users there cannot subscribe to the Nintendo Switch Online service.

No Features Require Membership

No special handling is required if the developers process the Result values returned by the account library appropriately.
The application can get an NSA ID token using the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function regardless of whether the user has a Nintendo Switch Online membership.
In addition, the application can get an NSA ID token even in countries without Nintendo eShop. However, if the application is being used in a development environment with a firmware version earlier than 6.0.0-1.0, it fails to get an NSA ID token in these countries.

Some Features Require Membership

In addition to appropriately processing the Result values returned by the account library, developers also must follow set procedures to handle calls to member-only features.
The application can get an NSA ID token using the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function regardless of whether the user has a Nintendo Switch Online membership.
In addition, the application can get an NSA ID token even in countries without Nintendo eShop. However, if the application is being used in a development environment with a firmware version earlier than 6.0.0-1.0, it fails to get an NSA ID token in these countries.

Using an Independent Server

If an independent server is being used, that independent server must control the availability of online features based on the Nintendo Switch Online license information contained in the NSA ID token sent from the application. For more information about NSA ID tokens, see the Nintendo Switch Independent Server Setup Manual.

When a user without a Nintendo Switch Online membership sends a use request for a member-only feature to the independent server, the server must return an error to the application indicating that the user does not have the license to use that feature.

When the application determines from the error returned by the independent server that the user does not have the license, call the nn::account::ShowLicenseRequirementsForNetworkService function. If the target account does not have a Nintendo Switch Online membership, the system displays an applet to prompt the user to become a member.

Using Both NEX and an Independent Server

Even if all the features of the independent server (or all of the NEX features) are complimentary features, the application policy for the application is classified as Some features require membership if any feature is a member-only feature. In such cases, note the following two points.

  • All users can get NSA ID tokens.
  • All users can access the independent server and NEX game server.

To control the use of the independent server features, both the independent server and the application must provide support. For more information about providing support, see the preceding section, Using an Independent Server.
To control the use of NEX features, the application must provide support. The application must use specific methods to handle the errors returned from the NEX game server that indicate the lack of a Nintendo Switch Online license. For more information, see 2.3.1 NEX Error Handling When the Application Policy Is Some Features Require Membership.

Using Both NPLN and an Independent Server

Same as the information described in Using Both NEX and an Independent Server.
For more information about handling on the independent server side, see Using an Independent Server earlier in this section.
For more information about handling on NPLN, see the NPLN Manual included in the NPLN package.

State of NSA ID Token and Availability of Online Features

The NSA ID tokens obtained by the application might or might not include Nintendo Switch Online license information. The application policy determines whether the application needs to deal with this fact.
For more information about NSA ID tokens and subscriptions, see Nintendo Switch Independent Server Setup Manual > Connecting to an Independent Server > Nintendo Switch Online Support.

When the Policy Is All Features Require Membership or No Features Require Membership

The ability to get an NSA ID token matches the ability to use the online features. There is no need for testing that accounts for differences in the state of the obtained NSA ID token.

When the Policy Is Some Features Require Membership

Testing that accounts for differences in the state of the obtained NSA ID token and the availability of online features into account is required. Check whether the application is working correctly.
For more information about how to change the status of the NSA ID token obtainable by the application, see Omitting Nintendo Switch Online Subscription Verification in Development Environments under 2.4 Use in a Development Environment.

Availability of Online Features When Using an Independent Server

See Nintendo Switch Independent Server Setup Manual > Connecting to an Independent Server > Nintendo Switch Online Support.

Availability of Online Features When Using NEX and NPLN

The relationship between the state of the NSA ID token and the availability of online features is as follows.

NSA ID Token Contains Nintendo Switch Online License Information
    • Member-Only Features
      • Available if there is a license.
      • Not available if there is no license (NEX or NPLN API returns an error).
    • Complimentary Features
      • Available regardless of whether there is a license.
NSA ID Token Does Not Contain Nintendo Switch Online License Information
    • All features are available, regardless of whether they are member-only features or complimentary features.
