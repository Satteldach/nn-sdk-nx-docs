7.2 Avoid Implementations That Continuously Try to Get an NSA ID Token in the Background (for Developers)

The Nintendo authentication server is accessed when you call the function to get the NSA ID token (the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function) if the NSA ID token is not cached at that time. If an error that cannot be resolved by the system or the application (an nn::account::ResultNetworkCommunicationError error) occurs and you continue to call the function to get the NSA ID token without fixing the cause of the error, you will put a load on the Nintendo authentication server. For this reason, avoid the following designs for your applications.

Note:

If the load on the Nintendo authentication server becomes a problem in the commercial market, you may be asked to revise your implementation.

Implementations to Avoid

If either of the following two processes apply to your implementation, consider adopting an implementation such as those presented later in Examples of Countermeasures.

  • Getting an NSA ID token in the background
  • Periodically trying to get an NSA ID token

The following sections describe these processes in more detail.

Getting an NSA ID Token in the Background

This refers to implementations where the user is not told of the error by displaying the error viewer applet when nn::account::ResultNetworkCommunicationError is returned by the function that gets the NSA ID token (the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function).

Such an implementation corresponds to cases such as where the application does not clearly separate online mode from offline mode and proceeds with the online features in the inactive state if the network connection fails in the background.

Periodically Trying to Get an NSA ID Token

This refers to implementations designed to periodically try to get the NSA ID token in accordance with the progress in the application if the first attempt to get the NSA ID token has failed.
Such an implementation corresponds to cases such as where user operations advance the application and periodically transition to a scene that uses online features, and at those times an attempt is made to get an NSA ID token to enable those features.

If the application fails to get the NSA ID token, it is restricted from trying again without an operation on the part of the user, as described in Nintendo Switch Guideline 0122: Prohibition of automatically retrying to get network service account ID tokens.

Reasons for Avoiding Implementations

If the process of getting the NSA ID token is conducted in the background and the process fails, the application might proceed without the user understanding that the online features have been inactivated or why an error has occurred. If the application keeps trying to get an NSA ID token without resolving the cause of the inability to connect online, the Nintendo authentication server will be accessed constantly.

Depending on the design of the application and the number of users, this can put a load on the Nintendo authentication server and affect stable service delivery. Avoid this kind of implementation.

There are no clear criteria for the kinds of designs and the numbers of users that are acceptable when an application is implemented this way. If the application is expected to be played by large numbers of users, for example because it is a free-to-play application, Nintendo may check the design specifications before or after the release. If the load on the Nintendo authentication server becomes a problem in the commercial market, you might be asked to revise your implementation.

Examples of Countermeasures

If your planning absolutely requires a design like those described in Implementations to Avoid, consider the possibility of taking the following countermeasures.

  • If the attempt to get the NSA ID token in the background has failed a certain number of times, display an error message to the user.
  • If the attempt to get the NSA ID token in the background has failed a certain number of times, stop making additional attempts in the background until the user explicitly re-enables the online features.
  • If the attempt to get the NSA ID token in the background has failed a certain number of times, reduce the frequency of subsequent attempts to get the NSA ID token in the background.
Info:

These are just some examples of possible countermeasures. You are welcome to adopt other countermeasures if they resolve or mitigate the problems described in Reasons For Avoiding Implementations.
