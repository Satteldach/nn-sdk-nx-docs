3.7.4 Notes When Supporting the Friends Features

Applying Presence Privacy Settings in Friend Matching

In general, we recommend matchmaking after getting the list of online friends from the friends library and passing that list to NEX or an independent server. In this way, the user is only matched with friends who have made their presence public.

There is also no need to support cases such as those where users are matched with friends by chance when playing in random matchmaking or another mode.

Using External Service Profiles Is Prohibited

It is prohibited for Switch applications to use external service profiles that do not belong to the user. (Profiles that are not in the application or on the Nintendo Switch are external.)

Info:

For example, applications cannot use Facebook profiles, Nintendo Network ID profiles, or Nintendo Account profiles other than the users' own profiles.

Showing Personalized Profiles of Friends and Network Service Account Nicknames Together

This information is important for applications that store personalized profiles (such as in games where the user can freely name the main character). When displaying a friend's profile, make sure that you show a personalized profile and the Switch network service account nickname together in at least one place.

The reason to show how they correspond at least one time is that users recognize their friends by their Switch network service account nicknames, and it might be difficult for a user to know which personalized profile corresponds to which Switch network service account nickname if only the personalized profiles are shown. You do not need to always show them together on every screen.

If you find this result difficult to achieve using the application's UI, you can call the friend details screen of the My Page applet without any issues.

Policy for Using Best Friends

Best friends are those friends a user would prefer to see displayed. We recommend that your application display these friends preferentially. The My Page applet is designed to mark best friends with a special icon and show them first in the friend list.

However, other than this kind of preferential display, refrain from instituting other ways of differentiating between best friends and other friends. If you design your application for play with best friends only, users are prompted to set players as best friends even when they do not want them displayed preferentially, which is contrary to the purpose of best friends. That being said, you can attach unique attributes to friends in the application to allow them to be distinguished.

Info:

You can design a specification that targets only best friends, but also prepare a specification that targets all friends, and design your application so users can use both specifications.

For example, if you prepare a mode for matchmaking only between best friends, also prepare a mode for matchmaking between all friends that can be played the same way.

Adding to Player History

The registration of information to Player History is typically done by the application using the friends library. If you are using the Pia5 version of the Pia library (a library provided by Nintendo), there is a flag for automatically registering session participants to Player History.

Info:

If you are using Pia6 or later, the application must explicitly call the nn::friends::AddPlayHistory() function of the friends library.

Note that you do not need to add players to Player History if your application has its own mechanism for defining friends and is not using the Friends feature that is provided as a system feature.

Note About Registering to Player History

Only register players to Player History when the gameplay allows users to recognize the people they are communicating with as people they have played with before.
For example, in the following situations, it might be difficult for the user to recognize that the person they are communicating with is a person in the Player History.

  • Viewing online play sessions as an observer
  • Measuring connection speed before the game begins
  • Only briefly encountering the other party in a map, such as in an MMORPG

Specification Overlap With the Overlay Notification System Feature

There is a Nintendo Switch system feature to display the following overlay notifications for friends while an application is running.
Be careful when implementing similar notifications independently in the application because the specification may overlap.

Notification Content Notification Timing

Number of friends online: XXX users

 The first time the user logs in after starting the system or waking it from sleep mode.
Number of friend requests received: XXX users The first time the user logs in after starting the system or waking it from sleep mode.
Friend XX is online (support period TBD) Each time a friend comes online.

Note that users have the option of disabling the display of these overlay notifications. For more information about overlay notifications, see the Nintendo Switch System Features Guide.
