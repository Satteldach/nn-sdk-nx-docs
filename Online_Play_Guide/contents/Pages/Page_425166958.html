2.3.1 NEX Error Handling When the Application Policy Is Some Features Require Membership

If the application policy for an application that uses NEX is classified as Some features require membership, you must implement appropriate handling for the specific NEX errors that occur when the user account does not have a Nintendo Switch Online license.

When using NintendoSDK 8.1.0 and later, use the nn::err::ShowError() generic error display function for handling. When using a version of NintendoSDK earlier than 8.1.0, use the dedicated nn::err::ShowNetworkServiceError() error display function for handling.

Using NintendoSDK 8.1.0 and Later

Displaying a Subscription Guide

If you are using NintendoSDK 8.1.0 or later and an error occurs because the user does not have a Nintendo Switch Online license, use the nn::err::ShowError() function to display the screen that prompts the user to subscribe to Nintendo Switch Online.

The application cannot determine from this subscription guidance screen whether the user has purchased a Nintendo Switch Online membership.

Content Displayed in the Subscription Guide

The system changes the screen displayed by the nn::err::ShowError() function that prompts the user to subscribe based on the following two conditions.

  • Whether the active users of the application all have Nintendo Switch Online memberships
  • The number of active users (described later) of the application
Info:

Conditions for Becoming an Active User of the Application
The user is considered active if all of the following criteria are met.

  • The user account is Open (logged in) in the application.
  • The user account is linked to a Nintendo Account, and is in an active state.

It is possible to perform handling using the nn::err::ShowNetworkServiceError dedicated error display function, provided in versions of NintendoSDK earlier than 8.1.0. However, we do not recommend it.

Conditions for Displaying the Subscription Guide

The subscription guide is not displayed if all of the active users of the application have Nintendo Switch Online memberships at the time the nn::err::ShowError() function makes this determination. However, the subscription guide is displayed if there are zero active users of the application.

In addition, the subscription guide is not displayed if the Switch is not connected to the internet, or the system cannot get the Nintendo Switch Online membership status from Nintendo's servers.

Conditions for Displaying a Link to Nintendo eShop in the Subscription Guide

If one or more active users of the application have not subscribed to Nintendo Switch Online, the subscription guide screen that is displayed changes depending on how many active users within the application do have memberships.
If the application has only one active user, a link to the Nintendo Switch Online subscription page in Nintendo eShop is displayed. If the application has two or more active users, or zero active users, the link to Nintendo eShop is not displayed.

Handling After Displaying the Subscription Guide

The Nintendo Switch Online membership status on the NEX server is saved when the user logs in to the NEX server. The membership status is determined based on the NSA ID token information.

For this reason, if the user subscribes to Nintendo Switch Online from the subscription guide shown by the nn::err::ShowError() function, you must perform the following handling in the application to destroy the previous membership status information.

  1. Log out from the NEX server (if already logged in).
  2. Get the NSA ID token for the user again.
Info:
  • This process of logging out again does not violate guideline #0024: Prohibition of unnecessary sign-ins to game servers in the Nintendo Switch Guidelines.
  • If the error that occurs due to a lack of a Nintendo Switch Online license is passed to the nn::err::ShowError() function, the NSA ID token cache is normally destroyed. However, if the Switch is not connected to the internet, or the system could not get the Nintendo Switch Online membership status from Nintendo's servers, the NSA ID token cache is not destroyed.

Samples

Using the NEX Library to Access the NEX Server

When using the NEX library to access the NEX server, use the following procedure to determine whether the Nintendo Switch Online membership status needs to be updated.

if (result.IsFailure())
{
    nn::err::ShowError(result);
    if(nn::nex::ResultAuthenticationNetworkServiceLicenseRequired::Includes(result))
    {
        // Getting the NSA ID token again is required for updating the license state.
    }
}

The result variable used for determination is the nn::Result type, and you can get it using the following functions.

  • To get the result of the login function (nn::nex::NgsFacade::Login())
    • Use nn::nex::NgsFacade::GetLastLoginNnResult() to get the result.
  • To get the results of various asynchronous API functions
    • After using the nn::nex::CallContext::GetOutcome() to get nn::nex::qResult, use nn::nex::qResult::GetNnResult() to convert to nn::Result.
Using the Pia Library to Access the NEX Server

If you are using the Pia library to access the NEX server, see the PiaSession Advanced sample demo and the PiaFramework Simple sample demo in the Pia library documentation.
For PiaUnity, see the PiaShot sample demo.

Using an SDK Earlier Than NintendoSDK 8.1.0

When using an SDK earlier than NintendoSDK 8.1.0, the nn::err::ShowError() generic error display function displays a description of the error but does not display the screen prompting users to subscribe to Nintendo Switch Online.
For this reason, use the nn::err::ShowNetworkServiceError() dedicated error display function.

Note:

When using an SDK earlier than NintendoSDK 8.1.0, not using the dedicated error display function violates 0163: Implementing Handling for Features Requiring a Nintendo Switch Online Membership. If errors occur under the following conditions, be sure to use the dedicated error-display functions.

Packages Containing the Dedicated Error-Display Functions

The following functions are used for the error handling described on this page.

  • nn::err::IsNetworkServiceError()
  • nn::err::ShowNetworkServiceError()

These functions are included in the following versions of NintendoSDK.

NX Add-On 4.x.x NX Add-On 4.6.0 or later
NX Add-On 5.x.x NX Add-On 5.6.0 or later
NX Add-On 6.x.x NX Add-On 6.3.0 or later
NX Add-On 7.x.x or later All versions
Info:

They are deprecated in NX Add-On 8.1.0 and later.

Using the Dedicated Error-Display Functions

Call nn::err::ShowNetworkServiceError() if the nn::Result::IsFailure() function returns true as the result of an NEX asynchronous process and the nn::err::IsNetworkServiceError() function returns true.

The user account will be guided to subscribe to Nintendo Switch Online. Make sure that you specify the appropriate nn::account::UserHandle for the argument of the nn::err::ShowNetworkServiceError() function so the user account that was responsible for the executed NEX asynchronous process is the same user account that is prompted to subscribe.

If only one user account is in the open (logged in) state, you can call the nn::err::ShowNetworkServiceError() function without passing a nn::account::UserHandle value for the argument. If multiple user accounts are in the open (logged in) state, such as when multiple user accounts in the same application are logged in the NEX game server, you must specify nn::account::UserHandle.

  • If nn::account::UserHandle is not specified for the argument:
    The process transitions to the process for membership purchase by the user account indicated by the user in the open (logged in) state.
  • If nn::account::UserHandle is specified for the argument:
    The process transitions to the process for membership purchase by the user account indicated by the specified handle.
Note:

If the user purchases a membership inside the process of the nn::err::ShowNetworkServiceError() function, you must get the NSA ID token again to apply the purchased license in the application.
The application cannot determine whether the user has purchased a membership inside the process of the nn::err::ShowNetworkServiceError() function.
Note that if the nn::err::ShowNetworkServiceError() function is called while logged in to the NEX game server, you must log out from the NEX game server after calling the function.
If the user has purchased a membership, the way to enable the license is to get the NSA ID token again after logging out and then logging back in.

This process of logging out and logging in again does not violate guideline #0024: Prohibition of unnecessary sign-ins to game servers in the Nintendo Switch Guidelines.

Info:

You do not need to call nn::err::ShowNetworkServiceError() if the nn::err::IsNetworkServiceError() function returns false. Handle the errors as described in each library.

Samples

The following code samples are examples of error handling when there is only one user account in the open (logged in) state.

Login Functions
pNgsFacade->Login(&oContext, gameServerId, accessKey, nsaId, nsaIdToken);
oContext.Wait();
if (oContext.GetState() != nn::nex::CallContext::CallSuccess)
{
    nn::Result result = pNgsFacade->GetLastLoginNnResult();
    if (result.IsFailure())
    {
        if (nn::err::IsNetworkServiceError(result))
        {
            nn::err::ShowNetworkServiceError(result);
        }
        else
        {
            // Error handling by functions like nn::err::ShowError().
        }
    }
}
Various Asynchronous Functions
pRankingClient->GetRanking(&oContext, rankingMode, rankingCategory, orderParam, &rankingResult);
oContext.Wait();
if (oContext.GetState() != nn::nex::CallContext::CallSuccess)
{
    nn::Result result = oContext.GetOutcome().GetNnResult();
    if (result.IsFailure())
    {
        if (nn::err::IsNetworkServiceError(result))
        {
            nn::err::ShowNetworkServiceError(result);
            // Log out, because you need to get the NSA ID token again to update the license status.
        }
        else
        {
            // Error handling by functions like nn::err::ShowError().
        }
    }
}
