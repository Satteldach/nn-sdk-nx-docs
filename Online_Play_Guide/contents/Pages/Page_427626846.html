7.4 Checking the Network Connection at the Appropriate Times During Online Play (for Developers)

The user's network connection might become unavailable while connected to the NEX or NPLN server or an independent server. This issue applies in situations where the connection to the wireless LAN access point is severed, or the Switch is waking from sleep mode.
In this type of case, if you use a function that communicates with the server when the network connection is unavailable, the cause of communication failure may not be communicated appropriately to the user.
For this reason, we recommend calling nn::nifm::IsNetworkAvailable() at appropriate times to check the network connection.

Appropriate Timing

Determine the appropriate timing to call nn::nifm::IsNetworkAvailable() based on the application specifications. For example, consider calls at the following timing.

  • Calling the function each frame while connected to the server
  • Calling the function before executing a function that communicates with the server

Handling After Connection Check

If a network disconnection is detected using nn::nifm::IsNetworkAvailable(), consider notifying the user according to your application's specifications.

Also note the following.

  • It is not always necessary to notify the user immediately after detecting disconnection.
    • Example: Notify the user at the time when the user explicitly chooses to use network features for the first time after disconnecting from the network.
  • You do not have to use error handling from calling nn::nifm::HandleNetworkRequestErrorResult() to notify the user.
    • Example: If a network disconnection is detected during an online match, change the match opponent to automatic control mode and notify the user without interrupting the match.
  • If communication with the server does not affect the user experience, an error notification does not need to be sent.
    • Example: Do not send a notification when collecting the user's play history on the server.
