5.3 Selecting the Ban Method

This section describes how to implement application-specific bans.

Application-Specific Bans

The following table shows the two types of application-specific bans. The usage restrictions can be applied to NEX, NPLN, and independent servers.
For more information, see 5.1 Ban Overview.

BAN Name Information Required for Bans
NSA App Ban
  • NSA ID
Device App Ban
  • NSA ID (common to NEX, NPLN, and independent servers)
  • For NEX and NPLN:
    The last login date and time (can be checked on BMAS)
  • For independent servers:
    bs:did value contained in the NSA ID token (written as the login ID in BMAS)
    Or
    The last login date and time (can be checked on BMAS)
Info:
  • For more information about the bs:did value contained in the NSA ID token, see 5.2 Implementing Bans.
    For more information about using an independent server, see the Nintendo Switch Independent Server Setup Manual.
  • Authentication is shared across NEX, NPLN and independent servers. When a ban is implemented, all features on NEX, NPLN, and independent servers become unavailable.

Implementing Application-Specific Bans

When implementing application-specific bans, use one of the following two methods.

Recommended: Method That Only Applies an NSA App Ban

We recommend using an NSA app ban for application-specific bans. This is because if you use both an NSA app ban and a device app ban (the method described below), there is a chance of banning Switch consoles that are not in the possession of the user you are banning.

Implementing an NSA app ban restricts the network service account of the target from using the network features of the application.

When the Nintendo Account is linked to user accounts on multiple Switch devices, the network service account for these accounts is the same, so the NSA app ban prevents using network features on multiple Switch devices.

If the account that is the target of the ban has a Nintendo Switch Online membership, you can synchronize save data using the Save Data Cloud backup feature.

Method That Applies Both an NSA App Ban and a Device App Ban

With only an NSA app ban, you cannot prevent a user from creating a succession of new user accounts, linked to a Nintendo Account on a Switch, and using those accounts to continue the behavior that caused the ban. In addition, if the user creates a new Nintendo Account, it is possible for them to use the Nintendo Switch Online 7-day free trial with that account and use services that require a Nintendo Switch Online membership.

To prevent these types of cases from occurring, consider using both an NSA app ban and device app ban.

Notes About Applying Device App Bans

When applying a device app ban, make sure that this ban does not apply to Switch devices that are no longer owned by the user whose activities caused the ban. All of the Switch devices that have been linked even one time with the applicable Nintendo Account are listed in BMAS. Some of these Switch devices may no longer be owned by the user to whom the NSA app ban was applied, and may be currently owned by other users.

Use the following information to determine whether a Switch device is owned by the user targeted by the ban.

  • bs:did value contained in the NSA ID token (written as the login ID in BMAS)
    • On an independent server, you must get the target user's bs:did value from logs or other sources.
  • The last login date and time (can be checked on BMAS)
    • You can use this information to determine whether the device has been used recently by the user who is the target of the ban.
