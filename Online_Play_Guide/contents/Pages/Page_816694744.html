6 Compatibility With Earlier Versions of an Application

Cases Where There Is a Need to Break Compatibility With Earlier Versions

The Switch patch mechanism does not ensure that all users play the patched version of the application following the release of the patch. As a result, there is always a possibility that access to the independent server or the NEX/NPLN server comes from a mix of both the unpatched application (earlier versions) and the patched application (the latest version).

If access from earlier versions of the application causes problems, you must stop such access so the features of the independent server or the NEX/NPLN server are unavailable to earlier application versions.

If there is no problem with access from earlier application versions, there is no need to stop access to the independent server or the NEX/NPLN server from earlier versions.

Block Earlier Releases Gradually Using the Nintendo Authentication Server

If it is not necessary to block access from earlier versions of the application at the same time that the patch is released, you can set the Nintendo authentication server to break compatibility gradually.

This method works for both independent servers and the NEX/NPLN server.

Configuring the Nintendo Authentication Server

When you set the distribution information for the patch in NCMS, select Force Update Flag (block earlier releases using authentication server) > Force Update for that patch.

Info:

Nintendo Content Management System (NCMS) is a web tool for registering products to sell on Nintendo eShop. You can access it from the link in the Nintendo Developer Portal.

For more information about using NCMS, see NCMS Manual, which you can access from the NCMS menu.

Behavior When the Force Update Flag Is Enabled

If you selected Force Update Flag (block earlier releases using authentication server) > Force Update for the patch in NCMS, that setting is applied to the Nintendo authentication server when the patch is distributed.

When the application gets an NSA ID token (by calling the nn::account::EnsureNetworkServiceAccountIdTokenCacheAsync() function), an error belonging to the nn::account::ResultNetworkCommunicationError class (2124-3001) is returned to earlier (unpatched) versions of the application and they can no longer get an NSA ID token. This error is normally shown by the error viewer applet, and a message appears in the error viewer applet explaining that the application must install the latest patch.

Info:

In the development environment, patches cannot be distributed and settings cannot be configured for the Nintendo authentication server.

You can generate the 2124-3001 error using the web tool. For more information about generating the error, see Nintendo Switch Network Error Simulation Manual.

You must get an NSA ID token before you can access an independent server and the NEX/NPLN server, so until the application gets a new NSA ID token, the user cannot access the independent server or the NEX/NPLN server.

Notes

Note that, even if you have configured the authentication server so earlier versions of the application cannot get an NSA ID token, earlier releases cannot be blocked immediately after the patch has been distributed for the following reasons.

  1. Even if the Nintendo authentication server has been set, it can take about a day for the setting that generates the error to be applied to all users.
    • The Nintendo authentication server authenticates the legitimacy of the application, but that information is cached on the Switch for about a day.
      While this cache is valid, the application version is not checked when the application gets an NSA ID token, so it gets an NSA ID token without an error.
  2. Earlier releases cannot be blocked while the session with the server is active.
    • If the Nintendo authentication server is set to force the update, access to the server is blocked by making it impossible to get an NSA ID token.
      For this reason, access to the server cannot be blocked while the session between the application and the server is active as long as the user does not need to get an NSA ID token.

Block Earlier Releases Immediately

If you need to block access from earlier versions of the application at the same time that the patch is released, you must handle it using the independent server and the NEX/NPLN server.

Independent Servers

If access to the independent server from earlier versions of the application causes problems, you can block access from earlier versions by taking all of the following measures.

  • End active sessions between Switch and the independent server at the same time that the patch is released.
  • Use the independent server to check the application version value that is included in the NSA ID token, and deny access if the version is an earlier version.

For more information, see Nintendo Switch Independent Server Setup Manual > Independent Server Development.

NEX/NPLN Server

If access to the NEX/NPLN server from earlier versions of the application causes problems, you can block access from earlier versions by taking all of the following measures.

  • Add the setting to the Nintendo authentication server using the method described on this page in Configuring the Nintendo Authentication Server.
  • When submitting the patch on OMAS, select Yes for Block Earlier Releases From Connecting to NEX/NPLN Server.
Info:
  • Prior to the OMAS server update in October 2021, Block Earlier Releases From Connecting to NEX/NPLN Server was called Restart NEX Server When Patch Is Released.
  • For NEX, also see Nintendo Switch NEX Guide > Tips and Tricks > Patches and Compatibility.
