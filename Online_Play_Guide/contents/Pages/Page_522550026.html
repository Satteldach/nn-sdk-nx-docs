3.5 Friend Invitation

The friend invitation feature is a mechanism by which users invite friends to play over the internet. Invitations can even be sent to friends who are offline.
For a user to use the friend invitation feature, you must first implement the application in a way that supports the feature.

Info:

The friend invitation feature is provided in NintendoSDK NX Add-On 9.3.0 and later. Portions of the feature are also provided in NintendoSDK NX Add-On 9.2.0.

For more information about support by the application, see 3.7.5 Supporting the Friend Invitation Feature.

Note:

The friend invitation feature is supported in Switch consoles for China starting in system version 10.x.x or later.

To use the friend invitation feature in the development environment, use a version of the NintendoSDK firmware that corresponds to NX Add-On 10.x.x and can be used to submit master ROMs.

Planning

System features like User Page and overlay notifications use the expressions "Send invitation" and "Join" in the context of inviting friends to play. In planning, consider designs that use the friend invitation feature within the scope of these expressions.

Procedure From Inviting to Joining

The following steps show that the procedure starts with one user sending an invitation to a friend, and ends with the friend who received the invitation joining the first user in online play.

  1. The user who makes the invitation begins online play.
  2. This user sends an online play invitation to a friend.
  3. The other user receives this invitation.
  4. The user who received the invitation checks the invitation in their User Page and joins.
  5. The user who received the invitation joins the user who made the invitation in the application.

Inviting Friends

You can invite friends from inside the application. Invitations are made using the friends library API.

Invitations must contain the following parameters.

  • Information needed for joining
  • Friends to invite
  • An invitation message

For more information about each of these parameters, see the following sections.

Information Needed for Joining

In the friend invitation feature, the user who is making the invitation sends the information required for joining in online play, and the user who receives the invitation uses that information to join.

For NPLN, set this parameter to the game session ID of the matchmaking session, for example. The user who receives the invitation joins the online play session of the user who made the invitation based on this received information.

If you have prepared your own matchmaking feature using an independent server, you can provide the same experience to users by including in this parameter information that specifies which matchmaking session to join.

Friends to Invite

You can use either of the following methods to choose which friends to invite.

  • Use the My Page applet.
    • In this method, you call the My Page applet and choose which friends to invite from inside the applet.
    • You can specify in the application how many friends to invite. (The maximum is 16 friends.)
    • For more information, see 3.7.3 Calling the My Page Applet.
  • Prepare your own UI in the application.
    • In this method, you implement your own UI in the application to display the list of friends and select who to invite.
    • The invitations are sent by the My Page applet. The list of friends to invite that was selected inside the application is specified in the friends library API for sending invitations.

The invitations can be sent even to friends who do not have the application for which the invitation is being made, and to friends that are offline at the time of the invitation.

Info:

When using your own UI for friend invitation, the friend invitation does not reach the user if you select a user who is not a friend and send a friend invitation to the user (in system version 9.1.0 and later).

Invitation Message

This message is attached to the invitation. Users who receive the invitation can check this message in their User Page.


The application must prepare this message in advance. This invitation message must be configured in every language supported by the application.

Info:

When sending the invitation, the application registers an invitation message in each language.
Out of the registered invitation messages, the application displays the invitation message that has the highest priority according to the system language to the side that has received the invitation.
For more information about system languages and UI language priorities, see Nintendo Switch System Feature Guide > Appendix > How UI Languages Work.

To give an example, if the invitation message has been registered in French and German in the application and the invitation is sent to a user whose system language is Japanese, the message will be displayed to that user in French.

Note:

Do not allow users to enter their own text created as user-generated content in these invitation messages.


Receiving Invitations

Checking Invitations

Users who receive an invitation can check what the invitation is about in the following places.

Invitation List in the User Page

Users can look on their User Page to see a list of the invitations that have been sent to them.

By opening the details for an invitation in the User Page and selecting Join, the user accepts the invitation and joins online play.

Info:

In the development environment, when an invitation is displayed in the User Page for an application that is not installed on the development hardware, the icon and the name for that application are not displayed correctly. This issue is a result of the design of the development environment.

Overlay Notifications

When the user logs in to (opens) their account, notification is provided of the number of invitations that have been sent to that user.

When an invitation comes to a user on the Switch system, notification of that invitation is made if either of the following conditions are satisfied.

    • The account of the user receiving the invitation is logged in (open) in any running application.
      (This condition is satisfied if the user is logged in (open) in any application, and not just the application for which the invitation has been made.)
    • No user account is logged in (open).
      (This includes situations where no application is running. If multiple users have invitations, they are all notified.)

Joining Through Invitation

Joining through invitation takes place via the User Page. To join, the user opens the details for the invitation on the User Page and selects Join.
The behavior at this point differs depending on the status of the Switch and the account that received the invitation.

In the following table, "the application that is the subject of the invitation" can sometimes refer to multiple applications. For more information, see Sharing Invitations Among Multiple Applications, described later.

Status of Switch and Account (for multiple applications, the AND condition applies) Behavior
  • The user account does not have the application that is the subject of the invitation.
    (The rest of the following items assume that the user has the application that is the subject of the invitation.)
  • The user is guided to the product page on Nintendo eShop.
  • No application is running on this Switch.
  • The application that is the subject of the invitation is started, and the application is notified of the invitation information.
  • Another application that is not the subject of the invitation is running on this Switch.
  • A dialog box is displayed to confirm whether it is okay to end the currently running application.
  • If the currently running application has ended, the application that is the subject of the invitation is started, and the application is notified of the invitation information.
  • The application that is the subject of the invitation is running on this Switch.
  • The behavior varies depending on the application's metadata (the NMETA file).
  • For more information, see the next section, Joining Through Invitation to a Running Application.

The processes for joining online play are performed by the application after it has received the information needed for joining.
For example, if you have set the NPLN game session ID as the information for the join-in feature, the application handles the process of joining a matchmaking session based on that game session ID.

Info:

In the development environment, you cannot join through an invitation in DevMenu even if you receive a notification. Go to Debug > Initial Boot Menu, change the setting to HomeMenu, then join the invitation from the User Page. If you just want to simulate the situation where an application starts from a friend invitation, use DevMenuCommand with the set-friend-invitation option. For more information, see NintendoSDK Documents > Features > Controlling the Development Hardware > DevMenuCommand > Friends Feature.

Joining Through Invitation to a Running Application

If the application that is the subject of the invitation is already running on Switch, the behavior of joining through invitation to online play for that application differs depending on the value that has been set in the NMETA file.

Info:

The setting for RuntimeParameterDelivery is available in NintendoSDK NX Add-On 9.2.0 and later. This setting cannot be configured in earlier versions.

Parameter Value Set Behavior
RuntimeParameterDelivery Always
  • Notifications are sent for invitations for the running application.
  • The application must support the friend invitation feature to get notifications of invitations from friends while it is running.
AlwaysIfUserStateMatched

The behavior differs depending on whether the user that is getting the invitation is the only user logged in (open) in the application that is the subject of the invitation.

  • If the invited user is the only user logged in (open) in the application
    • Notifications are sent for invitations for the running application.
    • The application must support the friend invitation feature to get notifications of invitations from friends while it is running.
  • If the invited user is not logged in (open) in the application,
    or if some user other than the invited user is also logged in (open) in the application
    • A dialog box is displayed to confirm whether it is okay to end the currently running application.
    • If the currently running application has ended, the application that is the subject of the invitation is restarted, and the application is notified of the invitation information.
OnRestart
  • A dialog box is displayed to confirm whether it is okay to end the currently running application.
  • If the currently running application has ended, the application that is the subject of the invitation is restarted, and the application is notified of the invitation information.

If no value has been set for RuntimeParameterDeliver in the NMETA file, it is set automatically to Always.

If it is difficult for the application to get notifications of invitations from friends while running, set this parameter to OnRestart.

Sharing Invitations Among Multiple Applications

In some cases, such as when the same title is released in different variations, you may want to support joining through invitation even among applications with different application IDs.
If you set the same value for the presence group ID in the NMETA files of these different applications, the applications can exchange join-in information.
For more information about setting up the presence group ID, see 3.7.5 Supporting the Friend Invitation Feature.

The condition for the application that is the subject of the invitation as described in Joining Through Invitation is that the presence group ID of the application is the same as for the application that sent the invitation.

If the user has multiple applications with the same presence group ID, a dialog box is displayed prompting the user to choose which application to start when they respond to the invitation and join from their User Page.

Info:

If invitations will be shared among applications that support different languages, we recommend that you register the invitation messages in all of the different supported languages in each application. Support for this functionality is not required.

We recommend this functionality because, as described in Invitation Message, the invited user might receive an invitation message in a language that they do not normally use.
