5.3 Limitations and Important Information

Limitations on Content and Items

The following limitations apply to each application. The distribution infrastructure can be a concern even when these limitations are satisfied, so contact Nintendo in advance if you are planning downloadable content that involves many pieces of content or large downloadable data.

Subject Limitation
Pieces of content 2000
Items

16,000
Size of one piece of content

10 GB
(32 GB if there are no updates after the content is released.)
Size of files that can be submitted at the same time 64 GB

In addition, note the following about the size of the content.

  • Users cannot specify and delete individual pieces of downloadable content when they remove the downloadable content for an application using the HOME Menu. Pay special attention to this point if you plan to distribute a large volume of large-sized pieces of downloadable content.
  • Unlike patches, downloadable content does not support partial updates. When there is an update, all of the data must be re-downloaded, so avoid making updates to large pieces of downloadable content. If you are making frequent updates, use a method such as setting a flag in the downloadable content and including the data in a patch.

Timing When DLC Becomes Available

Applications can only reference DLC that is available for use at the time the application is started. For this reason, DLC that is downloaded while the application is running only becomes available after the application restarts.
However, note that there is an optional feature for enabling DLC even when the application is running. For more information, see NintendoSDK Documents > aoc Library.

Controlling What DLC Can Be Purchased

You cannot control what DLC a user can purchase in Nintendo eShop. For example, the items available for purchase cannot be changed depending on progress in the game.

However, you can use the feature for getting information within applications and the feature for hiding products in Nintendo eShop together to control what DLC a user can purchase.
For more information, see 2.3 Feature for Getting Information Within Applications and 8.1 Common > Setting Products to Be Hidden in Nintendo eShop.

Sharing Downloadable Content With Other Applications

You cannot create downloadable content that can be referenced and used by multiple applications.

Info

The demo version and full retail version of the same application are treated as separate applications. You cannot have the trial version and retail version reference and use each other's DLC.

To use the same content in multiple applications, you must get that downloadable content for each application. The following examples show ways that the downloadable content for one application can be made available when the downloadable content for another application is obtained.

  • Privilege Grants
    • With this feature, when a user purchases the downloadable content for one application, a license is granted for the other application's downloadable content.
      However, an icon is shown in the HOME Menu when the other downloadable content is obtained, which might be confusing to users who do not own that application.
  • Owner Discounts
    • With this feature, when a user purchases the downloadable content for one application, the other application's downloadable content is made available free of charge.
      However, only DLC that is currently being sold can be made free of charge.

For more information about each feature, see 3.4 Sales Options (Discounts, Buyer Benefits, Download Codes, Pre-Orders, Season Passes).

Updating Downloadable Content That Has Already Been Released

Note the following when updating data containing downloadable content or information on Nintendo eShop for downloadable content that has already been released in the production environment.

Compatibility With the Application

When you update the data for downloadable content, make sure that there are no bugs that would stop any version of the application on which that content can run. By setting required application release versions for the content, you can restrict which versions of the application can be started after the content has been installed.

Updating the Downloadable Content Data

If you are going to update the data for downloadable content that has already been distributed, make sure that the user is not disadvantaged in any way.

When downloadable content is updated, users that have earlier versions of the downloadable content installed can update to the latest version of the downloadable content. Make sure that the features available to users in earlier versions remain available in such situations.

Changing Item Names

When the name of an item is changed in NCMS, the item name that is shown in Nintendo eShop also changes (see 4.4 Distribution). However, the item name is not changed in the receipt sent to users who already purchased that item.

Selling Items Exhausted Within the Application

Avoid using the downloadable content feature to implement items that are exhausted within the application. An example would be selling an item such as a "10-pack of medicinal herbs" in large amounts as downloadable content containing only flag data, and then for each purchased item checking that flag data in the application and saving the license information in the user save data. For this type of use case, consider using consumable service items rather than downloadable content.

Using a Patch to Distribute Resource Data for DLC

In some cases, the game might not work for users who have not purchased the DLC if they do not have the relevant resource data. An example would be when a user who purchases DLC in a fighting game fights a user who has not purchased the DLC. To handle this type of situation, you can distribute the required resource data as patches, and then sell a flag for using (unlocking) that data as downloadable content.

This method requires all users who have not purchased the DLC to also receive the patch data. As much as possible, reduce the amount of resource data distributed through the patch to reduce the patch size to a minimum.
