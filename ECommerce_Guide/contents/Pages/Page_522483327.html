5.2 Using in Applications

Downloading Downloadable Content

Downloadable content must be downloaded for the user to use it inside the application. View the HOME Menu to see whether there is content still being downloaded and installed.

If the application is running, the downloadable content does not become immediately available by default when it has completed downloading. The same is true for downloadable content purchased via the ec applet. Instead, the downloaded downloadable content becomes available after the application has been restarted. The same holds when the content for sale contains no data but rather serves as a flag indicating possession to unlock certain features inside the application.

Info

To determine whether the user owns the downloadable content, you must check whether the downloadable content can be mounted using nn::fs::MountAddOnContent().

Using Downloadable Content Downloaded When the Application Is Running

An optional feature allows downloadable content that was downloaded while the application was running to be used without closing the application. For more information, see NintendoSDK Documents > Features > System > AOC Library.

Deleting and Redownloading Content

Users delete downloaded content data using the system settings. Content cannot be deleted alone. All content and patches linked to the application are deleted together. For downloadable software, the downloadable software itself is also deleted.

Content is re-downloaded through Nintendo eShop. Nothing needs to be implemented in the application.

Updating Downloadable Content

The system does not automatically update the downloadable content. To perform an update, the user must go to the HOME Menu, select the icon for the application, and select the update button. That said, if a patch and downloadable content are distributed at the same time, the downloadable content will be updated automatically.

If the version of downloadable content currently installed in the application is not allowed, you can prompt users to update the downloadable content by calling nn::err::ShowUnacceptableAddOnContentVersionError(). When you perform an update, the application restarts and then the updated content is downloaded and installed.

Required Application Release Version

You can set a required version for an application that would be needed to use content. You can do this for each content item on the Nintendo Switch. This version is called a required application release version. When a required application release version has been set, versions of the application that do not satisfy that version requirement cannot access the downloadable content.

For example, suppose you have content A and content B, and the former requires application release version 1, while the latter requires release version 2. Also suppose that the user has downloaded both A and B. If only the patch for version 1 has been installed in the application, when the user starts that application it can only reference content A, and not B. By installing the patch for version 2, the application can reference both A and B.

If the application is started in a state that does not satisfy the required application release version, the HOME Menu prompts the user to update the application.

Advantages

Setting the required application release version offers the following advantages.

  • You do not have to consider the compatibility of earlier versions of applications and new downloadable content.
    • Restricting the application version that can run when specific content is installed reduces the combinations of applications that require debugging and versions of downloadable content.
  • When a patch is required for using content, the application does not need to inform users of the patch.
    • If a required application release version is configured for content, the system ensures that users with that content installed must apply a patch of the same version or later than that required application release version.

Nintendo Switch Systems and Accounts That Can Use Licenses

For more information about sharing licenses for downloadable content, see 9.2 Relationship Between Nintendo Accounts and Licenses.

Considerations When Associating Downloadable Content With Save Data

When developing applications that support downloadable content, consider the possibility that downloadable content that was available at one time may become unavailable in the future.

Show specific examples of such cases.

The following examples are specific cases where downloadable content becomes unavailable.

Example 1: Cases Where the License to the Downloadable Content Can No Longer Be Used, but the Application Remains Usable

The license for downloadable content is associated with the Nintendo Account that made the purchase (see 9.2 Relationship Between Nintendo Accounts and Licenses), so the downloadable content will become unusable on Switch if any of the following operations are performed on the Nintendo Account that possesses that license.

  • The Nintendo Account linked to the user account on the Switch system is deleted.
  • The primary console registered for the Nintendo Account, linked to the user account on the Switch system, is set to a different Switch system.

Even if the downloadable content can no longer be used due to one of these operations, the application itself can still be used if either of the following conditions apply.

  • The user possesses the card version of the application.
  • A console, on which the download software is owned by a different Nintendo Account, is set as the primary console.

Example 2: Cases Where the Storage Location of the Downloadable Content Becomes Inaccessible

Downloadable software and downloadable content are saved to either system memory or a microSD card. The download data is preferentially saved to a microSD card, but if a card is not inserted or lacks sufficient space, the data will be saved to system memory instead.

If the user has the card version of the application or if the downloadable software has been saved to system memory, there may be cases where downloadable content becomes unavailable because it has been saved to an microSD card and that card has been removed.

Example 3: Cases Using the Save Data Cloud Backup Service Offered With Switch Online to Move the Save Data to a System Where the Downloadable Content Has Not Been Installed

When using the Save Data Cloud Backup service offered by Switch Online, users might back up the save data on the system where they originally installed and used the downloadable content, and then download that same save data to a different system where the downloadable content has not been installed.

As a result, there may be cases where save data created in the presence of downloadable content may be loaded at a later time after that downloadable content is no longer available. In such cases, to ensure that save data on the application side is consistent, we recommend specifications that allow save data to be loaded even when downloadable content can no longer be used. Because the handling of save data depends on how the application is implemented, there are no restrictions against specifications that prevent loading data when in a state where downloadable content cannot be used.

Instructing Users When Content Cannot Be Found

Call the nn::aoc::ShowAddOnContentLostError() function to inform the user that the downloadable content is not available. A message like the following is displayed. For more information, see nn::aoc::ShowAddOnContentLostError() in the NintendoSDK API Reference.

Cannot find the downloadable content that you have been playing with.
Re-download the downloadable content from Nintendo eShop.
You can purchase it from Nintendo eShop if you have not done so already.

Requiring Certain Downloadable Content to Start the Application

If you set information about required downloadable content in the application's metadata, you can prevent the application from starting without that content. For example, consider the case where the application is just the base program and is not sold individually, but only in combination with either the Story A downloadable content or the Story B downloadable content. In this case, you can set the application so it cannot even start without Story A or Story B. For more information, see NintendoSDK Documents > Features > System > aoc Library > Features for Downloadable Content Provided Outside the aoc Library.
