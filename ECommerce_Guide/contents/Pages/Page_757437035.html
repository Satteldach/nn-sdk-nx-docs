8.1 Common

This section describes common specifications and considerations when using the feature for getting information within applications.

How to Use

Feature for getting information within applications use the nn::ec::ShopServiceAccessor class.

The following workflow shows how information is acquired and jumps to the shop occur.

  1. Specify the URL path string corresponding to the type of information you want to get in nn::ec::ShopServiceAccessor::Request().
  2. Get the JSON file as the response to nn::ec::ShopServiceAccessor::AsyncResponse::Get().
  3. Parse the JSON file to get the information, and then display it in the application.
  4. Specify the identifier of the product selected by the user, and jump to the shop.

For more information, see the API description in the NintendoSDK API Reference or the EcCatalog.

Setting Products to Be Hidden in Nintendo eShop

Products with this setting are not displayed when Nintendo eShop is started from the HOME menu. They are displayed only when the jump to eShop is made by specifying a product from within the application. Because you must go through the application to get to the shop, using this feature allows you to add the following conditions to product purchases.

  • Ensure that an application-specific account has been created before purchasing.
  • Provide sufficient description of the product content before purchasing.
  • Divide products according to where they can be purchased within the progress of the game.

The settings for hiding products in Nintendo eShop must be configured by Nintendo in NCMS. For more information, contact Nintendo.

Notes About Hiding

Not Displayed in Lists

Note that if a product is set to be hidden, it will not be shown if the jump to eShop is made using one of the following functions that display lists of item information.

  • Showing the list of downloadable content
    nn::ec::ShowShopAddOnContentList()
  • Showing the list of consumable service items
    nn::ec::ShowShopConsumableItemList()
  • Showing the list of subscription service items
    nn::ec::ShowShopSubscriptionList()

For this reason, to jump to an item that has been hidden on eShop, make sure to use a function that specifies the item.

Sometimes Displayed in Unexpected Cases

Note that hidden products might be displayed in the following kinds of cases.

  • A malicious user accesses eShop in an unauthorized manner.
  • There is an issue with the application.

Use Cases Where Other Features Are Recommended

Consider using a different feature in the following use cases.

  • When applying temporary discounts
    Use the temporary discount function.
  • When selling items that can only be obtained once within the application
    Use the purchase limit function.
  • When selling items for free under certain conditions, such as purchase bonuses or individual code entry
    Use the coupon function.

Requesting the Feature for Getting Information

You must make a request on OMAS to use this feature. In OMAS, in the list of e-commerce items, select Use the Ability to Get Item Information, and then select the target.

Development Environment Verification Settings

To validate this function in the development environment (dd1), each product must be registered with NCMS. For more information, see 4.2.1 NCMS Settings for Development.

A function is provided as a debugging feature that displays an overlay notification of the requested information on the screen when accessing Nintendo eShop from the application. For more information, see NintendoSDK Documents > Features > System > ec Library > Debugging > Notifications of Access to Shop Services.

Important Information When Using Features for Getting Information

Parsing a JSON File

The item information that can be obtained from Nintendo eShop is in JSON format. There is a possibility that additional elements may be added to the JSON with future changes to the Nintendo eShop server. Make sure that you consider such changes in the response when your application parses the JSON response. Specifically, see the following important information.

  • NintendoSDK Documents > Features > System > ec Library > Debugging > Response Simulation Feature.
  • NintendoSDK Documents > Features > System > ec Library > Debugging > JSON Compatibility Check Feature.

The item information that can be obtained as a response is not sorted. To control the display sorting within the application, the application must support the item tag information described in the following section.

Using the NsUID

The NsUID (an ID identifying the item) is included within the item information that can be obtained from Nintendo eShop. To jump to a specific item in Nintendo eShop, pass this NsUID to the jump API. The NsUID value is different in each of the development environments, Lotcheck environment, and production environment. For this reason, do not embed the NsUID in the application. Always use the value obtained through the feature for getting service item information.

Frequency of Calling nn::ec::ShopServiceAccessor::Request()

Making frequent calls to the nn::ec::ShopServiceAccessor::Request() function can increase the time it takes for a response to return. As a rough guide, call this function no more than about 15 times in any minute.

Please make calls as necessary. For example, if you always call the function each time the application is started, there is a possibility of a wave of access to the Nintendo eShop server, such as immediately after maintenance completes on the independent server used by the application. For this reason, we recommend avoiding such specifications and only calling the function when required, such as when the user actively moves to the in-application eShop.

If possible, consider caching the obtained information for a period of time, including prices. However, if the price is changed, the price displayed in Nintendo eShop and the price in the in-application shop will not match for a time, which may create a disadvantage to the user. If you plan to change prices, consider not caching price information, or shortening the cache duration.

Because the Nintendo eShop server is shared by all applications, there is the risk of users being unable to make application purchases if the load becomes heavy. Consider an implementation that reduces the load as much as possible.

Parameters for Requests to Get Information

ShopServiceAccessor Alias Replacement

The ShopServiceAccessor alias replacement feature replaces {applicationId} with the application ID configured in the application's metadata (the NMETA file), and {country} with the country/region of residence of the Nintendo Account making the request. Unless you have a special reason, use the alias replacement function.

If you use the alias replacement function and specify the request in the application as shown below, {applicationId} and {country} will be replaced when you actually make the request to the server.

/v1/applications/{applicationId}/aocs/items?country={country}&lang=ja
Info

When getting information about a title and bundles that include that title, if you are getting information about an application ID that is different from the one set in the metadata (nmeta) of the application, specify the application ID of the application you want to get in {applicationId}.

Information about applications other than the current product cannot be obtained.

lang Parameter

Specify the language used by the application. If the specified language is available, the response is in that language. If not available, the response is in the default language for the country/region of residence of the Nintendo Account specified in the request.

For example, if the country/region of residence of the Nintendo Account specified in the request is the US, the default language is en-US. As a result, if country (the Nintendo Account country/region of residence) in the request is US and the lang parameter is ja (Japanese), the lang in the response will be en-US and the language in the response will be English.

onsale_only Parameter

The onsale_only parameter indicates the sales status of the product. The default is true, which gets information about products in a state where they can be purchased from Nintendo eShop. To get information about products that are not available (registered but not available for purchase), specify false.

Item Tag Information

When getting downloadable content, subscription service items, and title information (including title information for bundles that include that title), a key and value set of information known as item tag information can be acquired as item_tag. For example, the key can specify "equipment" (a category common to the items), and the value can specify "sword" or "shield," which is information specific to the item. Item tag information is set in NCMS.

Item tag information is subject to the following restrictions.

  • Up to 30 tags can be set per item.
  • Duplicate keys cannot be set for a single item.
  • Keys and values may only contain uppercase and lowercase letters (a-z and A-Z), numbers (0-9), dashes (-), underscores (_), commas (,), and single-byte spaces.
  • The maximum length for keys is 64 characters, and the maximum length for values is 512 characters.
  • Empty keys and values cannot be set.

Example:

Item 1 (Wood Sword)
    "key": "equipment", "value": "sword"
    "key": "available_time", "value": "early"
Item 2 (Wood Shield)
    "key": "equipment", "value": "shield"
    "key": "available_time", "value": "early"
Item 3 (Gold Sword)
    "key": "equipment", "value": "sword"
    "key": "available_time", "value": "late"

If You Need to Get Information for Over 100 Products

The limit parameter defines how many products can be obtained at a time, but the maximum is 100. To obtain information on more than 100 items, use the offset element and split the process into multiple get operations. The following example is the process for getting product information for 150 items.


 Request Response
limit offset length total
First Get Operation 100 0 100 150
Second Get Operation 100 100 50 150
