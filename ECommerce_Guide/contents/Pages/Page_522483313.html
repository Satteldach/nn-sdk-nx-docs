5.1 Composition and Development Flow

This section describes the composition and development flow of downloadable content.

Composition of Downloadable Content

Switch downloadable content is composed of one set of metadata and one or more sets of content.

Figure 5-1 Overview of Downloadable Content

The data used inside the application is separated into individual pieces of content. Application developers are free to configure how much data is included within a single piece of content.

Application developers can also assign each piece of content an index value for identification purposes. This index value must be unique across the application. On Switch, each piece of downloadable content is installed and managed individually. Similarly, when working with downloadable content within an application, each piece of content (each index) is mounted separately to access and use the files inside that content. The same is true for Nintendo eShop. As a general rule, individual pieces of content are sold as individual products.

The actual data included in a piece of content consists of a collection of files and directories. There are no particular rules about the naming and hierarchical structure of these files and directories.

The metadata is information in XML format that describes the downloadable content. For more information about this metadata, see NintendoSDK Documents > Features > System > aoc Library.

Development Flow

Figure 5-2 Downloadable Content Development Flowchart

To test your downloadable content in the development environment and submit it to Lotcheck, you must package the content and the metadata together using Authoring Tool. During packaging, which collects multiple pieces of content together, the information about each piece of content is combined with information about the other content as a single set of metadata. There is no need to prepare metadata for each piece of content. In the development environment, the packaged downloadable content can be installed to the Switch development hardware for testing.

Items and Content in Nintendo eShop

The managed unit for selling downloadable content in Nintendo eShop is the item. The item is set with a sales price and a sales period and that information is shown in Nintendo eShop. Items are linked to content. By purchasing an item, the user can download and use the content linked to that item.

Multiple pieces of content can be linked to an item. No warning message is displayed at purchase time if the item contains multiple pieces of content and the user happens to already own some of them. Do not link multiple pieces of content to an item unless the content is being shared among multiple items that are for sale. For example, if you are selling two additional stories that have a common resource, configure multiple pieces of content, including the same content in each additional story, as shown.

Item Pieces of Content
Story A index 1 (resource for story A), index 3 (common resource)
Story B index 2 (resource for story B), index 3 (common resource)

If you want to sell multiple pieces of content together as a set, the normal method is to link each piece of content to a separate item, register all of the separate items, and then sell the items together as a bundle. For more information about the mechanism for bundles, see 3.3 Selling Bundles and Sets.

Items can be purchased from Nintendo eShop and the ec applet. Applications are only required to implement the ec applet call portion for purchases of downloadable content.

Figure 5-3 Items and Content

The sales settings for items in the production environment are configured on NCMS.

The metadata for the content can include information in the form of tags. The tags are not shown in Nintendo eShop, but if you set these tags in the content metadata when you register the sales information on NCMS, you can use them to link items and pieces of content.
