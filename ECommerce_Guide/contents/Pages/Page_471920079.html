8.3 Downloadable Content

This section describes the implementation method, feature specifications, and other important information when using the feature for getting information within applications to get downloadable content information.

Overview

A feature is provided for getting the following information about downloadable content and downloadable content bundles. A downloadable content bundle is a bundle consisting of only downloadable content.

  • Names, descriptions, and disclaimers
  • The release date that appears in Nintendo eShop
  • The downloadable content index (Downloadable content bundles are not supported.)
    For more information about downloadable content indexes, see NintendoSDK Documents > Features > System > aoc Library.
  • The identifier (the ns_uid) for display in Nintendo eShop.

Implementation

Use the following features for getting a list of downloadable content to get downloadable content information. The obtained downloadable content identifier (ns_uid) can also be specified in the jump to eShop API.

Determining Possession

To display only the downloadable content that the user does not possess, use aoc_indexes of the response. The values in aoc_indexes are the downloadable content indexes that were configured in NCMS.
Use the following process to determine ownership and display DLC that is not yet owned.

  1. Use nn::aoc::ListAddOnContent() to get the list of available downloadable content indexes.
  2. Using the DLC indexes acquired in step 1, call nn::fs::MountAddOnContent() for the ROM associated with each DLC index and check the return value.
  3. Use the features for getting the list of downloadable content to get the index for each item of downloadable content.
  4. If a downloadable content index obtained in step 3 is not on the list that was obtained in step 1, display the downloadable content that corresponds to that index.
Info

For more information about nn::aoc::ListAddOnContent() and nn::fs::MountAddOnContent(), see the discussion of those functions in the NintendoSDK API Reference.

As an example, assume you are offering the following downloadable content for sale.

Downloadable Content Downloadable Content Index Notes
Downloadable content A 1
Downloadable content B 2,3 Downloadable content index 2 is shared data used by downloadable content B and C.
Downloadable content C 2,4 Downloadable content index 2 is shared data used by downloadable content B and C.

If a user purchases downloadable content A and B, the results of the nn::aoc::ListAddOnContent() function and the feature for getting a list of downloadable content look like the following.


 Downloadable Content Index
The list obtained by nn::aoc::ListAddOnContent() 1,2,3
The aoc_indexes value for downloadable content A obtained by the feature for getting the list of downloadable content 1
The aoc_indexes value for downloadable content B obtained by the feature for getting the list of downloadable content 2,3
The aoc_indexes value for downloadable content C obtained by the feature for getting the list of downloadable content 2,4

You can tell from these values that the user possesses downloadable content A and B and does possess downloadable content C.

Info

Possession here does not mean that the user has purchased the downloadable content, but rather that the user has the rights to use and has installed the downloadable content. There is no way to determine whether the DLC has been purchased.

Conditions for aoc_indexes To Be null

If the ROM for the downloadable content has not been registered with a season pass, or if download of the DLC is prohibited, its index is not included in aoc_indexes. If aoc_indexes is empty, its value is null.
Also, if the bundle contains downloadable content that will not be displayed in Nintendo eShop, the bundle's aoc_indexes is null.

URL Path Specifications

Feature for Getting a List of Downloadable Content

Gets a list of the downloadable content and downloadable content bundles for the specified application.

Request

URL Path

/v1/applications/{applicationId}/aocs/items

Parameter

offset The position at which to start getting items (for paging). integer query Optional 0 0
limit The number of items to get (for paging). integer query Optional 100 10

Maximum value 100.

Example:

/v1/applications/{applicationId}/aocs/items?country={country}&lang=ja
Note

The limit parameter defines how many items of downloadable content can be obtained at a time, but the maximum is 100 items.

To obtain information on more than 100 items, use the offset element and split the process into multiple get operations. For a usage example of limit and offset, see 8.1 Common.
