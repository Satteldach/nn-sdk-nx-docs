6.3.1 Compensation Method

This section describes how to use a PC to provide compensation for user save data-controlled consumable service items.

Overview

Functionality is available to compensate users, specific to their NSA ID, for consumable service items when receiving user inquiries for compensation. To use this functionality, you need to request in OMAS and receive in advance a client ID and a client secret for compensation.

The overall compensation process is as follows.

  1. Check the item_id for the item that is the subject of compensation and the NSA ID of the user, call the API for checking transactions from a PC, and verify the purchase of the consumable service item.
  2. Call the compensation API and provide compensation for the target consumable service item.
Info

Use the transaction confirmation function to review the transaction where a compensation occurred using the compensation function.

For more information about the compensation function, see 6.3.1.1 Compensation API.

Important Information

  • Do not use this feature for any purpose other than providing compensation. Avoid using this feature for benefits awarded during campaigns.
  • There is the possibility that compensation would allow a user to acquire two of an item when normally only one of those items can be acquired. This situation occurs because it is difficult to confirm whether an item needing compensation has been lost within an application. Your application must work correctly when compensation is made, for example by not increasing the number of obtained items.
  • Use an implementation that enables compensation to be received within the application. In other words, if compensation is made via a PC operation, the application must be able to process that operation.
  • Service item purchase notifications do not apply to compensation. For more information about notifications, see 2.4 Service Item Purchase Notification Feature.
  • This feature cannot be used for independent server-controlled service items. To compensate these kinds of items, use the license-management feature of the independent server.

Client ID/Secret for Compensation

To use the compensation API, you need a client ID/secret for compensation. For more information about how tokens are issued, see 4.1 Usage Request on OMAS.

There are two kinds of client ID/secret for compensation, one for dd1 and one for lp1. For testing, use the one for dd1.

Note

Keep strict control over the lp1 client ID/secret for compensation to protect against misuse.

Consumable Service Item API Endpoints

Compensation can be used with dd1 for testing, and with lp1 for a production environment. For more information about the respective consumable service item API endpoint FQDNs, see the Correspondence Between Environment Identifiers and FQDNs of Subscription Service Item API Endpoints in 9.1 Using Independent Servers.

Getting the NSA ID

For more information about getting the NSA ID from the support number acquired during a user inquiry, see the Nintendo Switch Independent Server Setup Manual.
