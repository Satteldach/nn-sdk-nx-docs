6.2.2.2.1 Overview

Overview

The following two types of Nintendo eShop server APIs are used for consumable service items.

  • APIs for getting available license information from the independent server and updating license information
  • Debugging APIs that are also available from a PC or other device, such as for setting and clearing errors

Add the path described in the reference to the fully qualified domain name (FQDN) of the consumable service item API endpoint, and send an HTTP request.

API Endpoint FQDN

The FQDN of the API endpoint depends on the environment. For more information, see 9.1 Using Independent Servers > Correspondence Between Environment Identifiers and FQDNs of Consumable Service Item API Endpoints.

Authentication

To use the various APIs, you must use Basic Authentication with a client ID and secret. For more information about issuing a client ID and secret, see 4.1 Usage Request on OMAS.

The APIs for getting and updating license information must include the NSA ID token (obtained from the Switch application) in the header.

Note

When an NSA ID token that cannot be verified (because the token has expired, for example) is passed, the server returns a 401 (Unauthorized) response.

Before using the server API, you must add trust for the private Nintendo CA. For more information, see 9.1 Using Independent Servers.

Limitations on the Volume of API Requests

Although there is currently no explicit limit on the volume of calls you can make, avoid implementations such as the following that would lead to high load on the Nintendo eShop server.

  • A system where many consoles access the Nintendo eShop server simultaneously after maintenance, such as when checking for licenses immediately after the application starts
  • High frequency API calls, such as when the application periodically obtains transactions after startup

We recommend that you either only get license information and send purchase notifications when the user uses an item or service (that is, when it is necessary to check for a license). For more information about purchase notifications, see 2.4 Service Item Purchase Notification Feature.

Note

If the Nintendo eShop server is subjected to a high load, it may not be able to provide stable service.

Character Encoding

Responses are created using UTF-8 as the character encoding.

Error Response

Use the HTTP status code of the response to determine whether API calls for consumable service items succeeded. If a HTTP status code other than 2xx is returned, the request failed.

When an error occurs, the error description is generally in the following format.

{"error":{"code":"1530","message":"invalid item id"}}

However, some errors are returned with different (or blank) response bodies. Make sure that no issues occur in these cases, such as the application stopping.

For more information about handling and displaying errors in Switch clients, see 6.2.2 For Developers.
