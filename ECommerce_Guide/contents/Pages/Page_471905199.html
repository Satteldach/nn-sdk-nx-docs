6.2.2 For Developers

Independent Server Settings

To make various requests in Nintendo eShop, save the following information on the independent server.

Item Overview
Base URL of the consumable service item server

For more information, see 9.1 Using Independent Servers > Correspondence Between Environment Identifiers and Consumable Service Item API Endpoints.
Client ID/Secret

This information is used to send requests for the consumable service item.
Item ID

This ID is used to identify items purchased on Nintendo eShop. Independent servers use this ID to determine which licenses to assign to users.

Adding Licenses to User Accounts

After a request to get license information is received from the independent server, Nintendo eShop returns information for the item purchased by the user who sent the request. Identify the purchased item and grant licenses based on this information. In addition, to record that the license has been used, send a license information update request to update the purchase information status.

The following two IDs are used during this process.

ID Name Description
item_id

This item ID identifies the purchased item.
right_id

ID for identifying the units of consumable service items users purchase from Nintendo eShop.
When Nintendo eShop receives a request for a user’s license information, it returns that license information in units of right_id values.

The status of right_id is updated when the license is granted.

Debugging in the Development Environment

Using NCMS, consumable service items can be sold on the development environment (dd1) Nintendo eShop.

For more information, see 4.2.1 NCMS Settings for Development.

Testing Error Handling

The consumable service item server APIs may sometimes fail, such as when the Nintendo eShop server is down for maintenance. For more information about API responses when errors occur, see 6.2.2.2.1 Overview.

The following two features are available for testing error handling.

  • Using the Web tool, set errors for a specified account.
    • 6.2.2.1 Online Tool for Error Settings
  • Using the server APIs for debugging, set errors for a specified account.
    • 6.2.2.2.4 FOR DEBUGGING: API for Mandatory Error Settings
    • 6.2.2.2.5 FOR DEBUGGING: API for Clearing Mandatory Error Settings

Although the implementation of error handling is generally handled by the independent server, if an error is defined in the Nintendo Switch Guidelines as to be displayed in the application, use the error viewer applet to display the error to the user.

NintendoSDK NX Add-On 7.0.0 or later

Use the nn::err::MakeErrorCode() function to generate an error code for the consumable service item. For the second parameter, specify the code value included in the error response from the server API.

Code 6-1 Calling the Error Viewer Applet in NintendoSDK NX Add-On 7.0.0 or Later
nn::err::ErrorCode err = nn::err::MakeErrorCode(nn::err::ErrorCodeCategoryType::ConsumableService, error.code); // error.code is the code included in the error response of API
nn::err::ShowError(err);

Versions earlier than NintendoSDK NX Add-On 7.0.0

The corresponding error message can be displayed in the error viewer applet by specifying 2622 (the category code for consumable service items) for the category public variable of the nn::err::ErrorCode structure, specifying the code included in the server API error response for the number public variable, and then calling nn::err::ShowError(ErrorCode errorCode).

Code 6-2 Calling the Error Viewer Applet
nn::err::ErrorCode err;
err.category = 2622; // Consumable service item error category.
err.number = error.code; // error.code is the code included in the error response of API
nn::err::ShowError(err);
