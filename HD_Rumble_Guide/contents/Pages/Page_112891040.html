Isn't creating a vibration binary file a lot of work?

For the vibration binary files, Nintendo provides vibration samples in the Vibration Collection that can be quickly used in applications, and a vibration converter for converting audio data to vibration data. These can help bring down production costs.

Although people expect to need to generate individual vibration binary files for each audio file, it is not always necessary. You can get a different sensation when you use the same vibration pattern with different audio. You can bring production costs down by assigning a single vibration binary file for all actions of the same type. In addition, you can produce multiple effects with the same vibration binary file by changing playback parameters such as the volume, pitch, and playback speed when you play the file.

What do I have to watch out for when creating vibration binary files?

Make sure to consider not only the vibration feature by itself, but also how it works with user operations, video, and audio to produce a better experience. When you create a vibration binary file, we recommend that you avoid testing only the vibration feature, and instead test the overall sensation within the context of the actual application. It might be better to treat the Switch HD rumble feature not primarily for the vibrations, but for the sound effects and other effects that affect gameplay.

Even if you want to express something using only the vibration feature, make sure that users recognize beforehand what they are doing with the controller. Adding this step allows users to understand what the vibration represents.

Consider the following specific example. In the Ball Count minigame in 1-2-Switch, a video is run before gameplay that shows balls moving inside a box. (https://www.nintendo.co.jp/switch/aacca/sp/movie/countball.html) By viewing this video, the user becomes aware that the Joy-Con is treated as a box, and the balls are within the box. As a result, the user can naturally interpret the vibrations that occur when moving the Joy-Con as ball collisions. Next we turn to a description of the vibrations when balls collide. If there is only one ball, the collision is straightforward, but if there are multiple balls, there are multiple collisions. If vibration 1 and vibration 2 occur at nearly the same time, this could be presented as a single, strong vibration, or as two vibrations one right after the next. By reproducing these kinds of detailed vibrations, you can convey changes in the number of balls. Overlapping vibrations can be easily expressed using the vibration API. In addition to considering how to create the vibration file, it is important to consider how to play it.

What must I watch out for when porting vibration patterns from the eccentric rotating mass?

For example, consider the case where you want to generate vibrations at half the maximum strength. The eccentric rotating mass did not have an API for specifying the intensity of the vibration. To halve the strength, most applications would have repeatedly turned on and turned off the eccentric rotating mass to yield the intended intensity. On the other hand, because amplitude can be directly specified with the Switch, all you need to do to halve the strength is to specify a half-strength value for the amplitude variable.

There is one point worthy of note. Repeating a series of start and stop commands for the linear resonant actuator might not result in half the intensity as it would for the eccentric rotating mass. The vibrations linger instead of stopping when you stop the eccentric rotating mass, and because of this characteristic, you can express vibration intensity using a series of start and stop commands. Because the linear resonant actuator is so responsive, the vibrations actually start and stop when you repeat start and stop commands, creating the sensation of intermittent vibrations.

How can I create strong vibrations?

Increasing the amplitude to the maximum of 1.0 is not the only method for increasing the subjective strength of the vibration. Increasing the length of time that the controller is vibrating also increases the vibration strength.

The user becomes accustomed to vibrations, so changing the vibration pattern from those immediately before and after is also an important element. For example, you can make a vibration seem stronger by reducing the amplitude to 0.0 temporarily and then changing it to 1.0. The difference between when the controller is vibrating and when it is not vibrating is important.

Info

Instead of setting both the high-frequency band and low-frequency band to amplitude 1.0, using only one of these bands produces a stronger vibration amplitude.

For more information, see NintendoSDK Documents > Features > Input Devices > hid Library > Manual > Features > Vibration > Vibration Value.


Are there any considerations when creating applications that use the vibration feature?

Nintendo encourages developers to actively create scenarios on the Switch platform that use the vibration feature.

Info

An example of a scenario that uses the vibration feature is the Ball Count minigame in 1-2-Switch, which relies on the vibration feature to guess the number of balls.

https://www.nintendo.co.jp/switch/aacca/sp/movie/countball.html

However, in cases like the following, the user's controller does not vibrate.

  1. When the user is using a system such as the Switch Lite that does not support the vibration feature
  2. When the user turns off Controller Vibration in the Settings in the HOME Menu
  3. When the user is using something like the SNES controller that does not support the vibration feature


In general, the application is not required to have countermeasures for these cases. However, the following are examples of countermeasures that can be adopted for the user's convenience.

  • Adding an announcement before entering an area that uses the vibration feature
    • Example: Indicate on the physical package and the Nintendo eShop description that HD rumble can be enjoyed with a separately sold Joy-Con or Pro Controller.
    • Example: Prompt the user to enable Controller Vibration in the application. (You can use a function to get the Controller Vibration status.)
    • Example: Prompt the user in the application to play using a controller, such as the Joy-Con or the Pro Controller, that supports the vibration feature.
  • Considerations to prevent the user from getting stuck in a situation that uses the vibration feature
    • Example: Progress to the next scene if the user does not clear the operation in a certain amount of time.
    • Example: Make it possible to revert to the previous scene if the user performs a certain operation.

From an implementation perspective, the Nintendo SDK vibration API does not return an error based on whether the operating system supports the vibration feature.
As a result, Switch applications still run on the Switch Lite, just without vibration, and you do not need to perform special implementation for Switch Lite.
In addition, there is a feature on SDEV and EDEV to emulate the state where the vibration feature is not supported. This functionality can be used for testing and debugging.
For more information, see NintendoSDK Documents > Features > Controlling the Development Hardware > DevMenuCommand > Managing Controllers > Disabling Built-In Controller Features.

How do I handle users who dislike the vibration feature?

The user can enable or disable the Controller Vibration feature in the HOME Menu > Settings. If the option is disabled, all controllers connected to that system no longer vibrate. For this reason, the application does not need to implement turning off the vibration feature.

Normally, users may find it unpleasant when the controller vibrates strongly for an extended period of time. For user convenience, we recommend setting a restriction internally in the application for the accumulated vibration values over a specific period of time. In addition, it is important to use the vibration feature in important scenes and not just arbitrarily.

It is also effective to include vibration volume in the application. For example, in Super Mario Odyssey, you can set the vibration strength to one of three levels: Weak, Normal, and Strong. However, note that the volume settings may change the gameplay difficulty for applications with scenes that use the vibration feature.

How do I determine an appropriate vibration strength?

The appropriate vibration strength changes depending on the duration of the controller's vibration. For example, a strong vibration over a short duration may surprise the user, but would be uncomfortable over a long period of time. For this reason, you must determine the appropriate vibration strength after considering how often the vibration would actually occur. Although developers tend to use stronger vibrations for emphasis when first using vibrations in an application, we recommend using milder settings, considering that users might continuously play the application for as long as 30 or 60 minutes. We recommend asking users about the strength of the vibration over long periods of gameplay, such as during test play, and take their feedback into consideration.

What can happen when there is signal interference?

In some situations, unintended vibration patterns might occur due to the wireless environment.

If a nearby device is causing signal interference, data communication can fail for the controller. When that happens, unintended vibrations patterns might occur. (For example, the vibrations might last longer or feel stronger, or they might not occur at all.)

The same thing can happen in the following situations.
• Multiple controllers are connected wirelessly.
• A Bluetooth audio device is connected.

As a workaround, do not place devices that could cause signal interference in the vicinity of the Nintendo Switch console.

Is it possible to get the actual vibration value?

Use the nn::hid::GetActualVibrationValue function to get the actual vibration value that occurs in the vibration motor. However, the vibration value generated by the program is sent in an encoded state to the vibration motor, so it may not be identical to the actual vibration value generated by the program. In addition, the vibration value generated by the program may be adjusted depending on the system settings.

Does using the vibration feature affect battery life?

The standard operating time for the Joy-Con controllers is approximately 20 hours. Setting the controller to vibration for 10% of the gameplay time at maximum strength reduces the battery life by approximately 10%. For this reason, you can consider it to not have much effect on the battery life.

Is there any variation in the feel of the vibration feature between different devices?

The Joy-Con is subject to some disparities in individual hardware, so the vibration sensation is not strictly identical across all cases. To make subtle adjustments, we recommend acquiring multiple Joy-Con controllers and making adjustments considering the variations among them.

There seems to be disparity between the feel of the vibrations in the left and right Joy-Con. Is this a hardware specification?

The motors incorporated in the left and right Joy-Con controllers are identical. In addition, they weigh nearly the same, so there is no major difference in the feel of the vibrations between the left and right controller. However, human musculature is not identical in the left and right hands. The weight of objects feels different in the dominant hand and the non-dominant hand. For this reason, we recommend switching which hand holds which Joy-Con and checking again if it seems as though there is a difference between the left and right Joy-Con controllers. In addition, vibrations tend to feel weaker when the hand holding the controller is moving as opposed to when it is still, so differences in vibration may be felt depending on what kind of operations are being performed.

Considerations for Each Play Mode

In addition to the three play modes, Switch also includes various accessories and supports many styles of gameplay. We recommend adjusting the vibration feature with consideration of what styles are supported.

TV Mode

When the Joy-Con controllers are connected to the grip, both the left and right Joy-Con controllers are attached to and incorporated as one entity with the grip, so it is difficult to identify when only the left or right Joy-Con is vibrating. If you want to emphasize the difference between the right and left vibrations, advise the user to remove the Joy-Con controllers from the grip during use.

Tabletop Mode

For tabletop mode, we recommend that you use the vibration feature only on controllers connected wirelessly.

You must be cautious when enabling NpadStyleHandheld and getting input from Joy-Con controllers connected to the console. In this state, it is impossible to tell whether the user is operating the system with wireless controllers or with the controllers attached to the console. For this reason, you must consider which controller to vibrate when using vibration. For example, you must determine which controller was last used for input and consider that controller as the one being used.

Handheld Mode

In handheld mode, both the left and right Joy-Con controllers are attached to and incorporated as one entity with the console, so it is difficult for the user to identify when only the left or right Joy-Con is vibrating. In addition, some of the vibrations feel different, so you must adjust the amplitude. There is a compressor feature in the vibration API for damping strong vibrations. Use that feature.
