4.8 Entering Test Scenarios

The Lotcheck process verifies that the specifications entered in Features work correctly. The Lotcheck testers reference the test scenarios to perform these verification tasks.
Consider that the testers will be playing the application for the first time, and provide specific descriptions.
It is fine for test scenarios to be long. Make sure that all necessary information is present.

Procedure for Initial Release and Patches

  1. Click Features and enter information for each displayed item.
    When entering this information, use the same language that you selected on the Release Info page for Language used for text entry in Features, Test Scenarios, and Lotcheck Submission screen.
    Only proper nouns related to the application can be written in either English or Japanese.

  2. Click Test Scenarios. A list of options to test is displayed, based on the content entered in Features.

  3. A text box for test scenarios is displayed when an option is clicked. Describe the specifics, paying particular attention to the following three points.

    • Where: The process for reaching the scene where the behavior can be verified
    • What to do: The reproduction process for verifying the specifications
    • What happens: How to determine whether the behavior is correct

    If multiple scenes need to be tested, click the Add Method button to add additional entry fields.

    Note: This video does not have audio.

  4. If the process is difficult to describe using only text, you can submit a separate file.
    To do this, on the Test Scenarios page, click + Add File, or on the ROM Upload page, click Upload Additional File.

    • Notes

      • In some cases, the language of the copied text does not match the language selected on the Release Info page for Language used for text entry in Features, Test Scenarios, and Lotcheck Submission screen.

        • Example:

          In order to match the language used in this release, you translated the Japanese text into English, and used this English translation in the input field.
  5. If preparations including play conditions, hardware, and save data are required, enter this information.

  6. If it takes 10 minutes or longer to reach the test scenario, you must submit save data. Submit save data as indicated in the next section, 4.9 Submitting Save Data.

Procedure for Downloadable Content

The NDP operations are the same as those described in Procedure for Initial Release and Patches. However, some of the content described in Test Scenarios is different. The reason is that the content of Lotcheck testing for downloadable content is different from the test content for initial releases or patches.

Testing downloadable content involves downloading the content and checking that it works correctly. For this reason, when describing the test scenarios, focus on the following points.

  1. All indexes that are part of the master ROM for the downloadable content are tested; create testing methods for all of them.
  2. Describe the following five points. Describe in detail the data that is included in each index, using proper nouns, so that it is possible to determine how and where it is applied in the application. (Example: Instead of saying "character clothing," describe the actual character name and clothing name.)

    • Which index does the method correspond to?
    • Where: The process for reaching the scene where the behavior can be verified
    • What to do: How to use the content in the game.
    • What happens: When using the content in the game, what changes occur in the game?
    • Usage: For dummy data, enter that it is dummy data.

  3. If the process is difficult to describe using only text, for example because there are a lot of items, you can submit a separate file.
    To do this, on the Test Scenarios page, click + Add File, or on the ROM Upload page, click Upload Additional File.

Example of Entering Test Scenarios

Method for Initial Release and Patches

Entry Example A

Method Name

Verifying Matchmaking

Description of the Method
Preparation
  • Prepare consoles A and B, and link each console to a different Nintendo Account. You must have cleared Chapter 3 of the story mode.
  • Import the attached Data1.zip save data file to console A and the Data2.zip save data file to console B.
Procedure
  1. Start the application on consoles A and B.
  2. On consoles A and B, on the Title screen, select Continue.
  3. On both consoles A and B, talk to the NPC receptionist at the entrance of the arena.
    Note: If you used the attached save data 1 and 2, the arena is the brown block building west of where you start after loading the data.
  4. On console A, select Create Room.
  5. On console A, set any conditions for the room and then select OK.
  6. On console B, select Search for Rooms.
  7. On console B, set conditions for the room that match the room created in step 5, and select Search.
  8. On console B, select the nickname of the user account from console A, and then wait.
  9. The user account nickname for console B appears on console A. Select Start Battle.
  10. Confirm that matchmaking occurs between console A and console B, and that a 1vs1 match can be played.


Info:
  • When updates made in patches can be verified with the same method as test scenarios filled out in previous releases, report that under Features.
    • Related NDP Pages: Existing test scenarios are sufficient to test the updates, which appears when the check box is selected for an updated feature in Features > Patches > Content updated by patch



      Select the check box for the preceding item, and then enter the name of the test scenario to refer to.
  • If there are no visual changes to the gameplay, enter that there are no changes in Overview of updates.

Methods for Downloadable Content

Entry Example B: Downloadable Content (Release Data)

Method Name

Index 3: How to use additional item, Mario's hat

Description of the Method
  1. From the menu screen, select Closet.
  2. The Mario's hat item appears at the top of the owned items list.
  3. Select Mario's hat and select Change Clothing.
  4. The Mario's hat item appears in the character's worn items.
