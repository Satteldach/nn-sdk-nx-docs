4.9 Submitting Save Data

If not all features implemented in the application are available at the start of the game, saved data may be required together with the test scenario to enable Lotcheck to progress efficiently.

If it takes 10 minutes or more to reach the scene described in the test scenario, submit save data using the following procedure.

Related Documents
  • NintendoSDK Documents > Features > Controlling the Development Hardware > DevMenu > Managing Save Data
Related NDP Pages
  • NDP > MY PRODUCTS > target_product > Releases or Downloadable Content > target_release > go to the guide on the right side of the screen > Features
  • NDP > MY PRODUCTS > target_product > Releases or Downloadable Content > target_release > go to the guide on the right side of the screen > Test Scenarios
Procedure
  1. Click Features and enter information for each displayed item.
  2. Click Test Scenarios. A list of options to test is displayed, based on the content entered in Features.
  3. Submit save data when it takes ten or more minutes from the start of the application to arrive at the testing location as described for each item in Method.
  4. Submit save data using the + Add file button under Method.



Requirements for Save Data for Lotcheck

Submit save data that meets the following requirements.

  • Save data backed up using DevMenu:
    Note: Compress everything located in the BackupSaveData folder that was created on the microSD card (sd:\NintendoSDK\BackupSaveData), and submit that as the save data.
  • Save data created in the user environment:
    Note: For Lotcheck use (for the production device compatibility test), the save data must be comparable to the save data that can be created in actual gameplay. For example, you cannot use save data created in debug mode that would never be created in the actual production environment.
  • If a scene supports multiplayer gameplay, prepare save data for the corresponding number of players.
  • If the save data is compatible with another application, include the save data created by that compatible application.
    (Example: Save data created in a demo version when the demo version save data is used in the full retail version of an application.)
