2.6 Handling for Initial Applications to Reduce Unnecessary Regions

If data in the initial version of the application is no longer referenced when a patch is applied, the storage area for that data becomes superfluous. Whenever possible, avoid creating superfluous regions that are not referenced so as to free up storage space.

One method to reduce superfluous regions is to distribute most of your data through patches, instead of through the initial application. In particular, there will be no superfluous regions if the initial application merely contains a message that tells the user that update data is required.

This method is particularly effective for downloadable applications that periodically issue patches. If you are considering using this method, consult with Nintendo in advance.

Info

If there is an unavoidable reason for not making the initial application smaller, you can also use application compaction to later remove areas of the initial application that are no longer being referenced. For more information, see 2.7 Application Compaction.

Note

For applications that support pre-orders, data will be distributed to users prior to the release date, so there is the risk of patch information being leaked. In particular, be careful if the patch contains all of the content. You can configure secure distribution settings to prevent this type of information leakage. For more information, see 3.3 Patch Distribution > Important Information for Distributing Patches for Applications That Support Pre-Orders.
