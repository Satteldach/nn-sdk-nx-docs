2.7 Application Compaction

If data in the initial version of the application becomes unusable when a patch is applied, the storage area for that data becomes superfluous. Application compaction is effective in these cases.

Application compaction enables you to create the application without those areas of the initial version of the application that are no longer referenced. By reducing the application size, you can reduce the size required for installation and the game card write size.

This page provides an overview of application compaction. For more information, see NintendoSDK Documents > Features > Patches > Application Compaction.

How to Use

You can perform application compaction by specifying options in AuthoringTool, which is used to create patches. An application that has undergone application compaction is called a compacted application.
Both the patch and the compacted application are required for the application to run correctly.

Applying the Patch and Verifying Operations

The initial version of the application, if it has been downloaded, is not automatically updated to the compacted application. For this reason, all patches distributed after application compaction must be tested to ensure that they work correctly when applied to the initial version of the application and to the compacted application.
For example, assume that an initial release version 0 application was created, and then a release version 1 patch and compacted application were created. In that case, you must ensure that the patch created with release version 2 works correctly when applied to the following applications.

  • Release version 1 compacted application
  • Release version 0 initial application

In addition, if there are multiple compacted applications, you must check that all of the compacted application versions work correctly when the patch is applied. This check is required is because compacted applications that have already been downloaded are not automatically updated to the latest compacted application.

Info

Even when the user has downloaded the initial application or an earlier compacted application, if they then re-download the application in the Nintendo eShop, they will receive the latest compacted application and patch.
You must delete a downloaded application if you want to re-download it. To delete an application, go to the Switch HOME Menu, select Settings > Data Management > Software Details, select the application you want to delete, and then select Delete Software.

Submission

After specifying options in AuthoringTool to create an NSP file that combines a patch and compacted application, submit the file in Nintendo Developer Portal.
The procedure is the same as the procedure for submitting the ROM for a patch. For more information, see 3.2 Patch Submission.

When submitting the file, you also need to submit a waiver request in Nintendo Developer Portal. The request will be accepted if one of the following criteria is met.

  • You plan to create an on-card patch or on-card downloadable content, but the content will not fit within the desired amount of memory on the card unless you perform application compaction.
  • You can reduce the size of the application by 1 GiB or more through application compaction.

As described in Applying the Patch and Verifying Operations, additional compacted applications increase the number of patch/application combinations for which you must test the patch. To avoid this issue, if you plan to release a patch that would further decrease the size of the application through application compaction in the near future, perform application compaction at that time.
For example, when there are plans to release a release version 1 patch and a release version 2 patch, and the size of the application is smaller when the application is compacted with the release version 2 patch compared to its size after applying the release version 1 patch, perform application compaction when submitting release version 2.

Distribution

The compacted application must be distributed simultaneously with the patch. Nintendo will configure distribution for and approve compacted applications. The developer configures patch distribution settings in NCMS. Nintendo then checks and approves the settings. For more information, see 3.3 Patch Distribution.
