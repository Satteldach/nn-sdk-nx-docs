3.1.2 Shared Region

A variety of IDs are written to the shared region during manufacturing and shipping so that the application can determine information about the end consumer's amiibo. These IDs allow a variety of unique effects/features to be implemented for each amiibo the consumer purchases. These IDs also allow support for features to be implemented in advance for amiibo products that are not yet available for purchase. However, using these IDs without a complete understanding of the purpose of each may result in unforeseen limitations on the types of amiibo products that can be used with your application. In addition, improper implementation of amiibo support may result in unexpected behavior when additional amiibo products are released in the future and used with your application. Please read the following descriptions of each ID carefully and implement the proper support in your application.

Data Entered at the Factory

Character ID

The character ID allows the application to determine whether the corresponding character is supported in the application. A different character ID is assigned to each character. The character ID comprises a 3-byte region. The first two bytes represent the base character ID, and the last byte represents the character ID details.

The same base character ID is assigned to every version of the same character. For example, a base character ID of 0x0000 is assigned to every Mario amiibo, and a base character ID of 0x0001 is assigned to every Luigi amiibo.

The character ID details are used to indicate different versions of the base character specified by the base character ID. A different character ID details value is assigned to each version of a character. For example, a character ID details value of 0x00 is assigned to normal Mario, and a character ID details value of 0x01 is assigned to Dr. Mario.

If you want your application to react in a certain specific way to each different character, you would use the base character ID. The character ID (base character ID plus character ID details) allows you to implement a variety of unique application behaviors for each amiibo product. This provides a unique and valuable user experience for each amiibo product for consumers who purchase different versions of the same amiibo character. However, it is not possible to implement support for versions of a character that have not been assigned an ID while the game title is under development. If you want your application to be able to support new versions of amiibo characters as they are released, the safest option is to use the base character ID and only implement character-specific application behaviors (rather than behaviors unique to different versions of the same character).

Figure 3-3 Determinations Based on Character IDs

Series ID

The series ID indicates the amiibo design series. The same series ID is assigned to all amiibo products that belong to the same series, such as all amiibo products in the Super Smash Brothers series or all amiibo products in the Animal Crossing series, for example.

Using the series ID makes it easier to narrow down which amiibo characters will be supported in your application. Use the series ID when you want to implement particular application behaviors for all amiibo products in a particular design series or when you want to be able to implement different application behaviors for each amiibo product in the same series (including new amiibo products in the series that may be released in the future). There are also characters, such as Mario and Link, who appear in multiple series. Regardless of whether you decide to implement unique application behaviors for each character or to implement the same application behaviors for all characters in a series, ensure that the user has a smooth, natural, and enjoyable user experience.

Figure 3-4 Determinations Based on Series IDs

Numbering ID

Numbering IDs are part of a sequential numbering scheme that covers all amiibo products. A unique numbering ID is assigned to amiibo products of the same type. For example, numbering IDs are used to distinguish between amiibo products that have the same character ID and series ID but have different poses, are carrying or using different items, or have different coloring. Using the numbering ID allows you to implement different application behaviors for each different version of amiibo products.

However, for your application to be able to distinguish between amiibo products using the numbering ID, numbering IDs must already have been assigned when your application starts. As a result, implementing numbering ID-specific application behaviors limits the range of amiibo products that can be used in your application. When implementing numbering ID-specific application behaviors, you may want to investigate also supporting the use of amiibo products other than only those with certain numbering IDs. In addition, Nintendo cannot guarantee that production of an amiibo product with a particular numbering ID will continue indefinitely. Production of an amiibo product with a particular numbering ID may be discontinued at any time.

Figure 3-5 Determinations Based on Numbering ID

Unique ID

The unique ID is an ID unique to each NFP tag. The unique ID can also be read by other NFC reader devices. All amiibo products that contain an NFP tag can be distinguished from one another using this unique ID.

The unique ID allows you to distinguish between amiibo products that are otherwise identical. For example, the unique ID makes it possible to distinguish between you and your friend's otherwise identical Mario amiibo products from the Super Mario series.

Consider a case in which a user loads the data on her amiibo product prior to playing a game and then creates new gameplay data while playing the game. Before writing the new data to the amiibo product, you can check the unique ID to make sure that it is the same amiibo product and thereby prevent writing data to the wrong amiibo. Because the unique ID is unique to each amiibo product, you must take special precautions in cases such as when the amiibo is accidentally lost. Avoid game designs that write more save data than necessary on the amiibo, which can prevent users from continuing to play the game if they lose their amiibo products unless they delete the application-side save data and start over.

NFP Type

NFP type is an ID assigned to amiibo products based on product type. For example, different NFP types are assigned to amiibo figures and amiibo cards.

Using the NFP type ID allows you to implement application behaviors specific to a certain type of amiibo product. However, new types of amiibo products may be launched in the future. Overusing the NFP type ID may restrict the ability of your application to support new amiibo product types as they are launched in the future.

Data Entered When the Owner Registers

Owner

The owner of an amiibo product can register his/her Mii to the amiibo.

Nickname

The nickname given to the amiibo product by the owner. (Maximum of 10 characters.)

Data Entered When the Application Accesses the Application-Specific Region

Access ID

Nintendo assigns an access ID to each application. The access ID is used on the game system to determine whether to allow a specific application to access the application-specific region of an NFP tag. For more information about using the application-specific region, see 3.2.1 Use of the Application-Specific Region.
