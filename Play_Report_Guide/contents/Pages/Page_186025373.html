8 Play Report Restrictions

API Call Frequency

The following restrictions apply when you save Play Report data (report data) and when you send the data to the server.

Target Operation Restriction Specific Function Examples
Saving events Up to 900 events during 180 minutes nn::prepo::PlayReport::Save()
Immediate transmission of events saved in the system Up to 10 requests during 10 minutes nn::prepo::RequestImmediateTransmission()
Note:

We do not recommend saving inherently different kinds of data (keys and values) in individual events for the purpose of circumventing the restrictions. This makes analysis difficult.

The restriction on the frequency of function calls is checked automatically. The application does not need to limit function calls to comply with the restrictions.

The functions do not return errors when the restrictions are exceeded, but the saving of events and their immediate transmission is ignored. If SDK log output is enabled (as it is for debug or develop builds), the following messages are displayed in the log at this time.

Target Operation Log Message
Saving events [prepo] Warning: Rate limit for save exceeded, please wait before saving this report.
Immediate transmission of events saved in the system [prepo] Warning: Rate limit for immediate transmission exceeded, please wait before transmission.

If you are saving events, the current function call to nn::prepo::PlayReport::Save() is ignored if the function was already called 900 times to save events during the 180 minutes prior to the current call. In this case, the ignored API call is not included in the count. The same applies to immediate transmission.

Possibility of Data Being Deleted

The report data sent to the server from Nintendo Accounts in the following countries is deleted from the raw data under the following conditions.

  • Country: Most European countries, South Africa, Russia, Australia, New Zealand, and others.
  • Condition: The user opts out of sending information (see 4 Sending Play Reports).

For this reason, in some cases the analysis results change depending on the time of analysis. Keep that in mind.

Old Data Analysis

To analyze data that predates the S3 storage period for raw data, make sure that you import that data into an external BI tool before the S3 data is deleted.

Sending Duplicate Data

In rare cases, duplicate report data is sent to the server.

As a countermeasure, report_identifier is included as a system key in the report data.

report_identifier is a 36-byte string in UUID format (RFC 4122), and contains a unique value for each report data.

Report data analysts should handle this report_identifier value as needed to prevent duplicate aggregation of data.

Info:

On rare occasions, duplicate report data is sent for the following reason.

If the Switch system is turned off immediately after finishing sending the report data, the system will not be able to record that fact and the same report data will be sent again when the system is restarted.

Data Prohibited From Sending

Sending personal information is prohibited.

Pay special attention to UGC (user-generated content, defined in the UGC section in the Nintendo Switch Guidelines and the Nintendo Switch UGC Guide) because it may contain personal information.

Personal information refers to all information directly or indirectly related to an individual user that clearly identifies their identity or contact information.

Consult with the company legal department for the standards for determining whether specific data is considered to be personal information.

If the sending of personal information is discovered after product release, the server might be reconfigured to not receive the data.
