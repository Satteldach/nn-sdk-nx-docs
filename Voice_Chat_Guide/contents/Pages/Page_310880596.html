2.1.2 Matchmaking Voice Chat User Experience

The Matchmaking Voice Chat feature of the Switch Online app provides the following kinds of user experiences.

  • At the point when an online match begins in the Switch application, voice chat begins between the members participating in the match via smart device.
  • Voice chat using smart devices ends at the point when an online match ends in the Switch application.

In this example, users joining the match and starting voice chat progresses according to the following flow.

  1. Perform matchmaking in the Switch application.
  2. Start an online match between the users who were gathered via matchmaking.
  3. Send a notification to the smart device to start the Switch Online app and begin voice chat.
  4. End voice chat when the online match ends.

Matchmaking Between Users

Matchmaking is a feature that mediates online multiplayer gameplay by finding other users online to play with.

To support Matchmaking Voice Chat, it is not necessary to change the matchmaking implementation in a way that changes the user experience. However, it is okay to change the user experience when you add support for Matchmaking Voice Chat to your application.

As described in the 2.1.3 Supporting Matchmaking Voice Chat section, there are features for determining whether Matchmaking Voice Chat is available and for directing the user to download the Switch Online app.

Starting Online Matches Between Matched Users

It is also not necessary to change the implementation of online matches in a way that changes the user experience in order to support Matchmaking Voice Chat.

Starting Voice Chat

The Switch application calls the function for starting voice chat and sends a notification to the smart device.
Voice chat begins after the user starts the Switch Online app.
For example, if the function is called at the start of an online match, the user experience will be that voice chat begins at the same time as the online match.

Ending Voice Chat

When the Switch application calls the function to end voice chat, a notification is sent to the smart device and the state transitions to the state (described later) of waiting for voice chat to end. Voice chat ends after this state has continued for a certain amount of time.
For example, if the function is called at the end of an online match, Voice Chat transitions to the waiting-to-end state when the online match ends.

Waiting-to-End State for Voice Chat

The waiting-to-end state for voice chat is the state where the user is notified in the Switch Online app voice chat screen that voice chat will end shortly. Voice chat can continue to be used while in this state. After some time passes in the waiting-to-end state, voice chat ends.

Figure 2-1 Smart Device Screen in the Waiting-to-End State for Voice Chat

The transition to the waiting-to-end state for voice chat can be triggered in any of the following ways.

  • The application explicitly ends voice chat.
    • This occurs if the application calls SmartDeviceVoiceChatClient::LeaveRoom() or destroys the instance of the SmartDeviceVoiceChatClient class.
  • A heartbeat timeout is detected between the Voice Chat server and the Switch.
    • For example, communications are interrupted when the application is closed from the HOME Menu, even though the application has not explicitly ended Voice Chat processing.
    • For more information about the heartbeat, see Matchmaking Voice Chat in the NX NEX Manual.

The Switch Online app immediately transitions to the waiting-to-end state when voice chat ends because the application explicitly ended it.

When ending voice chat after detecting a heartbeat timeout between the Voice Chat server and the Switch, the application transitions to the waiting-to-end state after detecting that timeout. In such cases, it takes time to detect this timeout, so it takes more time for voice chat to end compared to when the application explicitly ends voice chat.
