Introduction

This document describes the requirements and recommendations for using development tools such as EDEV Kits at demo events for end users.
When creating applications for exhibition, comply with the Nintendo Switch Guidelines, which is available online.

If you are uncertain about how to handle an issue, contact the Nintendo Technical Support Department.

Equipment Used

Hardware

Development Hardware That Can Be Used

The only development hardware systems that can be used for events are EDEV, HDEV, and ADEV. SDEV cannot be used.

For equipment other than the system itself, such as Joy-Con controllers, the Nintendo Switch dock, the AC adapter, the Pro Controller, and HDMI cables, a version equivalent to the commercial version is included for all accessories other than the Pro Controller. Use these accessories.
Use a commercially available Pro Controller.

Development Hardware That Cannot Be Used

Some of the earlier EDEV Kits contain black Joy-Con controllers that are different from the production version. Do not use the black Joy-Con at events for the general public.

Figure 1 Joy-Con

Software

SDK and Firmware Used

Use the SDK described as acceptable for master submissions and the firmware versions that require testing, described in Technical Information > Master ROM Submission Information (https://developer.nintendo.com/group/development/g1kr9vj6/tech-info/master-submission-information) on the Nintendo Developer Portal.

Testing

The ROM data for exhibition at events does not need to be submitted for Lotcheck.
Use the same firmware you would use at your actual event to test the operations from either the exhibition mode or the HOME Menu.

Installation Target

To prevent theft, avoid starting software from a game card or microSD card, and start it from the system memory instead.

Notes for Event Operation

This section describes the requirements and other important information to consider for event operation.

Ensuring the Safety of Attendees

When exhibiting applications that use the accelerometer and gyroscope to detect movement, make sure to provide Joy-Con wrist straps. In addition, increase the safety of players by leaving sufficient distance between players and other attendees or equipment.

Exhibition Method

To prevent any operational problems at demo events, make sure to fully test the specifications and exhibition method of an application prior to the event.
For example, if you want users to try both TV mode and handheld mode, consider an exhibition method where users can touch the console.

Hardware Management

  • Manage hardware carefully during exhibitions.
  • For exhibitions that span multiple days, transfer and store the equipment in a locked location each day after the exhibition period for that day ends.

Handling of Specifications Different From Retail Products

Photographing Development Hardware

Do not allow users to take photos of the back of development hardware (EDEV, HDEV, and ADEV).

Showing Screens Other Than the Game Screen

At the exhibition venue, do not allow attendees to view or operate screens other than the game screen, particularly developer features such as DevMenu.

Either use the exhibition mode feature designed for events, or delete DevMenuApplication if you are using the HOME Menu.
We recommend using exhibition mode if there is no need to switch applications.

Info

When handling issues via DevMenu, remove the system from the dock and perform operations in handheld mode so video is not displayed on the TV.

User Accounts

The icon for a user account created via DevMenu cannot be selected when user accounts are displayed with the HOME Menu. For this reason, create accounts intended for events from the HOME Menu.

Figure 2 User Icon Created via DevMenu (Use Prohibited)

Exhibition Mode

DevMenu includes an exhibition mode to support various features that are necessary at events. In exhibition mode, the functionality of the system changes as follows.

  • The HOME Button is disabled and the system does not transition to DevMenu.
  • Although images are saved when the Capture Button is pressed, the overlay notification is not displayed.
  • When the system is turned on, the specified application starts automatically from DevMenu.
  • When resuming from sleep mode, the application resumes without displaying DevMenu.

In addition, you can use the following convenient features for exhibition events.

  • Play timer feature to automatically close an application after a specified amount of time.
  • Feature to use save data you prepared specifically to be a starting point for the application.

For more information about exhibition mode, see NintendoSDK Documents > Features > Controlling the Development Hardware > DevMenu > Exhibition Features.

English: https://developer.nintendo.com/html/online-docs/g1kr9vj6-en/Packages/SDK/NintendoSDK/Documents/Package/contents/Pages/Page_522465110.html

Enabling Exhibition Mode
  1. From DevMenu, select Debug.
  2. In Launch Mode Settings, change Exhibition Mode to Enabled.
  3. The "Reboot device to reflect changes" message is displayed. Tap the POWER Button at the upper right to restart the system.

When first enabling exhibition mode, restart DevMenu because the application to start automatically has not been configured. You must select the application to start.


Selecting the Application to Start
  1. Go to Application, and press the Y Button to select the application to start automatically.
  2. The application that was set starts automatically after restarting the system.

You can only set the automatic startup application in DevMenu with exhibition mode enabled. You cannot set this option when exhibition mode is disabled, and you cannot start it from the DevMenu application.

Info

If the application prompts you to select a user at startup, you must create a user account in advance.
Create a user account from the HOME Menu. (As described previously, do not use user accounts created with DevMenu.)

Info

If the application set to start automatically is deleted, application startup fails when the system is turned on, and continues to try to restart. In this case, open DevMenu as described below in Starting DevMenu in Exhibition Mode, and change the application that is automatically started.

Disabling Exhibition Mode
  1. From DevMenu, select Debug.
  2. In Launch Mode Settings, change Exhibition Mode to Disabled.
  3. The "Reboot device to reflect changes" message is displayed. Tap the POWER Button at the upper right to restart the system.
Starting DevMenu in Exhibition Mode

With the Joy-Con controllers attached to the console, repeatedly press ZL + R + Down simultaneously immediately after starting the system to transition to DevMenu.
Note: The Down Button () is the button pointing downwards when the left Joy-Con is attached to the console.

HOME Menu

Switching to the HOME Menu

If you set Initial Boot Menu to Home Menu, the screen at startup changes to the HOME Menu.

  1. From DevMenu, select Debug.
  2. In Launch Mode Settings, set Initial Boot Menu to Home Menu.
  3. The "Reboot device to reflect changes" message is displayed. Tap the POWER Button at the upper right to restart the system.
Deleting the DevMenu Application

To prevent the DevMenuApp icon from displaying on the HOME Menu, delete the DevMenuApp icon using the following procedure.

  1. From the HOME Menu, go to DevMenu Application and press the + Button.
  2. From Data Management, select Delete Software.
  3. In the dialog box that appears, select Delete.
Starting DevMenu From the HOME Menu With the DevMenu Application Deleted

You can start DevMenu from the HOME Menu with the DevMenu Application deleted.

  1. Check that all applications have been closed.
  2. At the lower right of the HOME Menu, select the sleep icon.
  3. While the screen indicating that the console is about to enter sleep mode is displayed, press the L or R stick simultaneously with the + or - Button.
    If pressing the buttons simultaneously is difficult, first press and hold the L or R Stick, and then press the + or - Button (or do the reverse).
  4. DevMenu starts.

To return to the HOME Menu, use the Power Button at the upper right to restart the console.

Reusing the DevMenu Application

This section describes how to make the DevMenu Application available again after deleting it from the HOME Menu.

Installing NSP Files

This method reinstalls the DevMenu Application while keeping the other installed applications as is.

For more information, see Installing and Running Applications in the Nintendo Switch EDEV Usage Manual, the Nintendo Switch HDEV Usage Manual, or the Nintendo Switch ADEV Usage Manual.
A PC or a microSD card containing the NSP file is required.

The DevMenu Application NSP file is located in NintendoSDK\TargetTools\NX-NXFP2-a64\DevMenuApp\Release.

Running Initialize EDEV (or Initialize HDEV or Initialize ADEV)

If you run the Initialize EDEV process to initialize the development hardware, the DevMenu application will be installed again. Note that installed applications will be deleted.

For more information, see Nintendo Switch EDEV Usage Manual > EDEV Operations > Initializing the EDEV, Nintendo Switch HDEV Usage Manual > HDEV Operations > Initializing the HDEV, or Nintendo Switch ADEV Usage Manual > ADEV Operations > Initializing the ADEV.
A PC is required.

Controller Signal Interference

When using wireless controllers such as the Joy-Con, there can be interference from Wi-Fi spots and other wireless devices placed in the venue. Issues can occur, such as difficulty connecting the controller, input not being applied in the game, or disconnecting from the console.
You can use the following methods to alleviate these issues.

  • Move the console and controllers closer together.
    The most effective way to resolve interference with surrounding equipment is to move the devices that need to communicate closer together. We recommend having the console and controller within two meters of each other, and within one meter if possible.
  • When multiple Switch consoles are used in the exhibition, make sure there is sufficient space between them.
    As an estimate, consider making the distance between consoles greater than the distance between a console and its controllers. We recommend leaving a distance of at least one meter between consoles.
  • Connect the minimum number of required controllers.
    The risk of wireless interference increases with each controller connected wirelessly to the same console. Connections are relatively stable if you limit the number of controllers connected wirelessly to 4 or fewer.
  • Move the consoles farther away from signal sources.
    If there are many people in the exhibition hall, there can be interference with signals from wireless devices carried by attendees. You might be able to alleviate this problem by moving the console farther away from crowded locations such as the lines where guests are waiting to play the game.
  • Connect Pro Controllers with wired connections.
    Pro Controllers can transmit data via the USB charging cable.
    Conversely, even if you attach Joy-Con controllers to the Joy-Con charging grip and connect the grip to the console via a USB cable, data is not transmitted through the wired connection.

Connecting Pro Controllers via Wired Connection

  1. Use a USB charging cable to connect the Pro Controller to a Nintendo Switch dock that is connected with an AC adapter.
  2. From the HOME Menu:
    1. Select System Settings.
    2. Select Controllers and Sensors > Pro Controller Wired Communication, and use the confirm button to switch the option from OFF to ON.
  3. From DevMenu:
    1. Select Controller.
    2. Select the Enable Pro Controller USB Communication check box.
Info

NFC features are unavailable while using a wired connection. When using NFC features such as reading amiibo, disconnect the USB charging cable and use wireless communication.

Signal Interference in Local Communication

When using local communication, signal interference from Wi-Fi spots and other wireless devices can occur, just as with wireless controllers. Signal interference can cause issues such as difficulty connecting, operations on one device being difficult to apply on another device, or disconnecting.
You can use the following methods to alleviate these issues.

  • Move the consoles closer together.
    Move the consoles participating in local communication closer together.
  • Use handheld mode.
    Local communication also interferes with wireless controllers, so using the controllers attached to the console in handheld mode might reduce interference.
  • Move the consoles farther away from signal sources.
    Similar to the solution for wireless controller signal interference, you might be able to alleviate the problems by moving the consoles away from crowded areas such as the lines where guests are waiting to play the game.

Malfunctions of the IR Motion Camera

When exhibiting applications that use the IR Motion Camera on the right Joy-Con, the device might be affected by lighting equipment in the exhibition hall due to the characteristics of infrared hardware, and it might not operate correctly.
Consider countermeasures such as instructing users to face the bottom of the right Joy-Con towards an area without light sources, such as a wall. (Confirm this solution before the exhibition.)


Screen Brightness

In general, turn the brightness all the way up and turn off Auto-Brightness. Make adjustments depending on the surrounding environment at the event.

Be careful when Auto-Brightness is on, because the screen might become dark when the console is held at certain angles. For ADEV, the light sensor is located at the top of the console.
