7 Supported Examples

This section describes actual cases such as how to determine the supported play modes, functional alternatives, and reasons for deciding not to support a basic policy.

Examples of Determining Supported Play Modes

Example 1: An application with only one game mode

Application Overview

This is the simplest case where the player progresses using only one game mode through the entire application, and game modes using alternate play modes do not exist.

For example, a game similar to the Super Mario series.

Figure 7-1 An application with only one game mode

Definition of Core Content

The entire application (because there is only one).

Policy for Supported Play Modes

All modes supported by the core content (all or one of TV mode, tabletop mode, and handheld mode).

Example 2: If there are minigames in addition to the core content

Application Overview

Application with content including a story mode, minigame 1, and minigame 2. The story mode is the largest-scale content in this application. Minigame 1 and minigame 2 are small-scale content that do not affect the progression of the story mode.

For example, a game similar to the Legend of Zelda series. Small dungeons and similar items that do not directly affect completing the game itself may also be considered the same type of case as minigame 1 and minigame 2.

Figure 7-2 If there are minigames in addition to the core content

Definition of Core Content

The largest-scale content is the story mode, so it is natural to define this as the core content. However, it is also possible to define all of the content, including minigames, as the core content. Determine the core content based on the specifications of your application.

Policy for Supported Play Modes

The story mode is the core content for this application, so the play mode supported by the application will be the play mode used for story mode.

  • Story mode
    →TV mode, handheld mode, tabletop mode
  • Minigame 1
    →handheld mode, tabletop mode
  • Minigame 2
    →TV mode, tabletop mode

In this case, TV mode, handheld mode, and tabletop mode are all supported play modes. However, Minigame 1 and Minigame 2 can only be played in some of these play modes. So we recommend including in the supported play modes field the description that "some content cannot be played" in handheld mode and TV mode, and explaining the compatible play modes at the beginning of the minigames.

If all content, including minigames, is to be included in the core content, the only supported play mode is tabletop mode. This is because it can be used for story mode, Minigame 1, and Minigame 2. What content is designated as the core content depends on the developer, but please take into consideration the users' recognition of "core content" to avoid any misunderstandings.

Example 3: An Application With Different Types of Core Content, for Which the Supported Play Modes Are Also Different

Application Overview

This is the case where a single application contains multiple game modes that are each compatible with different play modes. Both game modes are considered equal, and both types can be considered core content.

For example, a game like the Mario Kart series. Game Mode A is equivalent to single player mode and Game Mode B is equivalent to multiplayer mode.

Figure 7-3 An Application With Different Types of Core Content, For Which the Supported Play Modes Are Also Different

Definition of Core Content

If both game modes are considered equal and you want players to both play the most, they can both be considered core content.

Policy for Supported Play Modes

Both Game Mode A and Game Mode B are considered core content for this application, so enter the supported play mode for both modes into the play mode field.

  • Game Mode A
    →TV mode, handheld mode
  • Game Mode B
    →TV mode, tabletop mode

If the play modes for Game Modes A and B are as described previously, the supported play modes for this application are TV mode, tabletop mode, and handheld mode. However, all of the play modes are not used in each game mode, so to clarify this to the user we recommend adding further description in the supported play modes field such as "Note: Only supported in Game Mode A" for handheld mode and "Note: Only supported in Game Mode B" for tabletop mode. (TV mode is supported in both Game Mode A and Game Mode B, so it does not require additional description.)

Example 4: An application that progresses by clearing multiple minigames

Application Overview

This application contains multiple minigames. When the user completes a minigame, the next minigame appears and the game's overall progression is based on clearing these minigames in order.

For example, games similar to the Made In Wario series.

Figure 7-4 An application that has progress by clearing multiple minigames

Definition of Core Content

Because the game will not progress without completing each of the minigames, they are together considered to be a single continuous story, and, as a result, are a single unit of core content.

Policy for Supported Play Modes

  • Various minigames
    → The play modes differ for each minigame

Because the overall progression of the application is stalled if the user does not complete the minigames along the way, the supported play mode is the one common to all of the minigames. Based on the characteristics of minigames as described previously, it is likely that the play modes compatible for each minigame are different. In this case, if a common play mode cannot be specified for all of the minigames, we recommend performing the following to avoid stalling progression in the application.

  • Set alternative methods of operation (for example using cursor controls in place of touch panel controls)
  • Set options to avoid (for example operations that do not appear in a certain play mode)

Example 5: An application that contains multiple independent minigame contents

Application Overview

This is the state where there are multiple minigames, and each of these minigames is independent from the other minigames from the beginning. Completing a specific minigame does not affect the other minigames.

For example, a game such as Wii Sports.

Figure 7-5 An application with multiple minigame contents that exist independently of one another

Definition of Core Content

Each of the minigames exists independently and it is not possible to define any specific minigame as the core content.

Policy for Supported Play Modes

  • Various minigames
    → The play modes differ for each minigame

It is not possible to specify the core content for applications that consist of a collection of minigames. In addition, if the play modes for each minigame differ due to the characteristics of the minigames, we recommend describing all of the supported play modes in the play modes field and adding "Note: The play mode differs depending on the content", and then describing in the application itself which minigames use which play modes.

However, you can provide users with incorrect expectations if you include play modes in the play mode field that are only used in a small number of minigames. It is difficult to predict at what point play modes go against user expectations if they are not supported by certain minigames, as that depends on each application. We recommend determining a threshold, such as making a decision of only considering play modes that are supported by over 60 percent of the minigames as supported play modes.
