2.6 Delivery Log

What Is a Delivery Log?

Using the BCAT Management Tool in the production environment (lp1 server environment), you can download delivery logs to the Switch system for each News channel or application that supports data delivery.
The following use cases are expected.

  • Estimating the number of Switch systems that follow a channel
  • Estimating the number of Switch systems that can use network features of applications
Info

The number of unique Switch systems in the delivery log and the number of Switch systems that actively start applications may not always match because of the background synchronization feature in data delivery.

Delivery Log Requests and Downloads

Delivery log requests and downloads are made in the Stats > Log Requests menu.
The Manager role is required for requesting delivery logs.
The Viewer role or higher is required for downloading delivery logs.

Logging Time of Delivery Log

Specify the logging time when requesting a delivery log.

  • Specify a logging start time that is earlier than the time you begin to use the BCAT Management Tool.
    • However, you cannot specify a time that precedes the current time by more than a year.
    • For News delivery: The usage start time refers to the time when a channel was approved in NCMS.
    • For data delivery: The usage start time refers to the time when content of a request was first synchronized from OMAS.
  • Specify a logging end time that is earlier than two hours before the current time.
  • The logging time for a request can be specified for up to 31 days.
    • For example, if delivery logs for a whole year are required, 12 separate requests must be made.

Expiration Date of Delivery Log

Delivery logs cannot be downloaded after a certain period of time (currently set to one week) has elapsed since the request.
Request the delivery log again, if necessary.

Delivery Log Format

News Delivery

The following is a sample of the delivery log format for News delivery and a description of the columns.

"masked_ip","masked_serial","news_id","data_id","http_status_code","accessed_at"
"B91A1F74D56D1122FB05F7A111111111","839B9B2B432C0C562C43EFD499999999","777","16001","200","2017-08-25 00:18:00.000"
"B91A1F74D56D1122FB05F7A111111111","839B9B2B432C0C562C43EFD499999999","778","16002","200","2017-08-25 00:18:00.100"
Column Name Description

masked_ip

Global IP address of the Switch system.

It is masked.

masked_serial

Indicates the Switch system serial number.

It is masked.
news_id

An ID for identifying News.

This value is displayed in the BCAT Management Tool.

It is not changed even if News is revised and redelivered.
data_id

An ID for identifying News within the system.

This value is not displayed in the BCAT Management Tool.

It is changed when nNews is revised and redelivered.

Ignore this value when there is no need to differentiate News before and after revision.
http_status_code

HTTP status code.

For example, if you want to know when a particular Switch system first received News, note the rows where the value is 200.
At this time, ignore rows where the value is 304.
accessed_at

The time when a Switch system requested data transmission from the server.

The time is in the UTC time zone.

Delivering Data

The format of delivery logs for data delivery is the same as that for News delivery except for the following points.

  • datafile_id is listed instead of news_id.
  • datafile_id is a binary value. For more information, see 4 Data Delivery. This value is displayed in the BCAT Management Tool.
  • Ignore the data_id value.
