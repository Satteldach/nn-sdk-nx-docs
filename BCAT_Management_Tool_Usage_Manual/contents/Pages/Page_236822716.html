6 BCAT WebAPI

Using the BCAT WebAPI

This section describes how to use the WebAPI (the API) to operate the BCAT Management Tool.

This API is provided for use in data delivery.

Authentication

The method for authenticating requests differs depending on the version of the API.

V1 Authentication

Access tokens are used to authenticate requests.

To set up an access token, you must first prepare a Nintendo Developer ID (NDID) that has been configured with the appropriate role on OMAS.

For more information, see here.

NDID Setup

Complete the following steps to set up an NDID.

  1. Select an NDID to use with the WebAPI.
    We recommend creating a new NDID exclusively for patch processing instead of using an existing NDID linked to an individual.
  2. Use that NDID to log in to the BCAT Management Tool.
  3. Viewing permissions for titles are automatically synchronized with OMAS.
  4. On the Role Management page, assign appropriate roles for each title that can be viewed with the NDID.
    See the description in 2.2 Roles and Usage Requests.
Note

The roles configured on that page determine whether a specific WebAPI can be called.

For example, a user needs the Editor role or higher to call the WebAPI for creating new data.

Setting Up an Access Token

  1. Log in to OMAS with an NDID that can edit OMAS title information.
  2. Open the OMAS title information page. Select NDID Authorization (Web Services) > BCAT. Enter the purpose of use and access frequency, and submit the request.
  3. Nintendo reviews the request.
  4. If Nintendo approves the request, an OAuth client is added to the same page. This client is named using the naming convention "HAC_ABCDE_bcat" to indicate it is for the BCAT WebAPI.
  5. For more information about the rest of the procedure, see the Help for the NDID Management System, in Japanese or English.

Managing Access Tokens

Using an access token generated by the NDID, you can operate all applications that can be operated on the BCAT Management Tool.

When you manage these access tokens, consider that the applications that can be operated are not limited to those for which NDID authorization has been requested.

V2 Authentication

An ApiKey value is used to authenticate requests.

Click one of the links in the next section to jump to the page with the specifications for one of the different API versions. Then click WebApi Accounts (Create ApiKey) and follow the instructions on the screen to create a new WebAPI account and an ApiKey value.

When you create the WebAPI account, specify which applications can be operated using the ApiKey value. You can only specify applications for which you have the Manager role.

API

When you call an API, set the appropriate parameters and HTTP methods based on the specifications for that version of the API.

For more information about the specifications for each API version, see the following webpages. These webpages are divided by server environment and API version.

By entering an access token or ApiKey value in the text box at the upper right, you can run the API directly on the webpage.

Note

Assign a string with the 0x prefix omitted to the application_id parameter.

For example, if the Application ID is 0x0100bc90020e4000, assign 0100bc90020e4000.


Info

The function types and specifications are shared between all server environments.

However, because the server is updated at different times for each server environment, new types of functions may sometimes only be added to specific server environments.
