4.4 Ranking

Using RankingConstants::ORDER_CALCULATION_123

When RankingConstants::ORDER_CALCULATION_123 is specified and there are several instances of the same score, earlier scores are ranked higher. When a user registers a score that duplicates a previously uploaded score, the date for the score is updated, which could cause the score to be ranked lower than before.
If you are using RankingConstants::TIME_SCOPE_ALL for the time scope or filtering the time scope only by periodically resetting the period, you can prevent the ranking order from being reversed by not registering the same score if it has been uploaded already.
If the time scope filter has been set to a period of time relative to the present, the data collection period for rankings is always changing and the upload date for a score must be updated even if the score is the same as before. This method will not work in those cases.

Notes About Deleted Score Data

Incorrect ranking data is obtained for as long as an hour after score data is deleted using NMAS2 or WebAPI. Note that if you repeatedly delete score data for purposes such as debugging, you may not receive the correct rankings.
