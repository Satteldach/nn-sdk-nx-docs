4.7 WebAPI

You can use the NEX WebAPI to manage the data on the game server, periodically uploading, deleting, and aggregating the data.

These features provided as the WebAPI can also be used from NMAS2.

Processes Configurable Only From the WebAPI

The following processes can only be run from the WebAPI (or from NMAS2). Note that these processes cannot be executed by applications using NEX.

If your specification requires the game server settings to be configured in advance, use the WebAPI (or NMAS2) as needed to configure those settings.

Matchmaking
  • Creating and editing persistent gatherings
  • Configuring range broadening auto-matchmaking
  • Configuring score based auto-matchmaking
Ranking
  • Creating and editing categories
  • Setting the range of rankings that can be retrieved using cached rankings
  • Setting a custom time scope
Info

One exception is that a WebAPI for rankings is not provided, so the preceding processes can only be run from NMAS2.

Ranking2
  • Creating and editing categories
  • Creating and editing category types
  • Configuring ranking chart data
Utilities
  • Configuring application-specific server settings
  • Configuring settings for maintenance notifications
Debug Assistance
  • Configuring error simulations

Considerations When Using WebAPI

The NEX WebAPI is provided for the purpose of data management, so limit requests to one time per second per application. It cannot be used for sending requests linked to the operations of users using applications and web services, or for frequent updating.

The WebAPI can be used for the following purposes.

  • Tallying the data store ratings values one time per day and displaying them in a webpage
  • Moving the data posted in the data store to a server for management one time per day
  • Periodically deleting old ratings data

The WebAPI cannot be used for the following purposes.

  • Sending a request from the application to the independent server to get specific data, and having that independent server send a request to the game server using the WebAPI
  • Replacing all of the data in the data store at a specific time (because it would require sending more then one request per second)
  • Providing a web service for users where WebAPI requests are sent in response to user operations

Contact Nintendo if you are unsure whether any of these cases applies to your application.
