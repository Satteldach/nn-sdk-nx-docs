4.5 Server Operations

Automatically Copying Game Server Settings

When the game server settings are changed using NMAS2 or WebAPI, only some settings are copied from the game server in the development environment (dd1) to other environments.

If the application requires a particular configuration of the game server for normal operations, make sure that you check the settings on NMAS2 at the following times.

Timing What to Check
Immediately after the application has been submitted to Lotcheck. The settings in the Lotcheck environments (the sd1 and sp1 environments).

Immediately before the application release.

(The period between when the phase on OMAS becomes In Service and the actual release date of the application.)

 The settings in the production environment (lp1).


Timing of Copying

Game server settings that have been changed in the development environment are copied to other environments at the following times.

Lotcheck Environment

When the Lotcheck environment game server is first set up
  • The Lotcheck environment game server is set up at the same time as the development environment game server.
  • If the phase on OMAS has progressed to Setup Complete, the Lotcheck environment game server has completed being set up.
After the Lotcheck environment game server has been set up
  • After the Lotcheck environment game server has been set up, settings are copied once per day.
Info

This frequency is subject to change without notice.

Production Environment

When a new production environment game server is set up
  • The production environment game server is set up some time after Lotcheck is completed and before actual service begins.
  • If the phase on OMAS has progressed to In Service, the production environment game server has completed being set up.
When the production environment game server restarts when a patch is released
  • If the Block Earlier Releases From Connecting to NEX/NPLN Server item is selected when the patch request is submitted on OMAS, the game server will be restarted to coincide with the distribution of the patch.
    • If this item is not requested, the production environment game server will not be restarted and the game server settings will not be copied.
    • For more information on making the request, see 5.4 Patches and Compatibility > Breaking Compatibility Between Versions When Distributing a Patch.
  • If the phase of the patch title on OMAS has progressed to In Service, the production environment game server has finished restarting.
  • The game server settings will not be copied if the game server is restarted to deal with a server failure or at any other time except when a patch is released.

Copied Game Server Settings

The following NMAS2 settings are copied automatically. Consider this fact if you change any of these settings in a patch.

Matchmaking
  • Matchmaking server settings
  • Rating matchmaking thresholds
  • Score-based auto-matchmaking settings
  • Matchmaking referee settings (number of recent history items)
Note

The following settings are not copied.

  • Persistent gathering settings

Ranking
  • Settings
Info

To be specific, the following settings are copied.

  • Custom time scope 0
  • Custom time scope 1
  • UTC offset for the time scope
  • Time Scope ALL enabled or disabled
  • Length of cached top rankings


Note

The following settings are not copied.

  • Settings for each category (Minimum Score and Maximum Score)
  • Score data uploaded for each category

Ranking2
  • Category (settings for each category)
  • Category type (settings for each category type)
  • Ranking chart
Note

The following settings are not copied.

  • Season information in the settings for each category type
  • Score data uploaded for each category

Utilities
  • Application settings
  • Maintenance notification settings


Info

The preceding settings are managed per game server. When developing a new application that will share a game server, for example a localized version of the application, make sure that there are no conflicts.

Common Products and Shared Game Servers

One game server is set up for each application. However, if a common product is set for an application when the product is created in the Nintendo Developer Portal, that application shares a game server with the other applications that have been set with that same common product.

The game server is set up such that applications set with the same common product all use the same game server.

If you want an application that is not set to a common product to share a game server with other existing applications, you must configure it on OMAS.

Impact of Maintenance and Maintenance Notifications

This section describes the specifications for game server maintenance.

Types of Maintenance Notifications

When a game server is under maintenance, the following two kinds of notifications are sent.

Notification of Scheduled Maintenance

This notification is sent by the game server approximately one hour before the scheduled maintenance time.

This feature is disabled by default. The setting cannot be changed from NMAS2. Consult with Nintendo in advance when this feature is necessary.

Info
  • Notifications of scheduled maintenance are provided on the assumption they will be used by applications where online play exceeds roughly 10 minutes at a time.
  • Notification of scheduled maintenance is skipped in the case of emergency maintenance.

Maintenance Start Notifications

This notification is sent by the game server at the scheduled maintenance time.

This feature is enabled by default. The setting cannot be changed from NMAS2.

Receiving Maintenance Notifications

Maintenance notifications (both for scheduled maintenance and the start of maintenance) are received using one of the following two methods.

Receiving Maintenance Notifications Using the Overlay Notifications System Feature

This feature displays the maintenance notification as an overlay notification, which is part of the system features.

For more information about the Overlay Notifications system feature, see the Nintendo Switch System Features Guide.

Notifications to users are handled by the system feature, so the application does not need to support them.

This feature is enabled by default. The setting can be changed from NMAS2.

Receiving Maintenance Notifications as NEX Library Notification Events

This feature receives maintenance notifications as nex library events.

Use this method if you want to use application-specific controls to handle maintenance notifications in the application.

This feature is disabled by default. The setting can be changed from NMAS2.

Maintenance Flow and Impact on Users

①: The period until the notification of scheduled maintenance is sent
  • No effect on users.
②: The period between sending the notification of scheduled maintenance and the actual scheduled maintenance time
  • The notification of scheduled maintenance is issued approximately one hour before the scheduled maintenance time.
  • No effect on users aside from the notifications of scheduled maintenance.
③: The period between the time of the scheduled maintenance and stopping the game server
  • A notification of the start of maintenance is sent when the time has arrived for the scheduled maintenance.
  • The game server stops roughly 5 to 10 minutes after the scheduled maintenance time has arrived. In the case of emergency maintenance, the game server stops immediately.
  • In the production environment, users cannot log in.
  • In both the production environment and the development environment, users who are already logged in cannot use matchmaking.
④: The period after the game server has stopped
  • When the game server stops, logged in users are disconnected.
  • Users cannot log in to a new session until the game server has been restarted.
