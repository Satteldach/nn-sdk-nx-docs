4.1 NEX General Considerations

Initializing and Logging In

  • The NEX library and the other libraries (libraries that the NEX library is dependent on) must be initialized before logging in to the game server.
  • If multiple Nintendo Switch consoles all linked to the same Nintendo Account log in to the game server at the same time, the users on the consoles that logged in first will be disconnected from the server. You do not need to pay special attention to this situation in your application. Handle it in the normal way you would handle a disconnection from the server.

Logging in From a Windows Application

If you want to log in to the game server from a Windows application (an application for which NX-x64, NX-Win32, x64, or Win32 has been specified as the build target), do as described below according to the version of NintendoSDK that you are using.

Info

The login method using the NgsFacade::DebugLoginDirect() function (using a default user name like testuser_1 prepared for each game server ahead of time, and a default password that is the same as the access key) was deprecated in June 2021.

NintendoSDK 16.x or Higher

  • See account Library for the Windows Environment (Japanese, English) in the NintendoSDK documentation.

NintendoSDK 15.x or Lower

  • Contact your Nintendo support representative. Nintendo will provide guidance for a special login method. Include the following information.
      • The version of NintendoSDK that the application is using
      • The application's game code (example: HAC-P-ABCDE)

Canceling Asynchronous Processes

Although you can cancel all asynchronous NEX processes, we do not recommend it unless there is a specific reason.

In some cases, the processing on the server may have already completed when the asynchronous process is canceled. For example, it is possible for the asynchronous process of creating a matchmaking session to be canceled after that session has already been created on the server. If the matchmaking session was created in a state open to participation, an unmanaged matchmaking session may be created. In general, we recommend not explicitly canceling the asynchronous processes.

Network Disconnection During Asynchronous Processing

When the connection to the network is lost, NEX cannot continue with normal communication, so you must finalize the nex library. The same is true if the network is disconnected during asynchronous processing.

If a network disconnection is detected during asynchronous processing, finalize the nex library. It is acceptable at such times to finalize NEX without first canceling the running asynchronous processes.

Threads on Which NEX Functions Are Called

If you select a thread mode that is not thread-safe like ThreadModeUnsafeTransportBuffer or ThreadModeUnsafeUser, you must call all NEX functions from the same thread. Call all functions from the same thread regardless of whether they involve communication, and regardless of whether the functions are synchronous or asynchronous. Alternatively, you can use exclusive control as appropriate.

Working With IDs Issued by Game Servers

The IDs issued by a game server are not unique outside of that game server. Not only are these IDs not unique across different applications, they also are not unique for the same application across game servers in different server environments (such as the development environment, the Lotcheck environment, and the production environment). As a result, you need to be careful when managing these IDs on an independent server.

For example, the data IDs in the data store might be the same in both the Lotcheck environment and the production environment, in which case there is a risk of duplication if you manage data based solely on data IDs on your independent server. If you plan to save IDs issued by the game server on an independent server or elsewhere, make sure that you manage that data together with information about the server environment.

Number of Data Instances That NEX Can Handle

For NEX data store, matchmaking, and ranking data, an upper limit of about 10 million pieces of data is assumed for each use. If the data exceeds these limits, there is a risk that server performance will decline enough to affect the user experience.

If you think that your application might generate more than 10 million total pieces of data, contact Nintendo in advance.

Data Store

The upper limit is 10 million total pieces of data, regardless of whether you are using a storage server. If there are 100,000 unique users, for example, and each user uploads 100 pieces of data, the total becomes 10 million pieces of data.

Info
  • For this discussion, the total number of pieces of data includes pieces of data that have been logically deleted but not yet physically deleted. As a result, if the data is within its validity period, the total number of pieces of data on the server is not reduced even if that data has been logically deleted. For this reason, set appropriate validity periods for data so pieces of data that have been logically deleted are then physically deleted.
  • When data is logically deleted, the game server automatically shortens the validity period for that data. Unless the validity period is intentionally extended for the logically deleted data, it will be physically deleted in turn. For more information, see NX NEX Manual > DataStore > Logically and Physically Deleting Data.
Matchmaking

Take the following measures so the total number of matchmaking sessions does not increase unnecessarily.

  • When matchmaking has completed and there is no longer any need to accept new users (for example, when transitioning to P2P communication), call the nn::nex::MatchmakeExtensionClient::CloseParticipation() function and close the matchmaking session.
  • When a matchmaking session is no longer being used, call the nn::nex::MatchMakingClient::UnregisterGathering() function and remove that matchmaking session. Alternatively, leave the matchmaking session.
Info

A matchmaking session that is not being used is removed automatically. For this reason, even if you neglect to remove matchmaking sessions, the number is not expected to reach 10 million sessions.

Ranking (Ranking and Ranking2)

Each user can only keep one score to each category, so assuming there are 100,000 unique users and 100 categories, there would be a total of 10 million scores.

Info

If periodic resets are enabled for a particular Ranking 2 category, consider the number of past sessions of data that will be saved when you estimate the total number of scores. For more information, see NX NEX Manual > Ranking 2 > Predicted Number of Scores.

Required Connection Environment for Connecting to the Game Server

The game server's global IP address is not fixed. In addition, a list of game server global IP addresses cannot be provided. Exercise care when connecting from an environment like a company LAN that restricts connection targets. Prepare an environment that does not restrict connection targets.

Info

Depending on the NEX features, communication may occur with servers other than the game server, such as the storage server for data stores. The global IP addresses for these servers are not fixed.

Breaking Compatibility and Version Connection Errors

Both the game server and the authentication server check the version of the application when the application connects to the game server. If there is a compatibility break of the kind described in 5.4 Patches and Compatibility > Breaking Compatibility Between Versions When Distributing a Patch, and an error occurs when the earlier version tries to connect to the game server, either of the following codes can be returned, depending on the timing.

Server Performing the Version Check Error Code
Authentication Server

2124-3001
Game Server 2306-0819

In the implementation of your application, consider the possibility that errors could be returned not only by the game server, but also by the authentication server. For more information about debugging, see Nintendo Switch Network Error Simulation Manual.

Info

In versions 4.4.0 and earlier, the NEX library provides an override of the nn::nex::NgsFacade::Login() function that takes nn::account::UserHandle as an argument. Note that in applications that use this function, the values obtained by the nn::nex::NgsFacade::GetLastLoginNnResult() function include nn::Result instances that come not only via the game server, but also via the authentication server.

Some NEX Services Cannot Be Provided to Users in Countries and Regions Where Nintendo Switch Online Memberships Are Not Available

A subscription to Nintendo Switch Online is required in order to use some of the NEX services, such as matchmaking.

Users in countries and regions where people cannot subscribe to Nintendo Switch Online, such as Taiwan and other places in Asia, cannot use these services.

For more information, see Nintendo Switch Online Play Guide > Nintendo Switch Online Support > Policies (English, Japanese).
