3 Development/Usage Overview

NEX is used in combination with the application (client) and game server. During development, consider not only the application, but also the status of the game server.

This overview is organized by the seven stages of the development process and describes the factors that require consideration in each stage.

Planning

The planning stage involves assessing the specific ways that you can use NEX to achieve your vision for the application.

No dedicated game server is provided in this step. Use the sample demo server to test various NEX features and confirm that those features are suitable for your application.

Note

As a general rule, we will stop accepting new requests to use NEX in August 2023 (see Acceptance of new requests for NEX features will end in August 2023 in Technical Information on the Nintendo Developer Portal). As needed, consider using NPLN (the game server service replacing NEX).

Sample Demo Server

The sample demos included in the NEX package connect to this sample demo server. Because the demo server is shared with other developers, note the following when using it.

  • Do not upload application-specific information or screenshots into the data stores.
  • Do not specify the same matchmaking game mode used in the sample demos.
  • Do not store application-specific information in shared data used for rankings and other purposes.
  • Pay attention to the server load (discussed later).
  • Do not delete data that is not yours.
  • Do not use during the development/debug step described later.

There are no restrictions on running the sample demo as is without any changes.

Development and Debugging

The development and debugging stage begins when application planning is complete and you have a better understanding about how you will be using NEX in your title. This step uses the game server prepared for each application instead of the sample demo server.

Requesting Use

To use a dedicated game server for your application, you must make a use request on OMAS2 (called "OMAS" in this document) to use NEX.

When you submit this use request, include information about how you will use the NEX features. Nintendo might refer to this use request when providing technical support around the time the application is released and for Lotcheck. Nintendo can respond more easily if you enter information describing where and how the NEX features are used in scenes in the application.

If you have not yet determined the details, enter that the details are still under discussion. In this case, update your usage request after the details are finalized.

Info

Regardless of the release version of the application that actually uses NEX, you may submit the NEX usage request in advance for the convenience of your development schedule.

For example, if you are not implementing NEX in release versions 0 through 2 but plan to use NEX in release version 3 (a patch), discuss this with Nintendo and then submit an NEX usage request. In addition, describe this background when you submit your application for Lotcheck.

Even if you are in the process of developing release versions 0 through 2, do not select Yes for Use NEX in Development Environment (dd1) Only. Only select Yes for this field if there are no plans to provide the product to end users.

Setup

The game server is set up when the phase for the release on OMAS has progressed to Setup Complete. In addition, you can use OMAS to check the game server ID and access key for this game server. Use this information to connect to the dedicated game server for your application.

Info
  • For more information about OMAS phases, see the Help for the OMAS system (Japanese, English).
  • If you change the version of the NEX library, you may need to update the game server. If you make a request on OMAS to change the NEX version, the game server will be updated if necessary after Nintendo has approved the request. This process requires approximately three business days from approval.



Server Load Considerations

The game server for each separate application shares a common server infrastructure with many other applications. To avoid having an adverse impact on other applications, avoid implementations that place a continuous high load on the game server.

Note

For game servers in the development environment (dd1), the application might receive a communication error (error code 2306-0345: QERROR(RendezVous, LimitExceeded)) if a user (principal ID) meets one of the following conditions.

  • That principal ID continuously calls a function.
    • Roughly speaking, this condition applies if a particular function is called over five times more frequently than defined in the Nintendo Switch Guidelines in 0026: Restrictions on Frequency of Calls to NEX API.
  • It continuously calls a function, regardless of the type.
    • Roughly speaking, this condition applies if a particular function is called more than 300 times in 5 minutes.

Be careful when developing and debugging your application to make sure that this kind of error is not received.


Info

Even for applications that share the same game server infrastructure, if those applications are using game servers with different game server IDs, design them in a way that prevents cross-referencing of data.

Lotcheck

When submitting applications to Lotcheck, check the status of the game server in the Lotcheck environment. For more information, see 4.5 Server Operations.

Go Live

The game server is set up in the production environment (lp1) approximately three business days after Lotcheck has completed for the application.

Change in the OMAS Phase

The OMAS phase for the release changes to In Service when the game server has been set up in the production environment.

Exception to Change in OMAS Phase

After a patch has been distributed, the OMAS phase for the release changes to In Service if the following two conditions are met, even though a game server has already been set up in the production environment. This behavior is the intended behavior.

  • The release version of the application is version 1 or later.
  • When the patch request was submitted on OMAS, Block Earlier Releases From Connecting to NEX/NPLN Server was set to Yes. (For more information, see Distributing Patches later on this page.)

Timing of When Game Server Is Available

You may connect to the production environment game server as soon as it is set up. It is not linked to the release date of the application. The application can link to the production environment game server even before the application release date. Be careful when implementing features that will not work correctly until after the release date, such as features that work with data distributed from an independent server.

Note

Release the physical version of your application for sale after you have used the following procedure to confirm that the game server has been set up in the production environment. Also do this before distributing downloadable applications and patches.

  1. Log in to NMAS2 and select the production environment game server.
  2. Try to display the data for a feature.
  3. Verify that no error occurs.


Info

You cannot specify the day that the production environment game server will be set up.

Analysis

To check the statistics on the use of the production environment game server, access the SMAS web tool. Use this information when planning for patches or subsequent titles.

Distributing Patches

If you are distributing a patch, note whether there will be communications compatibility with the unpatched version of the application. If not, you must configure the game server so the unpatched application can no longer connect to the server. For more information, see 5.4 Patches and Compatibility.

Info

If you update the NEX library version when you distribute a patch, you must update the game server version at the same time. For this reason, if you do this, you must block the unpatched version of the application from connecting to the game server.

Localization

If you release a localized version of an existing application, as a general rule it will share the same game server. If you want to separate out the matchmaking results, data store data, and ranking data by region, do so by using separate categories and game modes for each region. You cannot prepare a separate game server for each region for this purpose.

For more information, see Common Products and Shared Game Servers in 4.5 Server Operations.

When releasing a patch for a localized version of an application, be careful about communication compatibility and changes to the NEX version. The game server is shared for all regions, so patches that break compatibility must be distributed to all regions at the same time. If you are considering such a scheme, consult in advance with the person in charge of distributing patches and make sure that this will be possible. Patches also must be distributed at the same time for all regions if the NEX version is being changed.
