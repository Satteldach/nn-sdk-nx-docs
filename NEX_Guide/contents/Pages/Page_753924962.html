5.5 Applications for China

Usage Requests

Before submitting a request to use the game server in OMAS, discuss and agree on internet communication specifications with Tencent in advance.

Game Servers Are Set Up in China

The game servers used by applications for China are set up in China for all of the environments (the development, Lotcheck, and production environments). On the other hand, game servers for global applications (applications for countries other than China) are set up outside of China.

For this reason, game servers cannot be shared between applications for China and global applications.

Library Versions That Can Be Used

As a general rule, applications for China must use NEX library version 4.6.3 or later.
If you would like to use an older version of the NEX library, contact Nintendo and include the SDK version.

Game Server For Chinese Government Evaluation

If you need a dedicated game server for review purposes (a game server with a different game server ID than the retail product game server) when you submit your application for review by the Chinese government, follow the following procedure to make the request.

  1. On the Nintendo Developer Portal, create a product (product B) separate from the actual product (product A).
    • The name of product B should include a string indicating that this product is for evaluation purposes only.
  2. On OMAS, submit a game server usage request for product B. Select Yes for Whether to limit setup of the NEX server to the development environment (dd1).

Nintendo Switch Online Application Policy

When you make NEX usage requests on OMAS for an application for China, you must be careful about the Nintendo Switch Online application policy set for the application.

For more information, see Nintendo Switch Online Play Guide > Nintendo Switch Online Support > Support in Applications for China. (English, Japanese)

Info

Also see 4.1 NEX General Considerations > Some NEX Services Cannot Be Provided to Users in Countries and Regions Where Nintendo Switch Online Memberships Are Not Available.

Relay Server

NAT traversal is known to be more likely to fail when using P2P communication in China compared to other regions. To address this issue, intermediary servers (relay servers) are provided just for applications for China.

Using relay servers increases the possibility of successful communication between Switch consoles when NAT traversal has failed or is not expected to succeed.

If you want to use a relay server, contact Nintendo and include the following information.

  • Are you using the Pia library?
  • Are you using the NEX library's VSocket feature?

Distance Estimate Based on Internet Path Is Ignored

Using the score-based auto-matchmaking feature, the physical distance between Switch consoles (as determined by GeoIP) can be specified as a condition in matchmaking.

However, this condition does not work for game servers used by applications for China. In that case, the behavior is the same as if all Switch consoles are connected from the same city (for example, Beijing).

Specifically, the value of SCORE_CONVERSION_TYPE_DISTANCE (integer value 5) is always 0 before conversion.

Info

The GeoIP Geolocation Overwrite Settings can be changed in NMAS2, but those settings are ignored.


Cannot View Statistics in SMAS

Statistics for game servers used by applications for China cannot be viewed in SMAS.

We also have no plans to provide statistics through SMAS or other systems.

Info

For an overview of SMAS, see 3 Development/Usage Overview > Analysis.

Data Uploaded By a User With a Specific Principal ID Can Be Deleted

To comply with the law, there will be situations where the data uploaded to a game server used by an application for China by a user with a specific principal ID (the target) will be deleted from the game server.

We recommend that you emulate this state and confirm the following.

  • The application does not crash.
  • Web servers that access data using the NEX WebAPI do not crash.
Note
  • The operation to delete data can occur not only when the game server is down for maintenance, but also while the game server is running (while the application and the NEX WebAPI can connect to the game server).


Info
  • The operation to delete data is performed only in the production environment.
  • The target's network service account is deleted before the deletion operation is performed. As a result, the target can no longer log in to the game server.
  • When the deletion operation is performed, the target is logged out of the game server.

Emulation Example

Use the following combination to upload data to a game server and delete that data.

    • An application created for testing purposes
    • NMAS2
    • NEX WebAPI

What Gets Deleted

  • Matchmaking
    • The target's personal statistics. (The data is reset.)
    • Matchmaking sessions and persistent gatherings owned by the target. (They are disbanded.)
  • Ranking (Ranking1)
    • The target's common user data.
    • The target's scores (including the parameter (Param) for each score.
  • Ranking2
    • The target's common user data.
    • The target's scores (including the other data (Misc) for each score.
  • Data Store
    • Data owned by the target (including persistent data).
  • Subscriber
    • Because the topics feature has been discontinued (see Discontinuation of NEX Subscriber Topics feature in Technical Information on the Nintendo Developer Portal), there is nothing to delete.


Info

Supplementary Information for Matchmaking

  • The target is kicked out of all matchmaking sessions before being logged out. This kicking out is treated as a straightforward communication disconnection.

Supplementary Information for Subscriber

  • The user status (the status uploaded by the nn::nex::SubscriberClient::UpdateUserStatus() function) is deleted when a user logs out.
    • This is a general specification that has nothing to do with the deletion operation.

Dependencies

If your application manages the IDs for data of users other than the data of the local user, you must consider the possibility that those reference targets might cease to exist.

For example, if user A's common user data for rankings contains the data IDs for data in the data store that is owned by user B (the target), that data might be deleted before the expiration dates for those data IDs.

Items That Might Reference the Data of Other Users

  • Ranking
    • Common user data
    • Parameter for each score (Param)
  • Ranking2
    • Common user data
    • Other data for each score (Misc)
  • Data Store
    • Meta binary for each separate set of data (data ID) (MetaBinary)
  • Subscriber
    • A string for each set of content
    • A binary for each set of content
  • Application Save Data
  • Data managed by an independent server
