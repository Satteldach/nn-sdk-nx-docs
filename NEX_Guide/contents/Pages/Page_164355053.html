5.3 Ranking

Using a Large Number of Ranking Categories

The RankingClient::GetRanking() function only allows you to specify one category at a time. If you are using a large number of categories, this function must be called as many times as there are categories. However, calls to the RankingClient API are limited to a maximum of 30 times in a five-minute period as per the guidelines, and so a maximum of 30 categories can be retrieved in five minutes.

To use a large number of ranking categories, you can use RankingClient::GetCachedTopXRanking() to get the cached rankings. This function can get a total of 100 top rankings across multiple categories. For example, if you only need the top five rankings, this function can get the rankings for 20 categories.

Note

However, when using cached rankings, it may take up to five minutes after the local user's score is registered before it appears in the rankings. As a result, in some cases the local user's score might not be included in the top rankings if rankings are retrieved immediately after the score is registered.

To avoid this issue, use RankingCachedResult::LocalUpdate() to register the local user's score. This step allows the cached rankings retrieved to include the local user's score.


Info
  • The guidelines are less strict about the frequency of calls to get cached rankings compared to the other RankingClient functions, so calls can be made at a frequency of 40 times in five minutes. In the case of the Top 5 rankings, you can get 800 categories over the course of five minutes.
  • If the frequency of calls still exceeds the limits in the guidelines even when using cached rankings, consider using Ranking2Client, the Ranking2 functionality.

Uploading Dummy Scores to a Ranking Category for Debugging

We strongly recommend preparing test cases with a large volume of dummy data ahead of time for debugging the ranking functionality.

Some of the NEX ranking functions have a restriction on the number of ranked scores that can be retrieved and might behave differently depending on the total number of ranked scores. In particular, when the range is specified in range ranking mode, these functions will only support offset values of less than 1000. If a larger offset has been specified, calls to these functions will return an error. Uploading dummy data enables you to test different workflows for getting rankings based on the total number of ranked scores.

Use NEX Management System 2 (NMAS2) to add dummy data. Select Ranking > Categories. In the Score tab, select Details for the category you want to add dummy data to, click Add Dummy Data, and add the dummy data.

Info
  • We suggest registering at least at 1500 instances of dummy data for each category.
  • Uploading dummy data takes a non-negligible amount of time. We recommend starting from a lower number of dummy scores and gradually increasing the number to get the desired number of dummy scores.
  • However, do not upload more than one million dummy scores due to the impact on server load.
  • This approach is the same as the approach for debugging the Ranking2 functionality.

Debugging When There Are No Scores in the Rankings

We strongly recommend using empty test cases (with no scores) for debugging the ranking functionality.

Use NMAS2 to delete the registered scores.

Info
  • There are no scores on the production environment server at the point the application goes live in the production environment. For this reason, automatically delete all scores registered during development to emulate the state it will be in at go-live.
  • This approach is the same as the approach for debugging the Ranking2 functionality.

Linking With Data Stores

If you want to include information about the user when uploading a score to the rankings, upload that user data to a data store and associate it with the ranked score.

To perform this, upload the desired user information to the data store in advance and associate a data ID with that data. Then, when calling the RankingClient::UploadScore() function, set the data store data ID as one of the parameters in the RankingScoreData object. Doing this allows you to download the data associated with that data ID on the data store when the user retrieves the rankings.

Info

You can use the same linking method when using the Ranking2 feature instead of Ranking.
