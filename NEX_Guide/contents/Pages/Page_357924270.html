5.4 Patches and Compatibility

Breaking Compatibility Between Versions When Distributing a Patch

To distribute a patch, you must submit requests on NCMS and OMAS.

If you want to break compatibility between versions at the same time that the patch is distributed, we recommend requesting both A and B below. This will make it so only the patched version of the application will be able to connect to the game server.

  • A: Prohibit logins by the unpatched application.
  • B: Restart the game server and kick out logged-in users.

That being said, if all of the following conditions apply, we recommend requesting only A.

  • Patched and unpatched versions of the application can coexist on the game server at the same time without issues.
  • There are no issues from a user support perspective with the unpatched application remaining on the game server.
Note

All of the following steps must be taken if a series of applications share a single game server (for example, there are separate application IDs for Europe and North America).

  • Request both A and B for all applications in the series.
  • Distribute the patch simultaneously worldwide for all applications in the series.

If these steps are not taken, there is a risk that incompatible versions of the application will be present on the game server.

Prohibiting Logins to Unpatched Applications (A)

Submit the following request on NCMS to prohibit any new logins by unpatched versions of the application at the same time that the patch is distributed.

  • When submitting the patch on NCMS, select Force Update for Force Update Flag (use authentication server to break compatibility).
Info

Prior to the NCMS server update in October 2021, this request item was displayed as Force Update Flag.

Restarting the Game Server and Kicking Out Logged-In Users (B)

Submit the following request on OMAS to have the game server restarted when the patch is distributed.

This kicks out users who are logged in when the patch is distributed.

  • When submitting the patch on OMAS, select Yes for Block Earlier Releases From Connecting to NEX/NPLN Server.
Note

The game server will be in the maintenance state before and after restarting. Note that this can affect users.

Info
  • Prior to the OMAS server update in October 2021, this request item was displayed as Restart NEX Server When Patch Is Released.
  • The name of this setting in Japanese was changed during the June 2020 server update for OMAS, but the English name was already Restart NEX Server When Patch Is Released.

Breaking the Compatibility of Features Without Restarting the Game Server

Depending on how the features that use NEX have been implemented, you can break communication compatibility between the unpatched and patched versions of the application but allow them to coexist on the game server.

In this way, services can continue without restarting the game server even if the distribution of a patch breaks compatibility in the application specifications. In addition, patches for applications sharing a game server can be distributed to the different applications at different times.

Matchmaking

You can prevent matchmaking between the unpatched and patched versions of the application by changing the game mode specified for matchmaking sessions in the unpatched and patched versions.

If you employ this method of changing the matchmaking game mode when a patch is distributed, there is a risk that the number of game modes will increase every time you release a patch that breaks compatibility, reducing the matchmaking success rate. To prevent users from being dispersed among numerous game modes and reducing the matchmaking success rate, we recommend using the procedure described in Prohibit Logins to Unpatched Applications to restrict connections by versions of the application that do not have the latest patch.

Ranking

You can prevent unpatched and patched versions of the application from referencing the same rankings by changing the categories for which scores are uploaded and rankings are obtained before and after the patch.

Data Store

You can prevent unpatched and patched versions of the application from referencing the same data by changing the data type of the data specified when uploading (or searching) data from before and after the patch.
