2 Server Services Functionality

Nintendo offers a library called nex that provides server services by communicating with the Nintendo game server. The nex library is compatible with multiple platforms.

The following is a description of the server services functionality available from NEX.

Matchmaking

Matchmaking is a feature that allows users to find other players to play with in online, multiplayer matches. A group of players that are matched up and play together in matchmaking is referred to as a matchmaking session.

You can use the matchmaking functionality to create matchmaking sessions based on criteria specified by the application, and to search for matchmaking sessions that match specified criteria. For example, you can search for matchmaking sessions created by a friend, or search for or create matchmaking sessions that have attribute values that are specified by the application. You can also get matchmaking sessions that specific users have already joined.

Persistent Gatherings

A persistent gathering is a group gathering where information persists on the server even after all group members have logged out from the game server. The server maintains data on group participation even when users are offline. In addition, the following use cases are available for matchmaking using only users who have joined specific persistent gatherings.

  • User-driven community creation functionality, in addition to matchmaking and ranking within communities
  • Official competitions hosted by the application's publisher
  • Competitions organized by users

Persistent gatherings are managed independently by each game server.

Ranking

Ranking refers to the ability to acquire an order, based on scores, after servers tabulate score data that users upload. There are two types of ranking functionality available from NEX: Ranking and Ranking2. Your application specifications determine how you differentiate them.

Ranking

With the first type (Ranking) you use different categories to separately handle multiple scores for a user. You can get the ranking order for each score separately. For example, by using several categories, you can get rankings for each stage, rankings for each game mode, and so forth.

You can also set group values for scores. By using group values, you can create ranking data that is narrowed down to a specific group. For example, suppose there is an online tournament where users are separated into a number of different power levels to compete. If each user's power level is specified for the group value when scores are uploaded, you can get the rankings later and specify a group value to get the rankings for a specific power level.

In addition to categories and group values, you can specify the following ranking modes to realize a variety of different kinds of rankings.

Info

You can also get statistics on score averages, minimums, and maximums.

Ranking Modes

Range Ranking

In this mode you get the rankings that are within the range of rankings you want to acquire.

Nearby Ranking

In this mode you get a range of rankings that places a specific user at the center of that list of rankings.

Friend Ranking

In this mode you get a range of rankings that is specific to your own friends.

Nearby Friend Ranking

In this mode you get rankings of your friends who are nearby.

Get User's Ranking Data

In this mode you get the ranking data for only the specified user.

Ranking2

The functionality available with the second ranking option, ranking2, is similar to that of the first option, described previously. There are some specification differences. The major differences are listed below.

  • The guidelines for restrictions on API call frequency are more relaxed compared to the ranking feature.
  • You cannot use group values.
  • You create settings for data like the periodic reset interval and minimum ranking order at the category type level.
  • You configure the various categories by associating them with preset category types.
  • Any score data that falls outside of the minimum ranking order that was configured for a category is deleted.
  • You can get a ranking chart with statistical information about all scores uploaded to date.

For more information about differences compared to the ranking feature, see the NX NEX Manual.

Data Store

Data store refers to network storage functionality that enables you to upload or download any data. When a user uploads data they created, they can then share that data with friends or other users.

Data store offers the following functionality.

Uploading

Uploads data to the server. Access permissions must be set for the data that is uploaded. Choose from among different options, including only me, only certain users, only friends, or all users. Because metadata including the data type and tag information can be attached to the data, you can use this metadata to search for data.

Downloading

Downloads data from the server. Users can download only the data for which they have the appropriate access privileges.

Search

Searches for the target data within the data uploaded to the server. There are several different ways to search, including searching for the user that uploaded the data, searching for the data type, searching for tags, and searching for the date the data was uploaded or updated. It is also possible to sort the search results by date or rating value.

Update

Updates data uploaded to the server. You can update just the data itself or just the metadata as well.

Rating

You can apply rating values to data uploaded to the server. Because you can sort the search results based on these rating values, you can do things like getting a list of data for users ranked in order by the ratings.

Deletions

Deletes data uploaded to the server. Even without explicitly removing data, it is automatically removed after a set period because an expiration time is set for the data when you upload it.

Perpetuating

Perpetuates data uploaded to the server to block the removal of the data that would normally occur at the expiration time. Each user can only perpetuate a certain amount of uploaded data.

Subscribers

In the subscriber feature, the status of users is sent and received via the server, enabling users to share their online status and online play status.

This section describes the two types of subscriber features.

Topics (Discontinued)

Note

This feature has been discontinued. For more information, see Discontinuation of NEX Subscriber Topics feature in Technical Information on the Nintendo Developer Portal.

This messaging feature is based on the publish-subscribe model. Users can post content to channels that handle specific topics. By periodically getting the content posted to a particular topic, users can always stay on top of latest posts to that topic.

Up to 128 topics can be used with each game server.

Shared User Status

With this feature, users post their status to the game server so friends can share that status.

Depending on the information that is posted, friends can disclose and reference each other's login status or play status. This feature can also be used to invite friends for matchmaking.
