3.3 User Account States

With the Switch, you can set the timing of when to ask the user to select an account to match the sequence design of the application. As a result, switching the signed-in or signed-out state of each user account is basically performed within applications. When a user account is in the signed-in state, that user is recognized by the system as a user of the application. For user accounts in the signed-in state, the system issues Friend Presence information and records information to the Activity Log. In situations where multiple users are playing an application at the same time, multiple user accounts can simultaneously be in the signed-in state. For more information about the sign-in and sign-out processing for user accounts, see Changing the Signed-In and Signed-Out States of User Accounts in 5.1.1 Feature Group 1: Displaying User Accounts and Changing Their States.

Note

In this document, the signed-in and signed-out states refer to the selection state of a user account on the Switch console. Note that this is conceptually different from the process of signing in for authentication when connecting to a network.

Differences Between the Signed-In and Signed-Out States

User accounts differ in the following ways when they are in the signed-in or signed-out states. Regardless of the signed-in or signed-out state of the user account, all save data associated with the application is accessible.


 Signed In Signed Out
Description of state The user account is selected in the application. The user account is not selected in the application.
Handling by system features Handled as using (playing) the application. Not handled as using (playing) the application.
Suspend icon The profile image is displayed on the application icon. The profile image is not displayed on the application icon.
Friend presence Can issue. Cannot issue.
Save data Accessible. Accessible.

If a user account is currently signed in, the profile image for that user account is displayed. If multiple user accounts are signed in, up to four accounts may be displayed.

If an obvious user for the application exists, putting the user account for that user into the signed-in state provides a more natural experience. In addition, Friend Presence can be issued while a user account is in a signed-in state as described previously, making it possible to show to friends that the application is currently being played.

Info

This documentation uses signed in or signed out, but other documentation may use open state or close state.

Timing of State Changes

The state of the user account changes at the following times.

  • Change from signed-out to signed-in
    • When the sign-in process of the account library is called on a user account that is in the signed-out state.
  • Change from signed-in to signed-out
    • When the sign-out process of the account library is called on a user account that is in the signed-in state.
    • When the application is ended.
      All signed-in user accounts are automatically signed-out.

System features such as the HOME Menu do not change the state while the application is running.
The timing of these switches in the state of the user account are diagrammed in the examples presented in 5.2 Different Designs for Supporting the Switch Account System. Refer to those as well.

Info

There is also the option of having the user select the user account before starting the application. For more information, see 5.2.5 Design 5: Select One Account Before the Application Starts.

Restrictions to State Changes

On Switch consoles with system version 6.0.0 and later, the user account states include one state where the user account cannot sign in. User accounts that are in this state cannot be used in the application. This state is set for the user account when the application starts and is based on the user's license to start the application. For more information about how the licenses owned by users are managed and shared on Nintendo Switch, see Nintendo Switch E-Commerce Guide.
