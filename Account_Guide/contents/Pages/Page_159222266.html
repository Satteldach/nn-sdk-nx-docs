5.2.1 Design 1: Select One Account After the Application Starts

In this design, the player is asked to choose from among the list of user accounts on the system immediately after the title screen for the application is displayed.
We recommend this design for applications that do not involve competitive or cooperative play on a single Switch system and are primarily played by one player (including applications where the player plays with other users over the network). For more information, see Reasons for Not Recommending Design 5 in 5.2.5 Design 5: Select One Account Before the Application Starts.

Advantages
  • You can use the account management applet.
Notes
  • For applications that include specifications for multiple users playing simultaneously, there is no way to specify users other than the first. For this reason, additional users are treated as guests.
    • This design is suitable if users after the first user only perform light support operations and the additional users are clearly identified as guests. (Their save data is not retained.)
      • You can also add a sequence to the application to allow users to select user accounts for the other users separately at the beginning of scenes where more than one person is playing. (Also see Design 3-3.)
  • To sign out and return to a state where no user is selected, a sequence must be performed.

Info

In version 6.0.0 and later of the NX system, a forced user selection can occur before starting an application, in conjunction with the application's license. However, in some cases user selection is duplicated for applications that have implemented this pattern in the HOME Menu and in the application.

As an option for avoiding this situation, a setting in SDK version 7.0.0 and later allows using selected user account data when the system has already performed user selection for reasons related to license. When this option is enabled, the application can get data about whether user selection occurred from the HOME Menu and data about the selected user. Using this data, you can achieve implementations that skip repeating user selection in the application when users were already selected in the HOME Menu.
