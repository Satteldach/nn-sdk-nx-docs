5.2.5 Design 5: Select One Account Before the Application Starts
Note

This design is an option provided with porting to the Switch in mind, such as for applications released on multiple platforms.
To improve the user experience on the Switch platform, we recommend using Design 1 or Design 2 instead of Design 5. For more information, see Reasons for Not Recommending Design 5.

This design uses the option to select a user account in the HOME Menu before starting the application.

Advantages
  • There is no need to consider sequences specific to the Switch account system.
    • In terms of implementing the application, the behavior is the same as it would be for the Wii U or for other ordinary account systems in that the application is started with a user account in a selected state.
Notes
  • If you select this design, you must still call the function to put the preselected user account in the logged-in state when the application is started.
    • For more information, see the reference for the account library in the SDK documentation.
  • For applications that include specifications for multiple users playing simultaneously, there is no way to specify users other than the first. For this reason, additional users are treated as guests.
    • This design is suitable if users after the first user only perform light support operations and the additional users are clearly identified as guests. (Their save data is not retained.)
    • You can also add a sequence to the application to allow users to select user accounts for the other users separately at the beginning of scenes where more than one person is playing. (Also see Design 3-3.)

Reasons for Not Recommending Design 5

The Switch is assumed to be used sequentially by multiple users. Prioritize a design where multiple users can play games comfortably without taking a lot of time or effort when switching users.

For example, the HOME Menu enables features that do not need to identify users to be used without first selecting a user, which means the user account does not need to be selected again when a different user performs operations.

Similar to the HOME Menu, also prioritize comfortable operation when switching users in applications.
For example, if you enable switching between user accounts within the application, the application does not need to be restarted when switching users, which eliminates the load times for processes such as restarting and reconnecting to the network. As a result, you can satisfy users who want to use the application as soon as possible.

Design 5 requires users to exit the application and restart when switching users.
This requirement adds extra effort for the user, and makes them wait longer than necessary. When considering an application that uses Design 5, you can change it to Design 1 (see 5.2.1 Design 1: Select One Account After the Application Starts) to reduce this extra effort and wait time.
