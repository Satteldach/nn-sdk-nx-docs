2.2 Application Features

Application Forms

Switch applications can be sold in two configurations: as card products and as downloadable products. The developer decides which form to create the application in, or whether to create both forms.

Applications sold as downloadable products are distributed by Nintendo eShop, the online marketplace operated by Nintendo. Users go there to get the downloadable version of the application. In addition to applications, Nintendo eShop can also distribute other products, including downloadable content sold as additions to games. For more information, see 8 E-Commerce.
For more information about the locations where content is saved, see NintendoSDK Documents > Features > Content Save Locations.

Updating the Application

Switch applications can be updated by installing patches.

If you offer your application as both a card product and a downloadable product, you can update both configurations with a single, common, patch.

A Switch patch is akin to a partial patch that makes revisions to only certain parts of a file, and it has several restrictions. Note that some of the restrictions must be supported when the initial version of the application is created. For more information, see NintendoSDK Documents > Features > Patches.

Switch systems receive notifications when patches are distributed. A Switch console that has received a notification proceeds to get information about the distributed patches and to download any necessary patch. The downloaded patch is installed when the application is started. Once a patch has been installed, the application will not be able to start without that version or a later version of the patch.

Multi-Program Applications

A multi-program application is an application that is a collection of programs. The individual programs can be developed independently, which is advantageous, but the downside of a multi-program application is that the process of switching between programs takes as much time as the normal application startup process.
For more information, see NintendoSDK Documents > Features > Multi-Program Applications.

Mechanisms Unique to Game Card Applications

Multi-Application Cards

Using a mechanism called the multi-application card mechanism enables you to write multiple applications to a single card. For more information, see NintendoSDK Documents > Features > NX Development Card > Multi-Application Cards.

On-Card Patches and On-Card Downloadable Content

Patches and downloadable content that are available for download on Nintendo eShop can also be sold bundled with the application on a card. This provides a way to give even users who play offline access to the latest patched version of the application or any content subsequently added to the application. These mechanisms are referred to as on-card patches and on-card downloadable content.
You need to pay attention to card capacity if you are using these mechanisms because the card must be large enough to hold both the original application and the patch or downloadable content. If card size is an issue, refer to Nintendo Switch Patch Guide > Application Compaction.

For more information about on-card patches, see Nintendo Switch Patch Guide > Switch Patch Features > On-Card Patch.
For more information about on-card downloadable content, see NintendoSDK Documents > Features > System > aoc Library > On-Card Downloadable Content.

Features for Saving Application Data

The following features are available for applications to save data.

Info:

There are several requests you must submit in advance to use these features for saving application data.
Read the information presented below, and if there is any possibility you will use any of these save features, review the cited documents and submit your requests as soon as possible.

Save Data

This feature is for storing application data and making it persistent. Data is saved to system memory. Applications can use the fs library to freely create files and directories in the save data, and read or write data.

There is a fixed upper limit on the amount of save data that an application can use. Contact Nintendo if it becomes clear that you cannot avoid exceeding this upper limit and will need more space.
For more information about save data, see NintendoSDK Documents > Features > Basic Features > fs Library > Manual > Features > Save Data > Save Data (NX Add-On) > Save Data Settings.

Temporary Storage

The temporary storage feature provides a work area for the application to save temporary files. The content saved to the temporary storage is not persistent, and is deleted when the application terminates. This feature is available starting with NintendoSDK NX Add-On 3.1.0.

You must submit a request to Nintendo to use temporary storage. For a description of temporary storage functionality and for more information about what is needed to submit a request, see NintendoSDK Documents > Features > Basic Features > fs Library > Manual > Features > Temporary Storage.

Cache Storage

The cache storage feature provides an area for the application to store data that can be regenerated and re-obtained. The content saved to the cache storage may be easily deleted or replaced at any time due to user operations, such as data management, deleting software, or replacing the SD card. This feature is available starting with NintendoSDK NX Add-On 3.1.0.

You must submit a request to Nintendo to use cache storage. For a description of cache storage functionality and for more information about what is needed to submit a request, see NintendoSDK Documents > Features > Basic Features > fs Library > Manual > Features > Cache Storage.

Performance Configurations Available to the Application

On Nintendo Switch, different performance configurations are available to the application (in terms of CPU, GPU, and memory clock rates) depending on the play mode. (See the following table.)

Table 2-1 Correspondence Between Play Mode and Performance Configurations
Play Modes Where Performance Configuration Is Available Performance Configuration
CPU Clock Rate GPU Clock Rate Memory Clock Rate
TV mode/tabletop mode/handheld mode 1020.0 MHz 307.2 MHz 1331.2 MHz
TV mode/tabletop mode/handheld mode 1020.0 MHz 384.0 MHz 1331.2 MHz
TV mode 1020.0 MHz 768.0 MHz 1600.0 MHz

For each play mode, you can select which supported performance configuration to use. The assumption is that performance will be configured with a GPU clock rate of 307.2 MHz and a memory clock rate of 1331.2 MHz when the Switch console is operating in tabletop mode or handheld mode. In principal, you must develop your applications so that they can operate under these conditions. However, it is acceptable to use a higher-performance configuration with a GPU clock of 384.0 MHz in some scenes where greater processing power is required. Note, however, that the following issues may arise more readily in scenes requiring this higher-performance configuration.

  • The cooling fan will spin faster, distracting the user with unwanted vibrations and noise.
  • The battery will drain faster and not last as long.

The Switch battery may not last as long as envisioned by Nintendo if you require a high-performance configuration in the majority of scenes in your application. (For more information about battery life, see the description of the battery pack component in 3.1 Switch System Hardware Configuration.) Consider one of the following procedures to handle this situation when it occurs.

  1. Reduce the volume of calculations when using a high-performance configuration.
  2. Implement a separate mode in the application that restrains battery consumption.

In the second instance, you can provide users with the option to select a performance for play that is based on the currently remaining battery capacity. This can be obtained by preparing a configuration that gets the most out of performance, and a configuration that prolongs battery life.

For more information about the performance configurations available to the application and how to set them, see NintendoSDK Documents > Features > Basic Features > oe Library > Manual > Features > Selecting Performance Configurations. For more information about gauging power consumption, see NintendoSDK Documents > Features > Features for Development > pcm Library.

Switch Applications for China

There is a special Switch system for China, and it differs in some ways from the Switch systems for other regions.

  • Nintendo Switch systems for the China region and Nintendo Switch system applications for China (applications for the China region) will only be available for sale in China.
  • The ROMs for applications for the China region must be created separately from the ROMs for the Nintendo Switch system applications that are not for China (applications for other regions).
  • Game cards for China are not ensured to run if inserted into Nintendo Switch systems for other regions, and game cards for other regions are not ensured to run on Nintendo Switch systems for China.

The following specifications are different for Nintendo Switch systems for the China region.

  • Nintendo eShop
    • You can only access Nintendo eShop designated for China from Nintendo Switch systems for the China region.
  • Network Environment
    • The NEX server (the game server provided by Nintendo) used by applications for the China region resides domestically within China.
    • Applications for the China region and applications for other regions may not share the same NEX server.
    • NPLN servers are not available to applications for China.
    • Applications for the China region and applications for other regions can communicate with each other by using independent servers.
    • Contact Nintendo if you plan to use Pia for internet communication.
  • Local Communication
    • If supported by the application, local communication is possible between Nintendo Switch systems for the China region and Nintendo Switch systems for other regions.
  • Account System
    • A separate account system, different from the Nintendo Account system, will be used in China.
  • Nintendo Switch Online
    • Not provided in China.
  • Health and Safety Warning Message
    • When an application for China starts, the Health and Safety warning message is displayed automatically.
    • Because the application screen is not displayed while the Health and Safety warning message is being shown, you must make sure that license logos and other important items that need to be shown are not hidden.
