3.6 Controller Support Applet

When developing applications for the Switch, you have many factors to consider for controllers, particularly because there are many ways to handle the Joy-Con controllers.

When starting or resuming an application, the controller connection status is hard to determine, and it is not clear how to hold the Joy-Con controllers. Consider that you might occasionally want to prompt the user to change the controller grip, depending on the scene while the application is running. In addition, the way a player uses a controller can change its state. Players can connect additional registered controllers, and connections can be lost as a result of the condition of the batteries or the signal strength.

The controller support applet is designed to decrease the amount of support needed from the application in such cases. You can prompt users to connect controllers or change controller positions based on instructions to the applet when you call it from the application. You might not need to use it, but if you do, it can simplify the handling of the controllers.

Info
  • For more information about implementation, see NintendoSDK Documents > Features > Library Applets > Controller Support Applet.
  • The NintendoSDK NX Add-On includes a controller support applet sample. For more information, see NintendoSDK Documents > Sample Descriptions.

Feature Description

A screen similar to the following is displayed when the controller support applet is called from the application.

Figure 3-3 Mockup Image for the Controller Support Applet

Press the L and R Buttons (or any of the following buttons: ZL, ZR, SL, and SR) to connect to the console. For Joy-Con, the button that is pressed determines the grip. Finally, pressing the A Button exits the applet.

Press and hold the SYNC Button to pair and connect the desired controller, even when it has not previously been paired with the console.

The target controllers and the number of controllers to connect are specified by the application.

The Controller Not Connecting applet feature describes how to pair controllers from the player perspective when they have problems connecting the controllers.

Info

A similar function can be called from Controller > Change Controller Grip/Order in the HOME Menu. The following settings are possible.

  • Acceptable play formats: Pro Controller play, Joy-Con controllers attached to the console play, Joy-Con (R) play, Joy-Con (L) play
  • Grip with single-controller: Horizontal grip
  • Minimum number of players using wireless controllers: 0 players
  • Maximum number of players using wireless controllers: 4 players
  • Dual-grip controller use: Enabled

The controller support applet has two modes: standard mode and single-player special mode.

Each of these modes is described separately.

Standard Mode

In this mode, users are promoted to prepare wireless controllers for up to eight players. Joy-Con controllers attached to the Switch console are not displayed as an option in the controller support applet screen, as shown in Figure 3.3.

Specifications When Calling the Applet

The application can also specify the following items when calling the controller support applet in standard mode.

  • The maximum and minimum number of players using wireless controllers (between 0 and 8).
  • Whether to maintain the connection status when the applet is called (if not maintained, all of the connected controllers will be disconnected).
  • Whether to fill in unused indexes when committing.
  • Allow determination when there are controllers in dual-controller grip mode? (For example, you can prohibit a dual-controller grip during local communication where a limited number of controllers can be connected.)
  • The frame color settings and the supplemental text settings for each controller (can be omitted).

The accepted types of controllers vary, depending on the settings separately specified by the application for the play formats and the grip for single Joy-Con play. For more information, see 3.1 Supporting Different Play Formats and Grips (Required).

Behavior After Returning to the Application

When the applet is in standard mode, one of the following is returned to the application that called the applet.

  • Indication that the user has selected to go back (meaning the controllers might not be in a state expected by the application).
  • Indication that the user has decided on a selection (meaning the controllers are in a state expected by the application). Also, the application is told the number of players recognized by the Switch system.

If the user decides on a selection that does meet the expectation of the application, an error is displayed and the process remains in controller support applet without returning to the application.

Note

In Nintendo SDK NX Add-On 8.0.0 and later, a Joy-Con attached to the system can be used to select to go back or make a decision in the applet, even if the application is not designed to support the operations of an attached Joy-Con controller. This design is intended to alleviate cases where the user cannot exit out of the controller support applet.

Supporting Five or More Players

In Nintendo SDK NX Add-On 8.0.0 and later, the controller support applet can accommodate the preparation of wireless controllers for five or more players (up to a maximum of eight). However, note the following points when five or more players have been specified.

  • Selection of dual-controller grip play is forcibly prohibited, even if the display of that play mode as a choice was allowed in Specifications When Calling the Applet. This design is intended to handle multiple connected wireless controllers (up to eight).
  • The display frame for each player is narrower, with less room for supplemental text.
Figure 3-4 Image of Controller Support Applet (For Eight Players, With Supplemental Text)

Supporting Solo Remote Grip

When you select single Joy-Con grip as a play format, which applies to both the Joy-Con (R) grip and Joy-Con (L) grip, you must also specify a grip (solo remote grip).

After making the selection and calling the controller support applet, the following screen appears.

If the play formats supported by the application include Joy-Con dual-controller grip and Pro Controller, the controller support applet cannot be called and returns an error.

Figure 3-5 Image of Controller Support Applet (Solo Remote Grip)

Note

In system version 6.0.0 and later, the controller support applet can now be called, supporting solo remote grip, even when applications support attached Joy-Con controller operations. This enables Back operations for attached Joy-Con controllers.

Single-Player Special Mode

Players are prompted to prepare controllers, including attached Joy-Con controllers, for one person. Use this single-player special mode when calling the controller support applet from single-player applications that support TV mode, handheld mode, and tabletop mode. Use standard mode even for single-player applications when the game requires a wireless controller.

Specifications When Calling the Applet

You can also specify the following options when calling single-player special mode in the controller support applet, from the application.

  • Whether to maintain the connection status when the applet is called (if not maintained, all of the connected controllers will be disconnected).
  • The frame color settings and supplemental text settings for the controller, used by the user (can be omitted).
Figure 3-6 Image of the Controller Frame and Supplemental Text

The accepted types of controllers vary, depending on the settings separately specified by the application for the play formats and the grip for single Joy-Con play. For more information, see 3.1 Supporting Different Play Formats and Grips (Required).

Behavior After Returning to the Application

When the applet is in single-player special mode, one of the following is returned to the application that called the applet.

  • A wireless controller was selected (controller index 1).
  • A Joy-Con/Switch combination configuration was selected.


There is no Back option for single-player special mode. A controller is always selected before resuming the application.

However, there are cases where cancel is returned to the application, depending on user operations (such as transitioning to the HOME Menu or calling the controller settings).

Note

In Nintendo SDK NX Add-On 8.0.0 and later, the controller support applet cannot be called in single-player special mode if the application does not support the operations of the attached Joy-Con controller. Use standard mode even for single-player applications when you want the player to use a wireless controller.


Unsupported Features

UI Customization

While some elements can be changed as specifications when the applet is called, the UI for the controller support applet offers a neutral feel, enabling it to work with any application.

Special Controller Configurations

The controller support applet is designed to be easy to use in most cases.

The following controller configurations are not supported by the controller support applet.

  • Simultaneous display of Joy-Con attached to the Switch system and wireless controllers (operations can be accepted if the application supports the configurations).
  • Joy-Con (R) solo-grip play is supported, but Joy-Con (L) solo-grip play is not supported (or vice versa).
  • Dual-controller grip play with five or more players.
  • Supporting a mix of solo remote grip and dual-controller grip.

Auto-Start

Because some applications must support connection or grip changes in their own independent UI, the controller support applet never automatically appears and starts running.

In all cases, the controller support applet will respond to calls from applications.

Considerations

  • When calling the controller support applet while performing local communication, wireless registration by holding down the controller's SYNC Button cannot be done due to radio frequency interference. However, you can connect, change the controller's position, and perform wired registration.
  • The internet connection can become unstable as a result of signal interference when calling the controller support applet while using internet communication. Avoid calling the controller support applet when you want to avoid internet connection issues.
  • When the controller support applet is called (including during the process of restoring the application), button input from holding down the button is invalidated by the system. For this reason, it is a better experience for the user to have the application enter a wait screen when resuming gameplay (such as in action games).

Not Using the Controller Support Applet

Applications can support reconnecting controllers and changing positions using a custom UI, without using the controller support applet.

It will not be possible, however, to pair by pressing and holding the controller SYNC Button.
