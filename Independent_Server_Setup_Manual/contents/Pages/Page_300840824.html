3.5 NSA ID Token Specifications


Note

It is prohibited to decode an NSA ID token within a Switch application and then use that information. For more information, see Nintendo Switch NEX Guidelines 0144: Prohibition of Decoding the Network-Service Account ID Token Within Your Application.

NSA ID Token Format

The NSA ID token is in JWT (JSON Web Token : RFC 7519) format. The three Nintendo signatures based on Header, Claims, and JWS (JSON Web Signature) are each encoded in Base64URL and concatenate with a period separating elements.

Header

A JSON object containing the following properties.

Key String

Type

Description
alg string

Indicates a signature algorithm.
kid string

The identifier for the public key used in the signature.
jku string (url)

Represents the URL needed to acquire a public key.
Claims

A JSON object containing the following properties.

Key String

Type

Description
iss string The base URL of the Nintendo authentication server that issues the token.
sub string

Indicates the internal ID of the network service account.

The format is an alphanumeric hexadecimal string of 16 digits, with lowercase letters and no 0x prefix.
aud string

Identifier issued by the Nintendo authentication server for Switch.

It does not need to be referenced by the independent server.
iat integer

The time when the token was issued. The format is a UNIX timestamp.
exp integer The period during which the token is valid. The format is a UNIX timestamp. Expires three hours after the token was issued.
jti string

The identifier issued for individual tokens. The format is UUID v4.
typ string The type of token. Fixed to id_token.
bs:did string

Indicates the login ID of the network service account.

The format is an alphanumeric hexadecimal string of 16 digits, with lowercase letters and no 0x prefix.
nintendo object

The following properties are included in the JSON object.

Properties included in the object may be added without notice in the future.

Key String Type Description
ai string

The ID (application ID) that identifies the application making the connection.

Reference this for verification by the independent server.

The format is an alphanumeric hexadecimal string of 16 digits, with lowercase letters and no 0x prefix.
av string

The release version of the connecting application. The value that is returned is the value that was set in the NMETA file.

The format is a 4 digit hexadecimal number.
at integer

The last authentication time of the application making the connection.

The format is a UNIX timestamp.

It does not match the time when the NSA ID token was issued (the iat value).
edi string

Information required when the independent server queries a Nintendo server.

The independent server cannot use this value.
opp string

This parameter is only added when an application's Nintendo Switch Online policy requires a subscription for some features.
For more information, see 3.3 Nintendo Switch Online Support.
ph string

This parameter is only added when an application's Nintendo Switch Online policy requires a subscription for some features.

For more information, see 3.3 Nintendo Switch Online Support.
hm bool

This parameter is only added when an application's Nintendo Switch Online policy requires a subscription for some features.

For more information, see 3.3 Nintendo Switch Online Support.

Verification Procedure

NSA ID tokens are verified using the following procedure. Sample verification programs are included in the appendix of this document.

Number Verification Content Notes
1

Verify that the token is in JWT format.

Confirm that the NSA ID token is in the correct format to perform the following verification.
2

Verify that the value of alg in Header is RS256.

This verification step is necessary to reject invalid NSA ID tokens, such as those with an alg value of none.
3

Verify the signature attached to the NSA ID token.

Use the Get member function to access the URL stored in jku for Header to get the public key or certificate to verify the signature.

The data that can be obtained is called a JSON web key set (JWKs) and is expressed as a JSON object array containing public keys and certificates.

The JWKs contains the kid property to specify which key to use.

The key information matching kid field in Header of the NSA ID token is obtained from the JWKs to verify the NSA ID token.

The signature verification algorithm is fixed to RS256 (RSA-SHA256) as indicated by the Header alg value.

Use the x5c value (certificate in X.509 format) contained in the JWK or the public key's n value (Modulus)/e value (Exponent) for verification.

The public keys and certificates needed to verify a signature are rotated every 24 hours.
To keep up with changes to the public key and certificate needed to verify a signature, the independent server must access the URL indicated by the value of the jku field and get the JWKs using one (or both) of the following methods.

Getting the JWKs On Demand

In this method, server-to server communication is conducted to get the JWKs if there is no cached JWKs when an NSA ID token must be verified.

  1. Check whether a JWKs is cached that corresponds to the kid value in Header.

    If it is not, execute the following procedure.

  2. Verify that the URL of the jku value in Header matches the URL provided by the Nintendo authentication server.

  3. Use the Get member function to request and get the JWKs for the URL of the jku value.

  4. Cache the obtained JWKs. At this time, old JWKs that have already been cached are destroyed.

Getting the JWKs Using a Periodic Batch Job

This method gets JWKs periodically using a separate process from the one for verifying the NSA ID token.
The rotation interval during normal operations is 24 hours. In the case of unforeseen circumstances like the leaking of keys, the keys might be replaced before 24 hours pass. For this reason, run the process at five-minute intervals.

Also, though you can use JWKs for a period of time by caching them after they have been obtained, be sure to destroy old JWKs when new ones have been obtained.

If you will be using a periodic batch job to get the JWKs, hard code the URL in the independent server. This is because you cannot get the URL for the request from the jku value in the NSA ID token. The URL to use for the request to get the JWKs is the Base URL (as listed in 6 Server Environments > List of Base URLs on the Nintendo Authentication Server) with the string /1.0.0/certificates appended.

Multiple generations (as of now, three generations) of JSON objects that include the public key and certificate are included within the JWKs. The reason for doing this is that the JWKs includes not only the public key and certificate to be used at the point when the JWKs was acquired, but also the public keys and signatures used before the prior rotation and after the next rotation.

This prevents an inability to acquire the target public keys or certificates in the following circumstances.

  • When the public key and certificate are rotated after Switch acquires an NSA ID token, and the NSA ID token is sent to the independent server which must verify it against the previous public key and certificate, until the NSA ID token cached in Switch expires.
  • When the public key and certificate are rotated after the independent server acquires the JWKs, and the NSA ID token that is sent from Switch to the independent server needs to be verified against the next public key and certificate, in comparison to what is cached on the independent server.
4

Verify that the value of iss in the Claims matches the Base URL on the Nintendo authentication server.

The Base URL of the Nintendo authentication server must be preregistered in the independent server in advance.

For the base URL value of each environment, see 6 Server Environments.
5

Verify that the value of iat in Claims is in the past.

 A calculation error of around 10 seconds can be tolerated to allow for time differences among systems.
6

Verify that the value of exp in Claims is after the current time.

A calculation error of around 10 seconds can be tolerated to allow for time differences among systems.
7

Verify that the /nintendo/ai value in the JWT claims matches the ID of an application that is allowed to make a connection.

 This verification is necessary to prevent connections from other companies' applications.
JSON Web Key Set (JWKs)

Key String

Type

Description
keys array

An array that includes the following JSON objects.

Key String Type Description
kid string

The identifier for the key used in the signature.
e string The exponent value of the Base64-encoded RSA public key.
n string The modulus value of the Base64-encoded RSA public key.
x5c array The Base64-encoded certificate chain in X.509 format.
alg string The signature algorithm. Fixed to RSA256.
kty string The key type. Fixed to RSA.
use string The use of the key. Fixed to sig.
usage string The use for the public key certificate. For an NSA ID token, the usage is developer.
