10.3 Example of Retaining Data When Managing Users on an Independent Server

In the following example, the independent server retains network service account information. This is just one example, and not intended to place any restrictions on constructing an independent server database.

{
    user_id:xxxx,//auto increment
    links : [
        {
            iss:"https://e97b8a9d672e4ce4845ec6947cd66ef6-sb.baas.nintendo.com",
            id:"xxxxx"//nsa_id
        },
        {
            iss:"https//something_other_service",
            id:"xxxxx"
        }
    ]
}

The characteristics of this example are as follows.

  • The primary key of the table for managing the users is the ID issued by the independent server.
    • This example does not use the network service account internal ID as the primary key. It assumes that users are identified using the iss value or id value in the links array.
    • This is designed with the expectation of logging in to the independent server using an external account that is different from the network service account and getting the user information that is managed by the independent server.
      This architecture allows support for logging in using external accounts different from the network service account simply by adding values to the links array.
