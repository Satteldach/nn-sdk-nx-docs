6 Server Environments

Nintendo Platform Server Environments

Several server environments for the server group provide the various network services on the Nintendo platforms.

Note the following points when developing applications that use the services provided by these servers, and when developing independent servers.

  • The fully qualified domain names (FQDN) for the API endpoints provided by these various servers differ.
  • There is no assurance that the IDs issued by the servers will be unique across environments.
    • Example 1: The internal IDs of network service accounts
    • Example 2: Nintendo Account identifiers.
  • Some server environments are used only for Lotcheck (the testing process conducted by Nintendo).

The following table lists the server environments operated by Nintendo and describes how they are used. Each server environment has been assigned its own environment identifier.

In addition, only some kinds of hardware are allowed to connect to each server environment. As a rule, only the permitted hardware can access the servers.

Independent Server Environment

This section describes the recommended configuration of the server environment for an independent server and how to switch among server environments.

Recommended Configuration

When you configure your independent server, we recommend preparing at least two server environments: a development server environment that application developers mainly connect to, and a production server environment that ordinary users connect to.

If the development server and the production server are identical, there is a risk that the production server will be affected by development work meant to update the independent server and the application after the service goes live.

If it proves difficult to separate the two versions of the independent server at the hardware level, you can make them logically exclusive.

Switching Server Environments

This section introduces several ways to switch the server environment, along with considerations for each method.

If you intend to use a method other than the following methods to switch server environments, make sure that you contact Nintendo in advance to prevent unanticipated problems during the Lotcheck process.

For more information about access from Lotcheck, see 7 Lotcheck.

Switching the Connected Environment Using Settings in the Application

In this method, you use build options or processing inside the application to switch among hostnames and IP addresses, which are different for each independent server environment.

If you choose this method, we recommend using the private package NintendoSDK NX Add-On ApplicationServerEnvironmentKit.

If embedding the hostname or IP address of a development server in the application, we recommend taking measures to prevent users from unexpectedly accessing that server, such as setting access restrictions.

ApplicationServerEnvironmentKit

The NintendoSDK NX Add-On ApplicationServerEnvironmentKit provides a mechanism for switching among the independent server hostnames and IP addresses that have been embedded in the application, doing so according to the application server environment. ApplicationServerEnvironmentKit is available in NintendoSDK NX Add-On 10.2.0 and later. Contact Nintendo support to request the use of this private package.
When making a usage request, include the purpose, such as "to switch the independent server environment."

The nn::oe::GetServerEnvironmentType() function included in this package gets the identifier for the application server environment, which can be used to switch which independent server to connect to. By switching the independent server environment as per this identifier, the application can change the connection destination server without having to prepare DNS and complete other similar tasks.

With the development hardware, you can use DevMenuCommand to change the value obtained by the nn::oe::GetServerEnvironmentType() function at any time. Only the application server environment obtained by the application changes, and no changes are made to the various network service environments provided by the Nintendo platform. You can use this feature to test in advance the application behavior when it has been submitted to Lotcheck or released to general users.

The following table lists the application server environments that can be obtained using nn::oe::GetServerEnvironmentType().

Application Server Environment Description
nn::oe::ServerEnvironmentType_Dd

This value is obtained for the default development hardware environment (dd1).

If this value is obtained, connect to your independent server for the development environment.

This value is also obtained as the default when the Nintendo platform environment identifier has been switched to td1 or jd1.
nn::oe::ServerEnvironmentType_Lp

This value is obtained for the default production unit environment (lp1).

If this value is obtained, connect to your general user-facing independent server.

nn::oe::ServerEnvironmentType_Sd

This value is obtained when Nintendo is running Lotcheck in the sd1 environment.

If this value is obtained, connect to an independent server that can be used to run Lotcheck with the development hardware.

nn::oe::ServerEnvironmentType_Sp

This value is obtained when Nintendo is running Lotcheck in the sp1 environment.

If this value is obtained, connect to an independent server that can be used to run Lotcheck with a retail unit.

nn::oe::ServerEnvironmentType_Dp

Used to switch the connection destination of the independent server in the dp1 environment.

This value is obtained by default when the retail unit environment is switched to dp1.

If you are not using the dp1 environment, you do not need to configure any settings for independent server switching.


Info

When running Lotcheck in the sd1/sp1 environments, you cannot change the default value for the application server environment (nn::oe::ServerEnvironmentType_Sd/nn::oe::ServerEnvironmentType_Sp) to another value to do the checks. As such, make sure that you embed in your application the destinations to connect to when nn::oe::ServerEnvironmentType_Sd and nn::oe::ServerEnvironmentType_Sp are obtained.

If Not Switching Connection Destination Server by Environment

If you use a build option to change the connection destination server, you cannot change the connection destination server settings embedded in the application after the build.

If you select this method, consider the following information.

  • The application ROM that is submitted for Lotcheck must be set with the actual server environment. This method might affect general users during Nintendo’s Lotcheck if an application has already been released.
  • Do not mistakenly ship the application built with access to the development server environment.

Switching Servers Using DNS

In this method, the application contains a single hostname and uses DNS to switch between connections to server environments.

When using this method, make sure that Nintendo can access the original server that was set up for Lotcheck. For more information, see 7 Lotcheck.

Note that if someone else sets up a DNS server with the same settings, setting the same DNS in the retail unit could result in the retail unit accessing the independent server that the DNS specifies.

Routing via User Identifiers

In this method, clients are routed to specific server environments only when some conditions are met, based on factors such as the version information obtained from the application and the network service account internal ID.

Be careful that the processing load from routing does not affect the provision of server services in the production environment.

Also make sure that you provide Nintendo with the conditions for connecting to the server environment for the Lotcheck process before you submit the application for Lotcheck.
