4.5 Authentication and Authorization Sequence

The linking sequence differs depending on the application type. This section describes the standard linking procedure for each type of application.

Web Applications

Web applications running on the server link with Nintendo Accounts by performing a procedure that complies with the Authorization Code Grant flow of OAuth 2.0/Open ID Connect.


Number Description
1

The user begins the process of linking a Nintendo Account by performing an operation like clicking a button displayed in the web application.

2-3

The web application generates a state value and saves and associates it with the session.
The state value is used to check whether the user agent that started the authorization procedure is the same user agent that later accesses the web application with the result of the authorization procedure, as checked in step 7.
This value is a hard-to-guess string designed to guard against cross-site request forgery (CSRF) attacks.
An authorization request is constructed from the state value and the following other parameters, and the user agent is redirected. For more information, see the section in this document about the specifications for authorization requests.

Item Description
client_id The client ID, issued in advance.
response_type code
redirect_uri The redirect URI, registered in advance.
scope The desired permissions.
state The generated state value.
4-6

If the user is not signed in to the Nintendo Account server, a login request is made. Also, if the web application making this user request is not authorized, the authorization procedure is requested.
After these procedures are completed, the user agent with the result of the authorization procedure is redirected to the specified redirect URI.
The web application can get the following responses as query strings.

Item Description
code The authorization code. Required before you can get the token.
state Returns the state value just like it was specified in the authorization request.
session_state

Information that transparently represents the Nintendo Account session.
7

Verifies whether the state value generated by the web application in step 2 is the same as the state value obtained in step 6.

8-9

A token request is constructed from the code parameter (the authorization code obtained as the result of the authorization request) and the following other parameters, and the request is made to the Nintendo Account server.
For more information, see the section in this document about the specification for token requests.

Item Description
Authorization Basic authentication based on the client ID and the client secret.
code The authorization code obtained as the result of the authorization request.
client_id

The client ID, issued in advance.
redirect_uri The redirect URI that was specified in the authorization request.
grant_type 'authorization_code'
scope The scope value that was specified in the authorization request.

If the token request is successful, the following tokens can be obtained.

Item Description
access_token A token required to use the Account API.
token_type The type of token. Fixed to Bearer.
id_token

Included if scope=openid was specified.
The user can be authenticated by verifying the value of id_token.
refresh_token

Included if scope=offline was specified. A token for reacquiring the access token.
expires_in The access_token expiration date.
scope

Stores an array of user-authorized scope values from among the values specified in the authorization request.
10-11

The user can be authenticated by verifying the id_token obtained in the token request. For more information about the verification procedure, see the 4.7.3 ID Tokens page.
After this step, the application is linked to the Nintendo Account identifier if necessary and then the access token and request token are saved.

12

If an error occurs, depending on the circumstances, an error is displayed to the user.

101

The access token can be used to run the account API. For more information, see the 4.7.4 Account API section of this document.

201

If the access token has expired, it can be reacquired using the refresh token. For more information, see the 4.7.2 Token Requests section of this document.

Switch Applications

The procedure for linking Nintendo Accounts to Switch applications and the independent servers is mediated by nn:account.


Application
Number Description
1 The user begins the process of linking a Nintendo Account by performing an operation in the Switch application.
2-4

If the application is not connected to the independent server at this time, the procedure described in 3 Connecting to an Independent Server is performed.

The independent server generates a state value and a nonce value and saves and associates them with the session.
The state value is meant to prevent CSRF attacks. The value is used to confirm that the application that started the authorization procedure is the same as the application in step 9 with the result of the authorization procedure.
The nonce value is meant to prevent replay attacks. Both strings are difficult to guess.

5

The following parameters, which include the values for state and nonce generated in an earlier step, are used to make an authorization request for nn:account.

Item Description
scope The scope of the requested permissions.
state The value generated in step 3.
nonce The value generated in step 3.

code id_token is automatically specified for response_type.
The client ID and the redirect URI linked to the Switch application are automatically specified for client_id and redirect_uri.
6-8

The authorization procedure starts if the Nintendo Account's sign-in status is abnormal, or if the user does not approve the application making the request.
The following response is ultimately returned for the application.

Item Description
code The authorization code. Required before you can get the token.
id_token Required before you can get the token.
state Returns the state value just like it was specified in the authorization request.
9

The Switch application sends the obtained response request to the independent server. You can send this data by any method, but make sure that you encrypt the communication channel.

10

Verification of the ID token and authentication of the user. For more information about the verification method, see the 4.7.3 ID Tokens page.
If the only objective is to authenticate the user and the account API is not being used, the procedures in steps 11 through 14 are not necessary.

11

The authorization code sent from the application is verified using the value of c_hash in the ID token.
For more information about the verification method, see Verifying the Authorization Code Using the c_hash Value on the 4.7.3 ID Tokens page.

12-13

Performs a token request using the authorization code.
Specifies the following parameter fields and casts the token request to the Nintendo Account server.
For more information, see the section in this document about the specification for token requests.

Item Description
Authorization Basic authentication based on the client ID and the client secret.
code The authorization code obtained as the result of the authorization request.
client_id

The client ID, issued in advance.
redirect_uri

Fixed to nintendo://${application ID}.app.
All letters in the application ID must be lowercase.
(Example: nintendo://0123456789abcdef.app)
grant_type Fixed to authorization_code.

If the token request is successful, the following tokens can be obtained.

Item Description
access_token A token required to use the Account API.
token_type The type of token. Fixed to Bearer.
id_token

Included if scope=openid was specified.

refresh_token

Included if scope=offline was specified.
A token for reacquiring the access token.
expires_in The access_token expiration date.
scope

Stores an array of user-authorized scope values from among the values specified in the authorization request.
14-16

The application is linked to the Nintendo Account identifier if necessary and then the access token and request token are saved.
101

The access token can be used to run the account API. For more information, see the 4.7.4 Account API section of this document.

201

If the access token has expired, it can be reacquired using the refresh token. For more information, see the 4.7.2 Token Requests section of this document.

Notes When Linking

The Nintendo Account identifiers are always unique within a single server environment. However, uniqueness is not ensured across multiple server environments.
Because the independent server connects with Nintendo servers in multiple environments, identify the Nintendo Account using the combination of the iss value in the ID token (or its FQDN) and the identifier.

The associations between network service accounts and Nintendo Accounts can be removed or changed by operations by Nintendo.
For this reason, do not act on your own accord with the independent server to convert the identifier of an account to the identifier of a Nintendo Account, or vice versa.
