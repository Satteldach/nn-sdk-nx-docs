4.7.2 Token Requests

Request Specification

HTTP Method/Path
HTTP method POST
Path /connect/1.0.0/api/token
encType

application/x-www-form-urlencoded
Request Parameters
Item Specification Method Required? Description
Authorization header Y Requests Basic authentication based on client ID and client secret issued by Nintendo.
grant_type body Y

Specifies the format of the token request.

Value Description
authorization_code Uses the authorization code.
refresh_token

Uses the refresh token.
client_credentials Uses the client ID and client secret.
redirect_uri body N (see note)

Specify the redirect URI that was specified in the authorization request.

Note: Required when grant_type=authorization_code.
code body N (see note)

Specify the authorization code obtained by the authorization request.

Note: Required when grant_type=authorization_code.
refresh_token body N (see note)

Specify the already acquired refresh token.

Note: Required when grant_type=refresh_token.

Response Specification

The response is returned in application/json format. If the request succeeds, the following properties are included in the response.

Item Type Description
access_token string The access token.
refresh_token string

The refresh token.

Included when both of the following criteria are met.

  1. scope=offline is authorized.
  2. grant_type=authorization_code is specified when requesting the token.
id_token string

The ID token.

Included when both of the following criteria are met.

  1. scope=openid is specified when requesting authorization.
  2. grant_type=authorization_code is specified when requesting the token.
expires_in number

Represents the period of validity of access_token and id_token.

token_type string Fixed to Bearer.
scope string

A list of the user-authorized scope values included among the values specified in the authorization request.

Sample

POST /connect/1.0.0/api/token HTTP/1.1
Host: e97b8a9d672e4ce4845ec6947cd66ef6-sb.accounts.nintendo.com
Content-Type: application/x-www-form-urlencoded
Authorization: Basic ***

grant_type=authorization_code&redirect_uri=http%3A%2F%2Flocalhost&code=ey...
 
 
HTTP/1.1 200 OK
{
  "access_token": "ey..",
  "id_token": "ey...",
  "refresh_token": "ey..",
  "scope": [
    "openid",
    "offline",
    "user.country"
  ],
  "token_type": "Bearer",
  "expires_in": 900
}
 

If the request fails, the following error is returned.

HTTP/1.1 400 Bad Request
{
  "error_description": "The provided grant is expired",
  "error": "invalid_grant"
}
Item Description
error
Value Description
invalid_client Error that occurs if Basic authentication fails for the specified combination of client_id and client_secret.
unauthorized_client Error when the specified client_id is invalid.
invalid_grant

Error that occurs if the authorization procedure fails. It occurs in the following cases.

  • The authorization code is invalid.
  • The authorization code has expired.
  • The refresh token is invalid.
  • The Nintendo Account is in an invalid state.
invalid_request

This error is returned when the request is in an invalid format.

unsupported_grant_type

This error is returned when the specified grant_type is invalid.
description

Text describing the error item.

Refreshing Access Tokens

When both of the following criteria are met, the Nintendo Account server returns a refresh token as the response.

  • scope=offline is specified when requesting authorization.
  • grant_type=authorization_code is specified when requesting the token.

The refresh token does not expire, and it is not reacquired when you act to refresh the access token. To refresh the access token, specify the refresh token that was obtained with the grant_type=authorization_code token request.

Info

The refresh token can become invalidated by the user (by such operations as changing the Nintendo Account password or the country setting) or by Nintendo. In this case, an invalid_grant error (described earlier) occurs.

If the refresh token cannot be used, repeat the authentication and authorization sequence to get a new refresh token.
