3.2 Required and Recommended Support

If the Switch application is linked with an independent server, there are several items that must be supported by the application and several other items that are recommended. Make sure that the application complies with the requirements.
For more information, see the Reasons and Additional Information column for each item.

Table 3-1 Support Items for Switch Applications

 Description Reasons and Additional Information
Required The application must get the NSA ID token before communicating with the independent server.

This is because judging whether to ban network features for accounts of illegal users is dependent on the time when the token was obtained.
For more information, see 3.6 Associating a Network Service Account in this manual and 0035: Getting tokens when starting communication with independent servers in Nintendo Switch Guidelines.
If the save data will store the network service account internal ID or information inherited from the internal ID, the application must be able to handle changes to the network service account.

This is because the relationship between network service accounts and the save data in Switch, which is a resource of the user account, sometimes change.
For more information, see 3.6 Associating a Network Service Account and the Nintendo Switch Account Guide.

If some of the services on the independent server are for Nintendo Switch Online members, use the nn::account::ShowLicenseRequirementsForNetworkService() function to notify users who have not joined the service.

This notification informs users who have not joined Nintendo Switch Online about how to subscribe to the service.
For more information, see 3.3 Nintendo Switch Online Support.

Info

There is currently no service equivalent to Nintendo Switch Online for Nintendo Switch applications for China, so this item is not applicable.
Strongly Recommended Verify the certificate of the server that you connect to. Nintendo strongly recommends verification of server certificates to prevent the spoofing of servers that you connect to.
Recommended

Send the NSA ID token even when not using network service account information on the independent server.

This is so that if the application was changed to use the NSA ID token on the independent server, a patch would not be required for the application to send the NSA ID token to the independent server.
For more information, see 3.6 Associating a Network Service Account.
Table 3-2 Items to Support for Independent Servers

 Description Reasons and Additional Information
Required Consider the Nintendo platform server environment and make sure that there is no problem if the internal ID of the network service account is duplicated in a different server environment.

This requirement supports the multiple server environments used by Nintendo.
For example, you can take measures such as using a combination of the iss value of the NSA ID token and an internal ID as the user identifier on the independent server.
For more information, see 3.6 Associating a Network Service Account, 6 Server Environments, and Nintendo Switch Guidelines > Communication features > Independent servers > 0117: Supporting multiple authentication server environments.
If some of the services on the independent server are for Nintendo Switch Online members, provide handling for the members-only services.

The reason for this handling is that if only some services require a Nintendo Switch Online membership, the independent server itself must control when the service is provided.
For more information, see 3.3 Nintendo Switch Online Support.
Strongly Recommended

Perform NSA ID token verification if the independent server uses the NSA ID token information.

The reason is that the validity of network service accounts, applications, and devices via Nintendo authentication is not ensured when NSA ID token verification does not occur.
For more information, see 3.6 Associating a Network Service Account.
Encrypt the communication route.

Nintendo strongly recommends encrypting communication routes to prevent the monitoring and spoofing of communication content and the spoofing of servers you connect to.
Optional Store the value of bs:did (the login ID) that is contained in the NSA ID token in the independent server.

This value is needed if you plan to use Nintendo's mechanism to restrict the use of network features by illegal users (execute a ban). If a ban is not required, or if you will be using your own mechanism to ban use, this value is not necessary.

For more information about bans, see Nintendo Switch Online Play Guide.

The following two types of bans can be implemented on the application side.

  • Device App Ban
    • This type of ban targets particular Switch devices and restricts using the application network features.
  • NSA App Ban
    • This type of ban targets particular accounts and restricts using the application network features.

With Device App bans, the login ID is necessary to specify the Switch that is being targeted to ban. For this reason, save the login ID information when executing a Device App ban.
