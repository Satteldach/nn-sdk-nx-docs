2.1 Flow From Development to Operation

This chapter describes the processes for developing and operating an independent server. In general, these processes advance in order through the following phases.

  1. Planning
  2. Usage requests
  3. Development
  4. Lotcheck (final testing at Nintendo)
  5. Go live
  6. Maintenance
  7. Developing and distributing patches
  8. End of service

Planning

There are basically two methods for providing network services for applications on the Nintendo platform.

Select the method to adopt based on the details of your plan.

Only use the server provided by Nintendo

This method makes use of the following services provided by Nintendo. If you will be using only these services, you do not need to configure an independent server.

  • NPLN
  • NEX (For new products, the use of this service has basically ended.)
  • BCAT
  • Patch
  • Downloadable Content
  • User Save Data Controlled Consumable Service Items
Configure an independent server This method is suitable when you want to provide network services that would be difficult to realize with NEX or NPLN, and when you want to operate services yourself.
In addition, you must configure an independent server to use the following service provided by Nintendo.
  • Subscription Service Items
  • Consumable Service Items Using the Independent Server Controlled Method


Info

When implementing the matchmaking feature uniquely using Switch friends, see the Nintendo Switch Account Guide.

For links to an overview of the network services available from Nintendo and to the documentation that includes more detailed information, see the Nintendo Switch Overview.

Usage Requests

For an application to use an independent server, it must access the Nintendo authentication server and get a network service account ID token (NSA ID token). The NSA ID token is obtained by calling the API provided in the NintendoSDK. For more information, see 3 Connecting to an Independent Server.

To issue NSA ID tokens, information about the application must be registered on the Nintendo authentication server. To register the information, submit a usage request on OMAS (the Online Title Management System). The information will be registered when the request is approved.

To set up the independent server, submit the request on OMAS as follows. For more information, see the OMAS Help.

  • In Application Overview, set Communication With Independent Server (Yes/No) to Yes.
  • If you will be using socket communication or HTTP communication for communication with the independent server, fill out the request item for Use Socket or HTTP Communication.
Info

For applications for China, submit the request in OMAS so that the application does not require Nintendo Switch Online membership. For more information, see 3.3 Nintendo Switch Online Support.

Development

If you are configuring an independent server, read the sections in the following list and develop your application accordingly.

  • 3 Connecting to an Independent Server
  • 6 Server Environments
  • 8 Independent Server Development

Additionally, when an application supports an independent server, the application and independent server must be implemented according to guidelines. If the guidelines are not supported, it may fail in the Lotcheck stage (described later). For that reason, when you first start development, see items like Communication features, Accounts, and Nintendo Switch Online in the Nintendo Switch Guidelines.

When supporting service items, see the following documentation.

  • Nintendo Switch E-Commerce Guide
    This documentation also describes how to use the service item feature.
    A service item is a selling method that grants the purchaser the right to use a service or item for a specific term, either a fixed period of time or a fixed number of times. With the independent server controlled method, independent server support is necessary to implement subscription service items and consumable service items.

Lotcheck (Final Testing at Nintendo)

Before an application can be released, it must pass through final testing process called Lotcheck at Nintendo.

For applications that communicate with an independent server, the process includes testing whether the application can communicate appropriately with the independent server and whether the provided services conform to the guidelines.

You must prepare an independent server environment that can be tested by Nintendo. See 6 Server Environments and 7 Lotcheck.

Go Live

Users will begin accessing the independent server after an application goes on sale and reaches the hands of consumers.

If the application's release date differs from the date when services will begin on the independent server, we recommend displaying a message in the application that conveys that fact to users.

In addition, testing occurs within Nintendo before any platform firmware updates are sent to regular users. With the consent of the developer, Nintendo may access the production environment independent server as a part of that testing to ensure that there are no compatibility issues with released applications.

Basically speaking, this option means connecting in the same environment (in terms of equipment and Nintendo server environment) used by general users. In other words, the independent server does not need to do anything special to support this option.

Independent Server Maintenance

To access an independent server from an application, you must get an NSA ID token from the Nintendo authentication server. As a result, users cannot use services provided by independent servers while the Nintendo authentication server is down for maintenance. In addition, to use the service item feature, you must link the independent server to Nintendo eShop.

To increase the availability of your game, time the maintenance of the independent server to coincide with the periodic maintenance of the Nintendo authentication server and Nintendo eShop.

The periodic maintenance of the Nintendo authentication server and Nintendo eShop takes place on Tuesdays between the hours of 05:00 and 11:00, Japan Standard Time. Note that server maintenance is not necessarily conducted even during this time. Sometimes maintenance will occur outside of the regular maintenance window. For more information about the actual maintenance status, see the Nintendo support site for developers.

Note that if you plan to maintain the independent server along with the release of an application patch, there are restrictions on when patches can be distributed. When considering the timing of maintenance, see Distributing Patches later in this document.

Developing Patches

You can update an application that has already been released to the market by developing and distributing a patch.

Patches, just like applications, are developed in the development environment, subjected to Lotcheck testing, and then distributed in the production environment.

Note that for patch development, the independent server that the patched application runs on must be available in the development environment. Because the independent server that has been prepared for the product environment cannot be used for patch development in some cases, we recommend that you allow for patch development by preparing separate versions of the independent server for the product environment and the development environment in advance.

Distributing Patches

Application patches are distributed via Nintendo eShop, so they cannot be distributed while Nintendo eShop is down for maintenance. When considering the timing of maintenance, avoid times when Nintendo eShop is down for maintenance.

If you plan an update that would make it impossible for the application to access the independent server if it did not install the patch, we recommend that you do not maintain the independent server along with releasing the patch while Nintendo eShop is down for maintenance. As previously mentioned, patches cannot be distributed while maintaining Nintendo eShop. As a result, even if you want to distribute a patch during the maintenance window of Nintendo eShop, there will be situations where you cannot start distribution as desired. You run the risk of service outage when using an independent server for the duration between an independent server update and the distribution of the application update data if the update data download is delayed when you end up updating the independent server on the assumption that the update data will be available at the desired time.

End of Service

You must submit an end-of-service report to OMAS before ending a service.

By establishing an end time for the service and applying it in the Nintendo authentication server, an error will be returned to the application when it is going through Nintendo's authentication process, using the authentication server, before connecting to the independent server.

The same will be true for future Switch network services: after the end time for a service has been reached, an error will be returned to the application during the Nintendo authentication process (using the authentication server), and access to the independent server will stop.
