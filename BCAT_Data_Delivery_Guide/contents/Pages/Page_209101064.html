2 Delivery Specifications

About BCAT Data Delivery

BCAT Data Delivery is a system for simultaneously delivering data registered on servers managed by Nintendo to multiple Switch systems. Data delivery involves synchronizing the data on the server with the data on the Switch system.

Multiple directories with a directory depth of one level can be registered on the server. Multiple files can be added to a directory. The delivery start date and time and end date and time can be scheduled for each file.

During synchronization, the directory and file tree structure will be copied as is to the Switch system. If directories or files are deleted from the server, they will also be deleted from the Switch system.

To register data on the server, use the BCAT Management Tool, a web system for PC browsers.

Info

This document collectively refers to the directories and files as data.

Usage Examples

BCAT data delivery is expected to be used in cases such as the following.

  • Delivering additional player characters along with online and offline campaigns
  • Distributing configuration files to adjust game balance

It is not possible to deliver dynamic program modules (such as NRO files).

Info

Previously, a special BCAT mechanism was provided for delivery of data by specific operators in certain retail stores and event venues, but support for that feature has ended.

Usage Conditions

The following conditions must be satisfied for the end user to use the BCAT data delivery feature.

  • The user has started the application that supports BCAT data delivery at least one time, and initialized BCAT data delivery (called nn::bcat::Initialize).
  • The user has internet access.
  • At least one user account on the system is linked to a Nintendo Account (or an account for China).

If these conditions are satisfied, even user accounts that are not linked to Nintendo Accounts (or accounts for China) can use the BCAT data delivery system.

Info

If the usage conditions for BCAT data delivery are not satisfied and a function that involves immediate synchronization is called, the function returns an error (an nn::Result instance for which nn::Result::IsFailure() returns true). For more information about immediate synchronization, see Synchronization Types later on this page. Note that this error can also occur for reasons other than a failure to meet the usage conditions described here.

As a general rule, if an error occurs, pass the returned value to the error viewer applet to notify the user about the error, as described in the Nintendo Switch Guidelines (0079: Displaying errors using the error viewer applet). An appropriate message will be shown to the user to resolve the cause of the error.

If the Nintendo Switch Guidelines do not pertain to your particular case, there is no requirement to notify the user via the error viewer applet. However, if you do not notify users via the error viewer applet, they might not be able to resolve the cause of the error. In those situations, it is the responsibility of the publisher to respond to inquiries from users and take appropriate measures to resolve the issue, for example by confirming with users that the BCAT data delivery usage conditions are satisfied.

Synchronization Types

Two synchronization methods are provided for BCAT data delivery.

A method of immediate synchronization is provided for downloading data from the server to the Switch console at any time when the application is running.

A method of background synchronization is provided for downloading data from the server to the Switch console in advance when the application is not running.

Info

Please avoid designs where all immediate synchronization is performed at the same time. That would concentrate the load on the server, which might affect the overall operations of the service.

Synchronization Granularity

  • Data is synchronized by directory.
  • After synchronization is complete, the content of directory A in the Switch console will be overwritten by the content of directory A on the server.
  • Directory synchronization is an atomic operation, so directory A with old content and directory A with new content will not coexist in the Switch console at the same time.
  • Even if the content of directory A on the Switch console is identical to the latest content on the server, there is no assurance that the content in a different directory B would also be the latest version.
    • This situation may occur, for example, when the internet connection is disconnected during synchronization. Keep that in mind.

Synchronization Limitations

Notifications

Background synchronization is performed when the Switch console receives a push notification from the server.

Push notifications are sent when there are changes to the data being delivered (for example, when new data is released).

If the Switch console is offline when the push notification is sent, it will receive the notification again when it comes back online.

However, there is no assurance that all Switch consoles will receive the notification when using background synchronization. When necessary, implement immediate synchronization in the application and verify that synchronization was successful.

Info

In situations like the following, push notifications cannot be received.

  • The user has not run the application recently.
    • Background synchronization is only performed for the 16 most recently run applications that support BCAT data delivery.
  • There is a problem with the server that delivers push notifications.
    • Note that an immediate synchronization will succeed even if push notifications cannot be received due to server problems.

Time Required

Note: It can take time for all Switch systems to be fully synchronized via background synchronization for the following reasons.

  • Push notifications for background synchronization are sent sequentially to the target Switch systems.
  • The internet connection speed differs for each target Switch system that is connected.

Discrepancies

Until all Switch systems are synchronized, both "systems that have completed synchronization" and "systems that have not completed synchronization" will coexist.

If your specification for inter-application communication does not tolerate discrepancies in synchronization states, perform immediate synchronization before inter-application communication.
