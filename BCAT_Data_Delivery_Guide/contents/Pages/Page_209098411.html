4 Operations

Getting Started

The following actions are required to begin using BCAT data delivery.

  • Submit a usage request on OMAS
  • Apply the OMAS request in the BCAT Management Tool
  • Register data in the BCAT Management Tool

The BCAT Management Tool is provided in several server environments, each for a different purpose, and so each BCAT Management Tool must be configured individually.

For more information, see Nintendo Switch BCAT Management Tool Usage Manual.

Operations to Perform Before Starting Lotcheck

When submitting a master ROM of the application to Nintendo for Lotcheck, register the data in the BCAT Management Tool in the Lotcheck server environment (sp1 and sd1 server environments).

The data does not have to be official, as long as the following behavior can be confirmed.

  • Immediate synchronization behavior if the application implements immediate synchronization
  • Behavior where the application loads synchronized data

Operations to Perform Before Application Release

Attempting to synchronize the Switch system without applying the OMAS request in the BCAT Management Tool at least one time will result in an error, and synchronization will fail.

In the case of Switch consoles with system version 3.x.x (consoles installed with NX Add-On 3.x firmware), the attempt at immediate synchronization will result in error code 2122-2404.

To avoid this error, make sure to apply the OMAS request in the production environment (lp1 server environment) BCAT Management Tool at least one time in advance, even if there are no plans to deliver the data starting from the application release date.

Note

For data required for specific sequences in the application, we recommend delivering the data in the production environment by the application release date.

In addition, we recommend implementing a design where the application operations do not stop, even if this data is not delivered.

Test Delivery

A process called test delivery is provided as a means to experiment with the delivery of data.

This process of test delivery enables the following actions.

  • Delivering data regardless of the start date and time set for each file
  • Delivering customized combinations of data to specific Nintendo Switch systems

Test delivery is meant for use in the following situations.

  • Final testing of an application in the production environment before its release date
  • Debugging the application in the development environment in multiple delivery states in parallel
    • For example, to debug a summer online event and winter online event in parallel

For more information, see Nintendo Switch BCAT Management Tool Usage Manual.

[China-Specific] Tencent Review

For applications for sale in China, Tencent reviews the data that will be delivered via BCAT data delivery.

Data that is not approved in the Tencent review cannot be delivered in the production environment.

For more information, see Nintendo Switch BCAT Management Tool Usage Manual.

Delivery Size Restrictions

Make sure that the total size of all files delivered for each application over a period of 30 days does not exceed 100 MiB. For example, if you create a single directory containing a 3 MiB file, you can add a schedule on the server to update this file every 24 hours.
If the transfer volume is expected to exceed the restrictions, contact Nintendo in advance.

Note

If it is proven that the transfer limit was exceeded in the product environment without consulting Nintendo in advance, data delivery may be stopped.
